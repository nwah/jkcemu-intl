ZX Spectrum

There were several clone projects of the Sinclair ZX Spectrum in the GDR, e.g. KUB64, Spectral, ZX-HFO, and ZX-Jena. The Spectral, in particular, distributed by the Erfurt-based company Hübner Elektronik, achieved wider distribution, partly because it is fully compatible with a ZX Spectrum 48K and could also be expanded into a ZX Spectrum 128K.

1. Emulated Hardware

Depending on the setting, the following are emulated:
  • ZX Spectrum 48K:
    • 48 KByte RAM
    • Speaker and cassette recorder connector
    • Kempston joystick interface
  • ZX Spectrum+ 128K:
    • 128 KByte RAM
    • Speaker and cassette recorder connector
    • AY-3-8912 sound generator
    • Kempston joystick interface

1.1. Keyboard

The ZX Spectrum has several input modes, which is why the keys are used for multiple purposes. Although the key mapping in the emulator is designed to be as simple as possible for the user, not all characters can be entered directly, because of the different input modes. For this reason, it is important that you know the different input modes:

The most important characters can be typed directly using the keys of the same name. For some characters, one of the two Shift keys (CAPS SHIFT or SYMBOL SHIFT) must be pressed together with the actual character key. For somewhat less commonly used characters, you first need to switch on the so-called Extended Mode (pressing CAPS SHIFT and SYMBOL SHIFT at the same time) and only then press the actual character key (possibly together with a Shift key). For the ZX Spectrum 48K, a table is given further below that explains the different input modes in detail. On the ZX Spectrum+ 128K, a few control keys were added that on the 48K can only be reached with key combinations. Because of this, as well as the new 128 BASIC, entry on the ZX Spectrum+ 128K has become somewhat simpler.

The emulator supports the different input modes as follows:

Pressing Ctrl and Shift at the same time emulates pressing CAPS SHIFT and SYMBOL SHIFT at the same time (Extended Mode), after which, in 48 BASIC, the E-cursor usually appears.

The two keys CAPS SHIFT and SYMBOL SHIFT can also be pressed individually with the function keys F5 and F6.

1.2. Timing Behavior of the Video RAM

The CPU and the video hardware cannot access the video RAM at the same time. On the ZX Spectrum, access by the CPU is delayed until the video hardware does not currently need to read a byte. In the original, this delay is achieved by intervening in the CPU clock. In JKCEMU, wait states are used for this instead. For the user, this difference from the original is only visible in the debugger, if you look closely at the clock cycles needed when accessing the video RAM. The resulting timing behavior nearly matches the original.

2. Miscellaneous

2.1. Sound/Cassette Output

To listen to, output, or record the sound or cassette output, you must open the Audio/Tape window and enable the corresponding function there. On the Tape Output tab, you can make the sounds audible, or record them and then save them to a file, which are output via the MIC connector. The EAR tab represents the EAR connector. On the ZX Spectrum+ 128, there is additionally the Sound Generator tab, which represents the AY-3-8912 sound chip.

2.2. Supported File Formats

The file formats CSW (*.csw), TZX (*.tzx), and ZX-TAP (*.tap), which are mainly used by ZX Spectrum emulators, are referred to here as tape files and can be loaded into JKCEMU with the function Read audio data from a sound or tape file. Write support is available for CSW and TZX files on the Tape Output tab.

2.3. Saving a BASIC Program to a Sound or Tape File

To save a BASIC program to a sound or tape file, the following procedure is recommended:
  1. Enter the command to save to cassette (SAVE "name") and press Enter.
    A message appears telling you to start the cassette recorder and then press a key.
  2. Enable the audio function Record audio data and save to a file
  3. Reactivate the window with the emulated ZX Spectrum and press a key.
  4. Once the emulated ZX Spectrum has finished saving, disable the audio function and save the recording

With a different procedure, if you are too slow, it can happen that the emulator detects the end of the data output before you have entered the save command, which then automatically ends the audio function.
