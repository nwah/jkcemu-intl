User-Defined Computer

With the user-defined computer, you can, within certain limits, virtually assemble your own computer, which is then emulated. In its basic configuration, the computer has a Z80 CPU and 64 KByte of RAM. In the Settings, you can add further hardware components, which are described below.

Caution! Not all possible hardware variants can be reproduced, only certain common standard configurations.

  • ROM
  • Screen Output
  • Keyboard
  • I/O Devices
  • FDC (Floppy Disk Controller)
  • GIDE (Hard Disks)

ROM

You can define as many ROM areas as you like, even ones that lie in the same address range. You set the ROM content by selecting a corresponding file. If no file is specified, the ROM area contains FFh bytes.

Each ROM area can optionally be switchable, i.e. either only capable of being switched out, or capable of being switched both in and out. To do this, you must specify the I/O address used to switch it in and out. If the ROM area can only be switched out, an output instruction to this address causes it to be switched out, regardless of the value output. For a ROM that can be switched both in and out, a bit as well as its polarity (H-active or L-active) must be specified, used for switching.

Program execution after RESET usually starts at address 0000h. If the computer being emulated has a different start address, then mark the ROM at which program execution is to begin as the boot ROM.

When reading from a ROM area, the list of ROMs is traversed from top to bottom, and the first matching ROM, i.e. the one switched in at the relevant address, is used. So if several ROMs are defined in the same address range and are also switched in, the first one is read from.

In the user-defined computer, the ROMs are write-through, i.e. on a write access to a ROM address, the byte in question is written to the RAM underneath. If the ROM at that address is later switched out, the written value can be read.

Screen Output

Screen output is emulated by defining part of the RAM as video RAM. Every character stored in that RAM area is output to the screen. The screen output is alphanumeric. Pixel graphics or full graphics are not emulated.

To define the screen output, specify the start address of the video RAM as well as the number of columns and rows. The rows and columns are organized in ascending order in the video RAM, i.e. row 1 comes first, with its characters from left to right, then row 2, and so on.

The English DOS character set Codepage 437 is used as the character set. Optionally, you can load your own character set file.

The video RAM is always located in RAM. Even if a ROM is switched in at that address range, the characters displayed are read from RAM. In combination with the property that the ROMs are write-through (see above), this allows a ROM and video RAM to be operated in the same address range.

Keyboard

Various variants for connecting a keyboard are emulated, from which you can choose one. What all variants have in common is that the characters supplied by the keyboard must be read with input instructions. Accordingly, specifying an I/O address is also necessary. For emulation via a simple input port, you specify the I/O address next to it. For the other variants, the keyboard is connected to a PIO or SIO. You must activate this PIO or SIO in the I/O Devices tab (see below) and specify the I/O address there as well.

Keyboard connection variants:
  • Simple input port:
    With this variant, when a key is pressed, the 8-bit character code is applied to the input port. If no key is pressed, a zero byte is read.

  • PIO port A or B with Ready/Strobe handshake:
    When a key is pressed, the 8-bit character code is applied to the corresponding PIO port and the strobe line responsible for that port is activated. With this connection variant, the PIO is usually operated in byte input mode and can therefore also trigger an interrupt.

  • PIO port A or B with strobe on bit 7:
    With this variant, when a key is pressed, the 7-bit character code is applied to the PIO port and bit 7 is set to H. If no key is pressed, bit 7 is L and bits 0 through 6 are undefined. The PIO is usually operated in bit I/O mode. Through appropriate programming, bit 7 can trigger an interrupt that signals that a key has been pressed.

  • SIO channel A or B:
    The 8-bit character code can be read via the corresponding SIO channel. If the SIO channel is programmed for 5-, 6-, or 7-bit reception, only the lower 5, 6, or 7 bits are read. The SIO's interrupt capabilities are available. A hardware or software handshake is not emulated.

For the SIO, you can specify whether a printer is connected to its outputs. If you specify a printer on both channels, the bytes output via them are appended to the same print job, since JKCEMU only emulates one printer.

For the CTC, the counters/timers are chained through, i.e. the output of counter/timer 0 goes to the input of counter/timer 1, and so on.

Finally, in this tab you specify which value should be read from unoccupied I/O addresses.

FDC (Floppy Disk Controller)

Here you specify whether, and at which I/O addresses, a floppy disk controller with four connected floppy disk drives should be emulated. If the original hardware contains additional I/O addresses for controlling the floppy disk drives (e.g. for switching the drive motors on and off), these are not emulated by JKCEMU or play no role in the emulation (there are no motors that could be switched on and off).

GIDE (Hard Disks)

In this tab, you specify whether GIDE should be emulated with up to two connected hard disks. GIDE occupies 16 consecutive I/O addresses.
