LLC2

The LLC2 is a home-built computer developed by Dr. Gerd Maudrich in 1985. In the original concept, the computer had a 2 KByte EPROM containing a bootstrap loader. The Studio Computer Club Halle (SCCH) took on further development of the LLC2 and developed a 4 KByte monitor program as well as several expansion modules. The monitor program and the expansion modules are also available, in adapted form, for the AC1. As a result, there is a certain degree of software compatibility between the AC1 and the LLC2. JKCEMU emulates the LLC2 with the SCCH enhancements. For this reason, the SCCH monitor program is included instead of the original bootstrap loader.

1. Emulated Hardware

  • 4 KByte ROM for the monitor program
  • 64 KByte RAM including video RAM
  • CTC with the output of channel 1 connected to the input of channel 3
  • cassette recorder connector
  • SCCH module 1 (additional ROM)
  • SCCH module 3 (additional RAM)
  • SCCH inverse-video circuit
  • inverse-video circuit via system PIO B5
  • inverse-video key (F1)
  • graphics key (F2)
  • V24 interface with printer
  • HIRES full-graphics expansion with split screen
  • Optional:
    • Two RAM floppies as described in Mikroprozessortechnik issue 3/1988, at I/O base addresses D0h and B0h
    • floppy disk module
    • GIDE with up to two hard disks at I/O base address 80h
    • joystick
    • K1520 sound card (see also Cassette and Sound Output)
    • KCNet-compatible network card at I/O base address C0h
    • USB connector (Vinculum VDIP module) at I/O base addresses DCh and FCh

1.2. Memory

The lower 48 KByte of RAM are not visible after power-on or after a RESET. Only with an I/O instruction to address E0h is the ROM switched out and the RAM switched in. With this mechanism, the monitor program relocates itself from ROM into RAM.

1.3. SCCH Module 1

SCCH module 1 provides additional ROM, namely:
  • 8 KByte for the Graphics/Sound BASIC interpreter
  • 8 KByte for Program Package X
  • 256 KByte for the ROM disk

The module is controlled via output port ECh:
Bit 0: switch in Program Package X in the range E000-FFFF
Bit 1: switch in Graphics/Sound BASIC in the range 4000-5FFF
Bit 3: switch in one segment of the ROM disk in the range C000-FFFF,
bits 0, 4, 5, and 6 determine the corresponding 16K segment.

JKCEMU does not supply any content for Program Package X or the ROM disk. You must provide this yourself in the Settings by loading ROM files.

1.4. SCCH Module 3

Depending on how it is fitted, SCCH module 3 provides 64, 128, 256, 320, or 512 KByte of additional RAM, which can be switched into working memory via I/O instructions. Specifically, bits 0 through 3 of I/O port EDh select one of 16 possible 64-KByte-sized blocks, which is then switched in, according to bits 4 through 7 of the same I/O port, as read-only, write-only, or read/write (in which case only 32 KByte are switched in).

The address space for the additional RAM is 1 MByte (16 x 64 KByte). Although the original module can only be fitted with a maximum of 512 KByte, JKCEMU emulates the maximum possible 1 MByte. This has the advantage that software using this additional RAM does not need to be specially configured for use with JKCEMU, because wherever the software in question expects RAM to be present, it will also find RAM there in JKCEMU.

1.5. SCCH Inverse-Video Circuit

The SCCH inverse-video circuit recognizes the values 10h and 11h stored in video RAM. A value of 11h turns inverse video on, and 10h turns it off again. Regardless of this, inverse video is always turned off at the end of a line.

1.6. Inverse-Video Circuit via System PIO B5

With this circuit, inverse video mode is activated by bit 5 on port B of the system PIO (I/O address E9h). In inverse video mode, all characters with bit 7 set are then output inverted.

Caution! The LLC2 monitor program included in JKCEMU turns off inverse video mode on keyboard input. So if you want to use this inverse video mode in your own programs, you must account for, or work around, this interfering behavior of the monitor program.

1.7. Inverse-Video Key (F1)

On the original, the SCCH inverse-video circuit also included a switch with which the entire screen could be inverted. JKCEMU emulates this switch with the F1 key.

1.8. Graphics Key (F2)

The graphics key (F2) allows graphics characters to be entered from the keyboard. However, this must also be supported by the respective application program. The Graphics/Sound BASIC included in JKCEMU supports the graphics key.

1.9. Character Set Switching

Character set switching via PIO B3 is emulated in conjunction with an externally loaded character set file. For this, the character set file must contain two character sets, i.e. it must be larger than 2 KByte. Switching to the second character set is done by outputting a 1 to PIO port B3.

Based on the size of the externally loaded character set file, the emulator recognizes what kind of file it is:

Character Set File Size Meaning
2 KByte
(1 to 2048 bytes)		 The file contains only one character set, i.e. no switching is possible.
4 KByte
(2049 to 4096 bytes) 		The file contains two character sets in succession. The second one starts at offset 0800h.
8 KByte
(more than 4096 bytes) 		The file is a dual HIRES character set file, i.e. besides the two character sets, it also contains the HIRES bitmap. The character sets are located in the file in the ranges 0000h-07FFh and 1000h-17FFh. The other two ranges each contain the HIRES bitmap, which, however, is not evaluated by JKCEMU.


1.10. Split Screen

Split screen means that during each screen refresh (i.e. 50 times per second), the display switches between text and HIRES mode, so that the screen output is split into a text part and a HIRES part. For this, the input of CTC channel 2 must be connected to the vertical sync pulse, and the CTC must be programmed to trigger an interrupt on the corresponding pixel row. JKCEMU emulates this connection from the vertical sync pulse to the CTC, so that programs using split screen mode also run correctly.

1.12. V24 Interface with Printer

The additional PIO (I/O addresses E4h-E7h) is emulated, along with the V24 interface implemented via it and a printer connected to it. The printer interface is set to the parameters that the built-in monitor program assumes after a RESET. This way, characters can be output to the emulated printer through the monitor program's functions without having to change the V24 parameters.

To easily try out the printer emulation, you can use Ctrl-X in the monitor program to additionally route screen output to the printer. Ctrl-Y switches this off again.

1.13. Joystick

If the Joystick checkbox is set in the LLC2 settings, a joystick is emulated according to the SCCH circuit. With this circuit, bit 4 of port B of the system PIO is used to switch between keyboard and joystick. If an LLC2 program reprograms the system PIO without taking the joystick circuit into account, keyboard input may no longer be possible. In that case, you must turn off joystick emulation.

1.14. Cassette and Sound Output

You can listen to the sound signals output at the emulated cassette recorder connector (PIO 1, port B, bit 0) in the Audio/Tape window on the Tape Output tab, or record them and save them to a file. The Speaker tab is responsible for the sound signals output via CTC channel 0 or via PIO 1, port B, bit 6 (speaker connector, see below). An additional tab appears if you have enabled emulation of the K1520 sound card.

1.14.1. Speaker Connector

On the LLC2 as originally developed by Dr. Gerd Maudrich, the speaker is connected via a flip-flop to CTC channel 0. Via PIO 1, port B, bit 6, this flip-flop, and thus the sound output, can be switched on and off. In the further development of the LLC2 by the Studio Computer Club Halle, the speaker connector was changed so that it now goes directly to the PIO port and no longer has a connection to the CTC. JKCEMU models both variants in parallel. For output on PIO 1, the phase of the speaker signal is switched directly to the value of port B, bit 6. At the same time, the emulated flip-flop is disabled at low level and enabled at high level. If this flip-flop is enabled, every pulse output on CTC channel 0 causes the phase to change, and thus produces half a sound cycle at the speaker connector.

3. BASIC

3.1. Graphics/Sound BASIC

The Graphics/Sound BASIC interpreter version 3.2 resides in a background ROM in the address range 4000h-5FFFh. By default, this address range contains RAM. Via bit 1 of I/O port ECh, the ROM can be brought to the foreground, making the BASIC interpreter visible in that address range.

With the SCCH monitor programs integrated into the emulator, you can call up BASIC directly with the command b (cold start). This also brings the BASIC ROM to the foreground. You perform a warm start of the interpreter with the command r.

3.2. Saving and Loading BASIC Programs

JKCEMU offers special support for saving and loading BASIC programs. To save a program, please use the function Save BASIC Program... in the File menu and save the program as a BASIC/RBASIC program file (*.bas). Alternatively, you can also save it as a Headersave file (*.z80) with file type B.

If you save a BASIC program in a different file format, JKCEMU will no longer recognize, when the file is loaded later, that it is a BASIC program, and will not adjust the system cells of the BASIC interpreter. The loaded program cannot then be used.

3.3. HIRES Image Files

The JKCEMU Image Viewer supports reading and writing LLC2 HIRES image files. These files contain the contents of the HIRES pixel memory unchanged and without any additional information. To be displayed in the JKCEMU Image Viewer, the files must have the extension *.pix and be exactly 16384 bytes in size. Conversely, the Image Viewer can be used to create HIRES image files for the LLC2 simply by saving them with the extension *.pix. To load and display these files on the LLC2, a corresponding program is needed. Such a program is not included in JKCEMU. However, you can easily create one yourself with the built-in BASIC Compiler. As an example, here is a program that loads HIRES images from a USB storage device. For this, a USB module (VDIP) must of course be connected, or USB emulation must be enabled in JKCEMU. The program asks for the name of the file to be loaded. The file name can also be entered without the extension .PIX.

cls
print "LLC2-HIRES-Bilder von USB-Speicher laden"
print
do
  input "File name (Enter only -> end): ";f$
  f$=trim$(f$)
  if len(f$)=0 then end
  if instr(f$,".")=0 then f$=f$+".PIX"
  open f$ for input as #1
  if err then
    print f$;": ";err$
  else
    screen 1
    a=&h8000
    for i=1 to 16384
      b=asc(input$(1,1))
      if err then exit
      poke a,b
      a=a+1
    next
    if not err then e=asc(input$(1))
    screen 0
    if err then print err$
    close #1
  endif
loop

Important! When compiling, you must select the target system LLC2 with HIRES graphics!
In addition, the runtime properties in the compiler options should be set to Compile for Production Use.

4. Miscellaneous

4.1. Pasting Text from the Clipboard

Pasting text from the clipboard is usually done by simulating, for each character to be pasted, the pressing of the corresponding key or key combination. This approach is rather slow. For the LLC2, there is an option in the Settings called Paste text by intercepting the system call. With this option, the emulator listens at address 1802h, the entry point of the system function for reading a character from the keyboard. When this system function is called, JKCEMU checks whether a character should be pasted. If so, it writes the next character to be pasted into the corresponding processor register and simulates a RETURN instruction. If the operating system or the application program does not query the keyboard through this entry point, pasting text will not work, and you must turn off the option. You must also turn off the option when using a different operating system (e.g. CP/M-compatible).
