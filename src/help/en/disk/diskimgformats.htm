File Formats for Disk Image Files

One form of floppy disk emulation is the use of image files (disk image files). JKCEMU supports:
  • Plain image files
  • AnaDisk files (*.dump)
  • CopyQM files (*.cqm)
  • CPC-Disk files `*.dsk)
  • ImageDisk files (*.imd)
  • TeleDisk files (*.td0)
These files can also be GZIP-compressed.

All these formats are supported by JKCEMU for both reading and writing. However, there is a restriction on write support: Emulating a floppy disk by means of an image file is only possible, for writing, with the file formats that get by without any compression and allow random access to the data of each individual sector. This is only the case for plain image files, AnaDisk files, and CPC-Disk files. Full write support, i.e. creating such a file, on the other hand exists for the manual creation of a disk image file as well as in the File Converter (see also summary).

There are floppy disks that have a different floppy disk format on the system tracks than in the data area. Such floppy disks can only be represented in disk image file formats that support a free sector arrangement. This is only the case for AnaDisk, CPC-Disk, ImageDisk and TeleDisk files.

1. Plain Image Files

A plain image file is a concatenation of all the sectors of a floppy disk, but without management or geometry data, i.e. a plain image file contains only payload data. The image file of a 720K floppy disk is thus exactly 720 KByte in size. A free sector arrangement, interleave, or gaps in the sector numbering are not possible with this file format.

Although plain image files are widely used, the format has no uniform name. It is often simply called the RAW format. The file extension is also not fixed. Common ones are *.img, *.image, *.raw and *.dd. The latter is derived from the Linux/Unix command of the same name, with which you can create image files, e.g.:

 dd if=/dev/fd0 of=<file name>

Under DOS, the programs rawread.exe and, for writing back, rawwrite.exe are well known.

2. AnaDisk Files (*.dump)

AnaDisk is a program for creating special disk image files (AnaDisk files). In an AnaDisk file, the sectors are strung together uncompressed, with an 8-byte header preceding each sector. This header has the following structure:
Number of BytesMeaning
1 byte Physical cylinder number (starts with 0)
1 byte Physical head number (starts with 0)
1 byte Cylinder number in the sector ID (starts with 0)
1 byte Head number in the sector ID (starts with 0)
1 byte Sector number (starts with 1)
1 byte Sector size:
  0: 128 bytes
  1: 256 bytes
  2: 512 bytes
  3: 1024 bytes
2 bytes Number of following bytes (actual sector size in the file, little-endian encoded))


From the header data preceding each sector, the geometry data and thus the floppy disk format can be determined. Since each sector has its own header data, not only can a free sector arrangement be represented, but also different sector lengths within a track. Deleted sectors are, however, not possible in an AnaDisk file, or cannot be marked as such.

When formatting an AnaDisk file in the emulation, the tracks must be formatted seamlessly in ascending order, and within a track, side 1 must be formatted before side 2.

3. CopyQM Files (*.cqm)

JKCEMU supports the file format of the floppy disk copying program CopyQM for both reading and writing. Write support, however, is limited to the manual creation of an image file and to the File Converter. In the JKCEMU Floppy Disk Station window, a CopyQM file can only be opened for reading, because the data area in the file is compressed as a whole and therefore writing an individual sector is not possible.

The CopyQM format is proprietary and not publicly documented. The CopyQM support contained in JKCEMU is based on the few pieces of information freely available on the internet and could therefore be incomplete. For this reason, it cannot be guaranteed that every CopyQM file works in JKCEMU, or that every file created with JKCEMU is accepted by CopyQM.

4. CPC-Disk Files (*.dsk)

The format commonly used by CPC emulators is supported by JKCEMU for both reading and writing. There are two subformats (standard and extended format), both of which are supported. When creating a CPC-Disk file, e.g. in the File Converter, JKCEMU automatically selects the subformat suitable for the specific case.

When formatting a new CPC-Disk file in the emulation, only the standard format is supported, i.e. all tracks must be formatted with the same size. In addition, the tracks must be formatted seamlessly in ascending order, and within a track, side 1 must be formatted before side 2.

5. ImageDisk Files (*.imd)

The file format of the floppy disk archiving tool ImageDisk, developed by Dave Dunfield, is supported by JKCEMU. This file format can also be created during the manual creation of a disk image file and in the File Converter. In the JKCEMU Floppy Disk Station window, on the other hand, only read support is available, because the sector data can be compressed, and thus seamlessly writing an individual sector in the middle of the image file is not readily possible.

The ImageDisk file format is very flexible and can contain deleted sectors as well as store the information as to whether a sector was read with a CRC error.

6. TeleDisk Files (*.td0)

JKCEMU supports TeleDisk files for both writing and reading, but without Advanced Compression. Write support is limited to the manual creation of an image file and to the File Converter. In the JKCEMU Floppy Disk Station window, a TeleDisk file can only be opened for reading, because, as with the ImageDisk format, the sectors in the file may be stored compressed, and thus seamlessly writing an individual sector in the middle of the image file is not readily possible.

TeleDisk is a program for creating and writing back special disk image files (TeleDisk files) and was very popular around 1990. A TeleDisk file contains, in addition to the payload data, very detailed management and geometry data. This allows TeleDisk to produce an almost identical copy of a floppy disk, even if the floppy disk format deviates from the standard.

The TeleDisk file format is very flexible and can, besides deleted sectors, also contain information about sectors read with a CRC error. Furthermore, TeleDisk can also store sectors for which only the data area, but not the header area, was readable. In that case, it generates a sector ID (i.e. it makes one up) and marks the sector accordingly.

Another special feature is that TeleDisk sometimes reads and stores sectors multiple times, i.e. the same sector can be present in the file more than once. Since this, as well as sectors with a generated sector ID, cause problems in the emulator, JKCEMU attempts to repair the data read in from a TeleDisk file if necessary, i.e. to replace a generated sector ID with the probably correct one and to eliminate duplicate sectors. If such a repair takes place, the user is informed about it. The repair applies only to the data read in, not to the file itself, i.e. the file is not modified.

7. Compressed Image Files

Image files can be compressed with GZIP to save disk space. For JKCEMU to correctly recognize such files, a .gz must be appended to the file name (see table). You can compress and decompress them using the File Browser.
