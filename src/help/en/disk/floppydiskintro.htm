Floppy Disk Emulation in JKCEMU

JKCEMU emulates the U8272 floppy disk controller, which is compatible with the Intel 8272A and the NEC 765A. This controller can handle up to four floppy disk drives.

The emulated drives are visible to the user in the JKCEMU Floppy Disk Station window, which you can open from the main window, menu File → Floppy Disk Station. This window is only available if the emulated system originally offers or supports floppy disk drives as well. Furthermore, only as many drives are emulated as are actually possible in the original.

Each drive has its own tab. In addition, you will find a button in the lower right of the window for opening/loading, which lets you conceptually insert and remove a floppy disk. Since the emulator computer may not have any physical floppy disk drive at all, JKCEMU offers several options for emulating a floppy disk. An emulated floppy disk can be represented by:
  1. a real floppy disk inserted in a physical floppy disk drive connected to the emulator computer
  2. a disk image file
  3. a directory in the file system of the emulator computer

Pressing the Open/Load button opens a menu in which you can select the various options.

1. Emulation with a Real Floppy Disk

If you want to access, from the emulated system, a floppy disk inserted in a floppy disk drive connected to the emulator computer, then select Open floppy disk... in the Open/Load menu. You will then be asked for the drive. On a Windows system, select the drive letter under which the floppy disk drive is visible in Windows. On a Linux/Unix system, specify the corresponding device file.

Caution! On a Linux/Unix system, JKCEMU may have to run with administrator privileges (user name root) in order to access the floppy disk drive.

When emulating a floppy disk drive with a real floppy disk, the following restrictions apply:
  • The physical floppy disk format, i.e. the number of tracks, the number of sectors per track, and the sector size, must be supported by the hardware and the operating system of the emulator computer. Newer operating systems and USB floppy disk drives probably only support 512 byte sectors anymore.

  • The logical format, i.e. the CP/M file system, on the other hand, does not need to be supported by the emulator computer (and usually is not supported), i.e., you will not be able to see the files on the floppy disk in the file system of the emulator computer.

  • The emulator cannot detect a floppy disk change. It is therefore important, before ejecting the floppy disk, to select Close floppy disk/image file in the menu Open/Load in the JKCEMU Floppy Disk Station window. If you should forget to do so, just do it afterwards. Under no circumstances should you insert a different floppy disk with a different floppy disk format without closing the floppy disk first and try to write to it! If you do this, you must expect data loss!

  • If you format the floppy disk in the emulated system, it is not physically formatted, but only overwritten. Therefore, formatting in the emulation is only possible if the new format is identical to the old one. If the formats differ, a write error is emulated, and the formatting program should also report this error.

Caution! If the floppy disk contains a CP/M file system or another "old" file system, the operating system of the emulator computer will probably not be able to do anything with it. In that case, Windows will offer to format the volume. Under no circumstances should you do that, or all the data will be gone! Furthermore, it can happen that when a USB floppy disk drive is connected with a floppy disk inserted that has an "old" file system, the floppy disk drive is not recognized correctly. Therefore, always connect a USB floppy disk drive without a floppy disk inserted, and only insert the floppy disk once the operating system has recognized the drive and the drive's access indicator has gone out.

2. Emulation with a Disk Image File

A disk image file (Disk Image File) is a 1:1 image of a floppy disk and thus also contains the tracks and sectors as found on a real floppy disk. There are various file formats for image files, which differ in content mainly in the amount of geometry and management data stored.

3. Mapping an Emulated Floppy Disk to a Directory

With this form, you select a directory in the file system of the emulator computer. The files located in that directory that conform to the CP/M file naming convention are packed into a virtual floppy disk and are thus visible from the emulated system. This provides a very simple way to exchange files between the emulator computer and the system running in the emulator.

When the virtual floppy disk is full, the remaining files in the directory are ignored. The same applies to files that are too large.

User areas 1 through 15 are represented by subdirectories named 1 through 15, i.e. files in these subdirectories will then appear in the corresponding user area.

After selecting the directory, you will be asked for the floppy disk format. For a format with system tracks, the contents of the file @boot.sys are copied into these system tracks. This makes it possible to boot from a directory as well. If the file @boot.sys is not found in the directory, the system tracks contain zero bytes.

Caution! JKCEMU also offers write support for a floppy disk that is emulated on the basis of a directory. To do this, open the directory without write protection. In that case, write accesses to the virtual floppy disk directly affect the underlying files, i.e. the files located in the directory. If the configured directory size does not match the one used by the program or operating system running in the emulator, or if you refresh the emulated floppy disk at an unfavorable time (see further below), this can lead to deletion or unintended overwriting of the underlying files and thus to data loss! It is even worse if the program running in the emulator incorrectly writes to the directory sectors of the virtual floppy disk. For these reasons, it is strongly recommended to open a directory for floppy disk emulation without write protection only if the files contained in it are also backed up in another location!

3.1. Refreshing the Emulated Floppy Disk

When a floppy disk is emulated on the basis of a directory, it is possible that the files located in the directory are also used and modified by other programs besides the emulator. If the changes made in the directory are to be reflected in the emulated floppy disk as well, it must be refreshed. To do this, select in the menu on the Open/Load button the item Refresh emulated floppy disk. As soon as the directory is next read from the emulated floppy disk, JKCEMU generates new content for the floppy disk. With a CP/M-compatible operating system in the emulator, you should press Control-C or Ctrl-C to trigger reading of the directory.

JKCEMU also offers automatic refreshing. To use it, you must enable the option Refresh automatically in the dialog for selecting the floppy disk format.

Caution! Some programs or operating systems may not cope well with automatic refreshing of the floppy disk contents and may therefore read incorrect data. In that case, you must turn off the option.

Caution! If you have opened the directory without write protection, you should be sure to only refresh the emulated floppy disk at times when the program or operating system running in the emulator is in its input loop and is not currently accessing the floppy disk! In addition, you should always force the directory to be re-read (Control-C or Ctrl-C).

Caution! If you want to open the directory without write protection and with automatic refreshing, you should definitely back up the files in the directory beforehand at another location, since this is a potentially especially critical combination. Please test extensively whether the operating system and the application programs running in the emulator cope well with the automatic refreshing and whether it does not lead to data loss or otherwise corrupted files. Every time the files in the directory are changed by programs outside of the emulation, you should force the directory to be re-read in the emulator with Control-C or Ctrl-C.

3.2. DateStamper

If you have selected a floppy disk format with DateStamper support, the emulated floppy disk automatically contains the file !!!TIME&.DAT, in which the timestamps of the individual files are stored. Any timestamp file that may already exist in the directory is ignored in this case.

Write accesses to the file !!!TIME&.DAT cause the timestamps of the files in the directory to be set, provided the Java runtime environment used and the file system allow the timestamps to be set.
