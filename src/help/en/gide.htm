GIDE and Hard Disks

Tilmann Reh developed a solution for connecting IDE hard disks to 8-bit computers. The solution is called GIDE (Generic IDE) and has also been rebuilt for computer types emulated by JKCEMU. For this reason, JKCEMU also includes a GIDE emulation, with which up to two hard disks can be emulated.

To emulate a hard disk, you must enable the GIDE emulation in the Settings for the respective system, on the GIDE tab, and select the hard disk model and an image file. To help you select the hard disk model, JKCEMU provides a hard disk directory that already contains a number of suitable models. You can change and extend this directory as you like. When entering a new hard disk model, you must enter the geometry data.

The data stored on the emulated hard disk physically resides in the image file. This file does not necessarily have to exist. If it does not exist, it is created on the first write access that the emulated system makes to the hard disk (e.g. when formatting).

The GIDE also contains a real-time clock. In the emulator, the time can only be read, not set.

Caution! If you enable the GIDE module but have not configured a hard disk to be emulated, the module is still emulated. In that case, however, only the real-time clock contained on the GIDE module is practically usable.

File Formats for Hard Disk Image Files

For the emulation of hard disks, JKCEMU supports two kinds of image files:
  1. Plain image files
  2. Plain image files with a 256 byte header block

The first format, also called the RAW format, is identical to the plain image files used for floppy disk emulation. JKCEMU can create image files in this format from a volume (see here).

The second format is supported for reasons of compatibility with other emulators. The 256 byte header block is neither evaluated nor written by JKCEMU.

When a file is opened, its type is detected from the file length (RAW files must end on a 512-byte boundary). When creating a new file, you are asked which type you want.

Image files in both formats can also be written back to a volume with JKCEMU (see here).
