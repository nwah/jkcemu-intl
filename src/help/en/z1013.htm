Z1013

The Z1013 microcomputer kit is a single-board computer that was manufactured from 1985 onward at VEB Robotron-Elektronik Riesa. This kit was aimed at hobbyists and tinkerers, who only had to solder the supplied membrane keyboard and a self-supplied (i.e. not included) 12V transformer onto the already fully assembled circuit board.

The original idea behind the Z1013 was to make use of electronic components that did not meet industrial requirements (so-called reject components, which were functionally fine but, for example, did not reach the required clock frequencies) in the form of a relatively low-clocked computer kit for the general population. As a result, the Z1013 initially had a clock frequency of only 1 MHz (model Z1013.01) and, at 690 Marks, was the cheapest computer available in the GDR that had video output and could thus be considered a fully-fledged home computer. It was also available to private buyers through an official channel right from the start, although only from the Robotron shop in Erfurt and with a waiting time of about a year.

However, the idea of using reject components for the Z1013 turned out to be unfavorable for the manufacturer, since for warranty reasons the components ultimately had to be individually tested and measured anyway. For this reason, from 1987 onward the Z1013 was shipped with "fully specified" components and a 2 MHz clock frequency (model Z1013.16). This, however, also raised the price to 965 Marks. In 1989 the Z1013.64 model was released, which had 64 KByte of RAM and had dropped in price to 590 Marks. In the spring of 1990, before the introduction of the Deutschmark in the GDR, the Z1013 was offered in Erfurt for only 99 Marks.

In 2016, dedicated hobbyists presented the Z1013-128 (occasionally also called Z1013.128), in which a number of blemishes in the original hardware design were fixed. It also offers a few optional expansions, among them 128 KByte of RAM, which is where its name comes from. The hardware configuration can be adjusted very flexibly by means of a whole series of jumpers. In the default settings of these jumpers, the Z1013-128 essentially corresponds to a Z1013.64 with an additional switchable 32 KByte EPROM in the address range 8000h-FFFFh. This ROM, and thus implicitly also the Z1013-128 in its default settings, is optionally emulated.

1. Emulated Hardware

Since the Z1013 was sold as a kit, a particularly large number of modifications and expansions have been developed for it. This applies especially to the keyboard, the monitor program, and the RAM size. JKCEMU emulates the common keyboards together with one or more matching monitor programs each. In the Settings you select the desired combination of monitor program and keyboard.

1.1. Membrane Flat Keyboard

On the membrane flat keyboard, the digits are by default reachable only via the Shift-1 key. However, in the monitor program and via system calls, the shift levels can be switched so that digits can be entered without the Shift key. In that case, for some letters the Shift-1 key must be pressed instead. This recoding of characters, however, interferes with the emulator. For this reason, JKCEMU automatically detects the switching of the shift levels and then emulates the pressing of the Shift-1 key accordingly differently. As a result, the monitor commands A and H appear to have no effect.

Altogether, the membrane flat keyboard has four Shift keys, which are also polled directly by some game programs and used to control the game character. So that you can also operate such programs without restrictions in the emulator, these four Shift keys are also emulated as individual keys, namely with the function keys F1 through F4.

A keyboard view is available for the membrane flat keyboard.

1.2. Alpha Keyboard

The alpha keyboard is the keyboard required by the A.2 monitor program. However, this is not a ready-made keyboard, but only a circuit for connecting a keyboard with an 8x8 matrix. The circuit diagram for it and the prescribed arrangement of the keys in the matrix are given in the supplementary manual for the Z1013.16. A schematic key arrangement is also given there. This is available in the emulator as a keyboard view.

With the exception of the Graph I/O key, all keys or characters of the alpha keyboard can usually also be found on the keyboard of the computer running the emulator. The Graph I/O key can be operated with the function key F1.

1.3. Peters Board

The Peters board makes it possible, via I/O port 4, to disable the ROM and to switch the character set, the clock frequency, and the screen organization.

1.4. Mega-ROM Module

The Mega-ROM module, already known from the Z9001, KC85/1, and KC87 and adapted to the Z1013, offers 2.5 MByte of memory, divided into 256 individual 10 KByte segments. The currently active segment is mapped into the address range C000h-E7FFh. Switching the active segment is done via an output instruction to I/O address FFh. Unlike with the Z9001, KC85/1, and KC87, the Z1013 variant of the module cannot be switched off by software.

JKCEMU does not include any content for the Mega-ROM module. You must therefore provide a suitable ROM file yourself and select it in the settings.

1.5. 32K ROM Corresponding to the Z1013-128

The Z1013-128 contains an additional EPROM, which can be mapped into the address range 8000h-FFFFh by outputting a set bit 5 to I/O address 4. However, the range EC00h-FFFFh is only visible if bit 4 is also set at the same time, which switches off the video RAM and the system ROM.

This 32K EPROM is optionally emulated in accordance with the Z1013-128 default settings. JKCEMU does not include any content for this ROM. You must therefore provide a suitable ROM file yourself and select it in the settings.

Caution! The switchable 32K ROM corresponding to the Z1013-128 also comes with emulation of the clock frequency switch via I/O address 4, bit 6.

1.6. Printer

There are two ways to emulate a printer:
  1. Intercepting the corresponding jump table calls
  2. Emulating a Centronics interface at the user port

With the first variant, the calls for printer output are intercepted at the jump table and appended to the current print job. No printer driver is needed. However, this variant only works with programs that also use the jump table for printer output.

With the second variant, either a printer driver is required, or the application program addresses the Centronics interface itself. Data output on the emulated Centronics interface is appended to the current print job.

1.7. Joysticks

Several hardware variants for connecting joysticks to the Z1013 have been published, along with a corresponding software interface. JKCEMU can emulate both the three common hardware variants and the software interface. However, which type of emulation you need to enable depends on the specific game or application program.

Some programs directly poll the user port to which the joysticks are connected. In that case, you must select the correct joystick hardware in the settings, area Z1013, tab User Port.

If, on the other hand, the game or application program uses the software interface, then enable the option Intercept jump table calls for joystick queries on the Miscellaneous tab. In that case, JKCEMU emulates the joystick driver that is normally invoked via the jump table for joystick queries. Alternatively, you can also disable this option and load a suitable joystick driver yourself, which provides the connection between the software interface and the (emulated) hardware.

1.9. USB Connector (Vinculum VDIP Module)

The USB module is emulated at the I/O base addresses DCh and FCh. If the Mega-ROM module is enabled, the USB module is emulated only at the base address DCh, since otherwise there would be a conflict with I/O address FFh.

1.10. Real-Time Clock Module

A real-time clock RTC-62421 or RTC-72421 is emulated at I/O addresses 70h to 7Fh. The clock can only be read, not set.

1.11. Full Graphics per practic 2/1988

The ZX Spectrum-compatible full graphics expansion presented in the magazine practic 2/1988 is emulated as a second display unit (menu Extra → Second Display Unit...). This graphics expansion has a 6 KByte pixel memory for the 256x192 pixels (address range 4000h-57FFh), but not the color attribute memory found on the ZX Spectrum. The screen output is therefore black and white, with white as the background color. A set bit in the pixel memory results in a black pixel.

The graphics expansion also generates the interrupt, known from the ZX Spectrum, during the vertical sync pulse. Since the hardware does not support an interrupt vector or a daisy chain, this interrupt can practically only be used in interrupt mode 1. In addition, the interrupt registration of all other interrupt sources is disrupted (e.g. the PIO, which triggers interrupts for the single-step mode of the monitor program (command B)).

In the original, the graphics card does not generate a MEMDI signal, i.e. the memory on the Z1013 main board or a memory expansion is not switched out. If other memory is present in the address range of the pixel memory, the graphics expansion is configured so that the pixel memory can only be written to.

1.12. Full Graphics per KRT 11 and FA 7/1991

The book Kleinstrechnertips 11 (KRT 11) presented a fairly simple circuit that gives the Z1013 full graphics capabilities. A slightly modified version of this circuit was published again in the magazine Funkamateur 7/1991 (FA 7/1991). Both circuit variants are optionally emulated.

The principle of the circuit is fairly simple: instead of the original video RAM, there are 8 RAM banks in parallel, with each RAM bank representing one pixel row within a character row. If RAM bank 0 is active, the address range EC00h to EFFFh gives access to all topmost pixel rows within the character rows. With RAM bank 7, it is all bottommost pixel rows within the character rows. The RAM bank is selected via the lower 3 bits of output address 8 (the same I/O address as for the keyboard columns). The pixel data is inverted, i.e. a cleared bit results in a white pixel.

You can switch between full graphics and the original text mode in software. This switching differs between the two circuit variants:

FunctionKRT 11FA 7/1991
Full graphics on Output of an 8 to the lower 4 bits of I/O address 8 Input or output instruction with any data byte at address 0Ch to 0Fh
Full graphics off
(original text mode back on) 		Output of a 9 to the lower 4 bits of I/O address 8 Input or output instruction with any data byte at address 10h to 13h

Both circuit variants are emulated in parallel, i.e. in the emulator you can switch on full graphics per KRT 11 and switch it off again per FA 7/1991.

1.13. CC Jena Graphics Card

The Computerclub Jena developed a graphics card that uses the graphics display controller U82720. Although a graphics processor is used, the card can only output text at the hardware level. The resolution is usually 80x25 characters.

The graphics card contains an 8 KByte EPROM as the character generator. Several character sets can be stored in it, the desired one of which can be selected through corresponding programming of the graphics processor. The character generator built into JKCEMU for this graphics card contains only one complete character set. However, in the settings, by loading a ROM file of up to 8 KByte, you can fill the character generator with different content.

The graphics card is emulated as a second display unit (menu item Extra → Second Display Unit...).

1.14. Color Graphics Card with 32x32 and 64x32 Characters

Heiko Poppe developed a color graphics card for text output, which also exists in a special variant for the Z1013. This variant is optionally emulated.

The graphics card offers the two output formats 32x32 and 64x32 characters. The video RAM is located in the address range E800h-EFFFh and consists of a text memory and a color memory. In the 32x32-character output format, the address mapping is identical to the Z1013 standard, i.e. only the range from EC00h-EFFFh is displayed. In this output format, the Z1013 character set is used.

In the 64x32-character output format, two character sets with a character size of 8x6 pixels are supported, between which you can switch. However, JKCEMU only includes one ASCII character set for this, so switching the character set has no effect. If you want to use the character set switching, you must specify a 4 KByte character set file on the Graphics Expansions tab in the Z1013 settings. The first 2 KByte of it are used as the first character set and the second 2 KByte as the second character set.

The color graphics card has a control register that can be accessed via two input/output addresses. The table shows the meaning of the individual bits of this register and the access options:

Caution! Since the Z1013 monitor programs included in JKCEMU do not initialize the color memory, after a RESET you see a colorful random image in which the text output is difficult to make out. For this reason, the color graphics card is emulated as a second display unit. The original Z1013 screen output thus remains visible. For this to work technically, the video RAM of the graphics card is only accessible for writing. Write accesses in the address range E800h-EFFFh therefore go into the Z1013 RAM, i.e. the original video RAM, and in parallel also into the video RAM of the color graphics card. Reads in the address range E800h-EFFFh, on the other hand, are only from the Z1013 memory, not from the graphics card. In the original, this corresponds to the connection variant in which the graphics card does not generate a /MEMDI signal and thus does not switch out the memory on the Z1013 main board.

4. Miscellaneous

4.1. Saving, Loading and Opening BASIC Programs

JKCEMU offers special support for saving and loading BASIC programs as well as for opening BASIC programs residing in RAM in the text editor. You can find the corresponding functions in the File menu.

The following BASIC interpreters are supported:
  • Z1013-BASIC version 3.1 (Tiny-BASIC)
  • HC-BASIC in RAM (KC-BASIC)
  • HC-BASIC in ROM (KC-BASIC)

When saving BASIC programs, a window appears for selecting the file format. Please save Tiny-BASIC programs as a Headersave file (*.z80) with file type b, and KC-BASIC programs either as a KC-BASIC program file (*.sss) or as a Headersave file (*.z80) with file type B.

If you save a BASIC program in a different file format, JKCEMU will later, when loading the file, no longer recognize that it is a BASIC program and will not adapt the system cells of the BASIC interpreter. The loaded program cannot then be used.

4.2. Pasting Text

Pasting text from the clipboard is usually done by simulating, for each character to be pasted, the pressing of the corresponding key or key combination. This approach is fairly slow. For the Z1013, the settings offer the option Paste text by intercepting the system call. With this option, the emulator listens at the entry address for the INKEY system function. When this system function is called, JKCEMU checks whether a character should be pasted. If so, it writes the next character to be pasted into the corresponding processor register and simulates a RETURN instruction. If the operating system or the application program does not poll the keyboard via the INKEY system function, pasting text will not work, and you must turn the option off.

With this option, JKCEMU must know the start address of the INKEY function. This is the case for the monitor programs built into the emulator. However, if you start a different operating system or, by loading an external ROM image, use a different monitor program in which the INKEY function begins at a different address, you must likewise turn the option off.
