BASIC Compiler

Data Types

The JKCEMU BASIC compiler knows the following data types:
  • Integer for whole numbers in the range -32767 to +32767
  • Long for whole numbers in the range -2147483647 to +2147483647
  • Decimal for whole numbers and floating-point numbers with up to 11 decimal digits, of which a maximum of 7 are decimal places
  • Single for floating-point numbers in the range ±10-38 to ±10+38 with a precision of 6 decimal digits
  • String for character strings

Integer

With the numeric data type Integer, numbers are stored internally in 16-bit two's complement. This means the value range also includes the number -32768. However, this number cannot always be computed, because its absolute value (+32768), which must be formed internally for some calculations, is no longer within the value range. For this reason, only numbers from -32767 to +32767 are fully usable with Integer. Mathematical calculations with the data type Integer are especially fast, faster than with any other numeric data type.

Long

Long is a numeric data type that stores whole numbers in 32-bit two's complement. Analogous to Integer, there is also a number for Long that belongs to the value range but is not fully usable: -2147483648.

Decimal

This data type stores numbers as packed BCD numbers in 6 bytes (BCD: Binary Coded Decimal, packed: two digits per byte). The uppermost nibble contains the sign (1 bit) and the number of decimal places (3 bit). This results in 11 decimal digits, 0 to 7 of which are decimal places. The following numbers can therefore be stored:

  -99999999999 to 99999999999 or
  -9999999999.9 to 9999999999.9 or
  ...
  -9999.9999999 to 9999.9999999

The smallest representable magnitude is: 0.0000001

As you can see, Decimal can also be used to store floating-point numbers. Unlike the data type Single (see further below), which can likewise store floating-point numbers, Decimal represents the numbers in the decimal system. As a result, mathematical calculations are considerably slower, but no rounding errors arise from conversions between the decimal and binary systems. Decimal is therefore especially suited to cases where even the last digit must be calculated exactly, e.g. for monetary amounts. Rounding errors can nevertheless still occur, namely whenever the result of a calculation has more decimal places than the data type can hold. In that case, the error variables ERR and ERR$ are set accordingly. This allows you to check in the program with

  IF ERR=E_DIGITS_TRUNCATED THEN ...

whether decimal places were truncated during the last Decimal calculation, or whether the mathematically exact result could be calculated.

Single

Single is a numeric data type for binary floating-point numbers of single precision, corresponding to the IEEE 754 standard. The numbers are represented with an 8 bit exponent and a 24 bit mantissa (32 bit total). This results in a number range of roughly ±10-38 to ±10+38 with a precision of about seven decimal digits. However, the data type stores the numbers in approximated form. This means that not every decimal floating-point number can be represented exactly in numeric form. Many numbers must be stored with a numeric value that only approximately corresponds to the decimal value. This results in rounding errors, which grow larger with every mathematical calculation. The precision can therefore also be less than seven decimal digits. In order not to feign a higher precision than is actually present, numbers of the data type Single are rounded to 6 decimal digits on output, i.e. when converted to a decimal number.

Because of the large number range of Single, numbers can also be written with a decimal exponent, both in the BASIC source code and when entering data with the INPUT statement. Here are a few examples:

ExampleMeaning
1.23E7 1.23 * 10^7 = 12300000
2E+4 2 * 10^4 = 20000
4.5e-3 4.5 * 10^-3 = 0.0045
-0.00678E5 -0.00678 * 10^5 = -678

The smallest representable magnitude greater than zero is 1.17549E-38. If a mathematical calculation results in a value with a smaller magnitude, the result is zero, even if it is mathematically not actually zero.

Example:

2E-30 * 3E-20 mathematically gives 6E-50. However, this cannot be represented with the data type Single. The result is therefore 0.

The largest representable magnitude is 3.40283E+38. If the result of a mathematical calculation is larger than that, the compiled program aborts with a numeric overflow error.

The advantage of Single over Decimal lies in the considerably higher calculation speed. For this reason, some mathematical functions that require complex calculations are available only for Single.

The name Single is only customary in the BASIC programming language. In other programming languages, this data type is often called Float. For this reason, the JKCEMU BASIC compiler also allows the keyword FLOAT to be used instead of SINGLE.

Note: Although the data type Single corresponds in its properties to the single-precision floating-point data type defined in the IEEE 754 standard, it is not implemented exactly according to the standard. Specifically, the sign and exponent are swapped, since this is considerably easier to implement on an 8-bit processor. Furthermore, the special values +Infinity, -Infinity and NaN are not supported, since they do not occur in the language concept of the JKCEMU BASIC compiler.

String

The data type String is used to store character strings and is always marked with a trailing $ character, i.e. all variables and functions whose names end in a dollar sign are string variables or string functions that store or return a character string. Further information can be found on the page: String Handling

Type Conversions

There are implicit and explicit type conversions. Implicit means that the compiler automatically performs the necessary type conversion. This happens wherever a numeric data type with a smaller value range is specified at a position where a numeric data type with a larger value range is expected. This affects, for example, operators with two operands and certain function arguments. The implicit type conversion always goes from the smaller to the larger value range, i.e. in this direction:

Integer → Long → Decimal → Single

In the other direction, i.e. when a numeric data type was specified that has a larger value range than intended at the position in question, the type conversion must be performed explicitly. In that case, the software developer must ensure that the value range is not exceeded. If it is, the compiled program aborts with an overflow error.

For an explicit type conversion, a BASIC function explicitly specified by the software developer in the source code of the BASIC program is called, which performs the type conversion. The following functions are available for this:
  • CDEC (Integer, Long, Single → Decimal)
  • CINT (Decimal, Long, Single → Integer)
  • CLNG (Decimal, Integer, Single → Long)
  • CSNG (Decimal, Integer, Long → Single)
  • DECVAL (String → Decimal)
  • INTVAL (String → Integer)
  • LNGVAL (String → Long)
  • SNGVAL (String → Single)
  • VAL (String → Integer)

In a broader sense, these functions also serve type conversion:
  • ASC (String → Integer)
  • BIN$ (Integer, Long → String)
  • CHR$ (Integer → String)
  • HEX$ (Integer, Long → String)
  • OCT$ (Integer, Long → String)
  • STR$ (Decimal, Integer, Long, Single → String)
