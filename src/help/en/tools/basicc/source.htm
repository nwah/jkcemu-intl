1. File format

The BASIC program is the source code for the compiler. It must be in the form of a plain text file. When programming within JKCEMU, the built-in Text Editor is well suited for this. With it, it is possible to have the compiled program automatically loaded directly into the emulator's main memory. If you want to use a different text editor, you can translate the BASIC program with the command-line version of the compiler.

2. Upper/lower case

Upper/lower case does not matter except in strings and character constants. All statements, functions, procedures, variables and labels can be written in any mix of upper case, lower case, or a combination of both. For better readability, blank lines can be inserted, and statements and syntax elements can be indented or separated with spaces.

3. Line numbers

The compiler understands BASIC programs both in the classic form with line numbers at the start of each line and without line numbers. Specifically for the second case, labels were introduced as a replacement for line numbers.

The example shows a program with and without line numbers. In the version without line numbers, a label is used. Labels are described in the next section.

Program with line numbers Program without line numbers
10 I=0
20 I=I+1
30 PRINT I
40 IF I<100 THEN GOTO 20
50 END 		I=0
schleife:
I=I+1
PRINT I
IF I<100 THEN GOTO schleife
END


Line numbers appearing in the BASIC program are referred to in JKCEMU and in the help as BASIC line numbers.

4. Labels

There are BASIC statements that refer to a line number, e.g. GOTO, GOSUB, RESTORE. If you now work without BASIC line numbers, you need a different way to reference a place in the source code. For this, the BASIC compiler has labels. A label is a marker for a source code line with a freely chosen name, which, however, must not be a reserved keyword and must also not otherwise match the name of any variable, function or procedure.

A label must stand alone on a line, begin at the start of the line (no leading spaces) and be terminated with a colon. It is referenced without the colon. The example demonstrates the use of a label named datenanfang.

RESTORE datenanfang
...
datenanfang:
  DATA 1,2,3

Caution! Nothing else may follow the closing colon of a label on that line, so that the compiler can syntactically distinguish a label from a statement.

5. Syntax of a program line

There are three kinds of program lines:
  1. Blank line
  2. Line with a label
  3. Line with statements

Blank lines are used for better readability. A line with a label is used to mark a place in the source code and is a replacement for BASIC line numbers. Lines with statements can contain one or more statements. In the case of several statements, they are separated from each other by a colon. A list of the statements can be found here.

Blank lines and lines with statements can contain a BASIC line number. This is not possible for lines with a label.

6. Comments

For comments, there is the statement REM. Instead of the keyword REM, an exclamation mark or an apostrophe (quote character) can also be written. A comment always runs to the end of the line, even if the comment contains a colon.

Examples of comments:

REM Comment
!Comment
'Comment
A=100:REM Comment
B=200:!Comment
C=300:'Comment: still a comment
