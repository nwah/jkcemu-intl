BASIC Compiler

String Handling

The JKCEMU BASIC compiler offers extensive support for the handling of strings. This support includes string variables for storage, functions for processing, and statements for input and output of strings. The notes on string handling are divided into the following sections:

1. Length limit of a string

The internal string handling can process strings up to a length of 255 characters. Longer strings are truncated.

The length limit does not apply to string literals, the functions INSTR, LEN, LTRIM$ and MEMSTR$, or to the output of strings.

2. String literals

A string literal is a string constant, i.e. the string is already written in the BASIC source code. A string literal is a sequence of characters enclosed in double quotation marks.

Syntax: " <character_sequence> "

3. String variables

String variables are used to store strings, where the limit of a maximum of 255 characters likewise applies. Both simple variables and array variables can be used to store strings.

The name of a string variable must end with a $ character.

4. String functions

The term string function has a double meaning. In the semantic sense, it refers to a function in which strings play a role, i.e. in which a string is passed in or returned. In the syntactic sense, only functions that return a string are string functions. These functions have a $ as the last character in their name.

Some of the string functions create a new string. Memory is needed for this, but only briefly, because once the current statement has been executed, the resulting string has either been processed or, in the case of a LET statement, stored in a variable. Either way, temporary memory is needed for internal string handling. The JKCEMU BASIC compiler uses a static string buffer for this. In contrast to dynamically allocating and freeing memory areas, this static approach makes it possible to generate fast and compact program code. However, this also entails a few minor limitations: the static string buffer can be used by only one function at a time. For this reason, such functions cannot be nested inside themselves, or put another way: when functions are nested inside each other, at most one of them may use the static string buffer. The following functions use the internal string buffer:
  • BIN$
  • CHR$
  • HEX$
  • INPUT$
  • LEFT$
  • LOWER$
  • MID$
  • MIRROR$
  • RTRIM$
  • SPACE$
  • STRING$
  • TRIM$
  • UPPER$

If the limitation regarding the nesting of string functions is not observed, the compiler issues an appropriate error message. However, the need to nest these string functions inside each other may still arise. In that case you must use a variable as a helper: you store the result of the inner string function in a variable and then use that variable as the argument in the outer one, e.g.:

Problem (compiler error)Solution
A$="Das ist ein Beispiel."
B$=TRIM$(MID$(A$,4,5)) 		A$="Das ist ein Beispiel."
M$=MID$(A$,4,5)
B$=TRIM$(M$)


5. String expressions

The BASIC compiler distinguishes between simple and complex string expressions. A complex string expression consists of simple string expressions concatenated with the plus operator. A simple string expression is either a string literal, a string variable, or the call of a string function.

Complex string expressions are only allowed in output and when assigning a variable, e.g.:

A$="Hallo"
B$="Welt"
C$=A$+SPACE$(1)+B$
LABEL "--"+C$+"--"

As arguments in function calls, only simple string expressions are allowed. Here too, a variable must be used for intermediate storage if needed.

6. Optimizations

6.1. Avoiding unnecessary assignments

String handling requires considerably more computing time than handling Integer values. In particular, storing strings in string variables is very costly in terms of performance, since memory must be dynamically allocated and freed again as needed. For this reason, the number of variable assignments should be kept as low as possible, and unnecessary assignments should be avoided. Furthermore, when working with individual characters, they should where possible be converted to Integer values and then processed further as such. The following table shows both of these optimization possibilities, using keyboard polling with INKEY$ as an example:

Slower code Faster code Even faster code
E$=INKEY$
IF E$="A" THEN ... 		IF INKEY$="A" THEN ...

→ variable assignment saved 		IF ASC(INKEY$)='A' THEN ...

→ Integer comparison instead of String comparison

Caution! As soon as you use even a single string variable, and thus a single assignment to a string variable, anywhere in the BASIC program, the compiled BASIC program will also contain the entire program code for internal dynamic memory management. So if you do not need any string handling in the program and would only use a string variable because of functions such as INKEY$, you should apply the above optimization, not only for the sake of better performance, but also because of a significantly smaller binary program.

6.2. Accessing parts of a string

For extracting part of a string, there is the function MID$. Internally, the extracted substring is then provided as a new string in a different memory area. If you only want to access individual characters of a string, you can also do this while bypassing the string handling, and thus more efficiently, with the functions STRPTR and PEEK. However, you must take care yourself not to go past the end of the string. This is marked with a null byte. The example shows how you can count the number of upper-case letters in a string:

T$=...
A=STRPTR(T$)
N=0
DO
  B=PEEK(A)
  A=A ADD 1
  IF B=0 THEN EXIT
  IF B>=65 AND B<=90 THEN N=N+1
LOOP
PRINT N;"Groessbuchstaben enthalten"
