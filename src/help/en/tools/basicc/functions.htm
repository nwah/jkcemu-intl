1. Data Type of the Return Value

Functions whose name ends with a $ character return a string. All others have a numeric return value, whose data type is given in the Return row of the respective table. System variables whose name ends with a $ character contain a string, all others an Integer value.

2. Arguments

The arguments, or parameters, are written in parentheses after the function name. For functions without arguments (e.g. INKEY$) these parentheses are omitted.

3. System Variables

System variables behave like functions without arguments. They can be read, but not written to directly. System variables are set by the system. Some can also be set with the help of special statements (e.g. XPOS and YPOS by the MOVE statement).

Since system variables behave like functions from the software developer's point of view, they are listed and described here in the function overview.

4. Accuracy of the Mathematical Functions

For the mathematical functions  ATN,  COS,  EXP,  LN,  POW,  SIN,  SQR and  TAN the respective result is calculated using an iterative approximation method. For this reason, and because of the limited accuracy of the Single data type, these functions usually do not return the mathematically exact result, but a value that comes very close to it. As a rule, the accuracy is 6 decimal places, which also corresponds to the accuracy with which values of the Single data type are displayed. However, this accuracy cannot be guaranteed in every case. Especially at the edges of the range, e.g. with very small or very large numbers or near zero crossings, the accuracy can be lower.

For the trigonometric functions, which expect an angle in radians as their argument, the accuracy also decreases if the angle lies outside the normal range of 0 to 2π (especially if it lies far outside that range), since the angle first has to be converted into that range.

6. Description of the Functions and System Variables

Elements enclosed in angle brackets serve as placeholders and must be replaced accordingly.

ABS

Syntax: ABS ( <value> )
Value: numeric expression
Return: same type as the value passed

The function returns the absolute value of the value passed.

ASC

Syntax: ASC ( <string> )
String:simple string expression
Return:Integer

The function returns the code of the first character in the string passed. If the string is empty, 0 is returned.

ASM

Syntax: ASM ( <string> [, <string> [, ...]] )
String:string literal
Return:Integer

The ASM function inserts one or more assembler lines into the assembler text generated by the compiler. Unlike the ASM statement, the ASM function returns the value in the HL register to the BASIC program. In combination with the MEMSTR$ function, strings generated in your own assembler routines can also be returned to the BASIC program.

The example shows a possible use of the ASM function in combination with USR, as a way of passing a parameter to the assembler routine and having it return a numeric value:

DEF USR0 = ASM(" LD HL,meine_negation")
PRINT USR0(123)
END

ASM "meine_negation:"
ASM " LD HL,0000H"
ASM " OR A"
ASM " SBC HL,DE"
ASM " RET"

In the second example, the assembler routine returns the string ABC:

PRINT MEMSTR$( ASM(" CALL meine_routine") )
END

ASM CODE "meine_routine:"
ASM CODE " LD HL,mein_string"
ASM CODE " RET"
ASM DATA "mein_string: DB 'ABC',0"

Caution! Please read the notes on including your own assembler source code!

ATN

Syntax: ATN ( <value> )
Value: numeric expression
Return: Single

The function calculates the arc tangent of the value passed. Please also read the notes on accuracy of the mathematical functions!

BIN$

Syntax: BIN$ ( <value> )
BIN$ ( <value> , <number of digits> )
Value:Integer or Long expression
Number of digits:Integer
Return:String

The function BIN$ generates a string that represents the value passed as a binary number. Negative values are represented in two's complement. If the second argument is omitted, the generated string is 16 characters long for an Integer value and 32 characters long for a Long value.

The optional second argument can be used to specify the length of the binary number to be generated. Possible values are 0 to 16 for an Integer expression and 0 to 32 for a Long expression. With a value of 0, the binary number is generated without leading zeros, with as many digits as are needed to represent the value completely. With a digit count greater than 0, the binary number has as many digits as specified, starting from the right, i.e. with the least significant digits.

CDEC

Syntax: CDEC ( <numeric expression> )
Return: Decimal

The function converts the value passed into a Decimal value. If the conversion is not possible, e.g. because the magnitude of the value passed is too large, the program aborts with an overflow error.

CHR$

Syntax: CHR$ ( <character code> )
Character code:Integer expression
Return:String

The function CHR$ generates a string consisting of only the one character that corresponds to the character code passed (usually the ASCII code). If the value 0 is passed, the returned string is empty.

Caution! With the statements PRINT and LPRINT, CHR$(0) outputs a null byte.

CINT

Syntax: CINT ( <numeric expression> )
Return: Integer

The function converts the integer part of the value passed into an Integer value. The fractional part is lost in the process. If the conversion is not possible because the magnitude is too large, the program aborts with an overflow error.

CLNG

Syntax: CLNG ( <numeric expression> )
Return: Long

The function converts the integer part of the value passed into a Long value. The fractional part is lost in the process. If the conversion is not possible because the magnitude is too large, the program aborts with an overflow error.

COS

Syntax: COS ( <angle> )
Angle: numeric expression with the angle in radians
Return: Single

The function calculates the cosine of the angle, which must be given in radians. Please also read the notes on accuracy of the mathematical functions!

CRSLIN

This system variable contains the current line number the cursor is in, starting at 0. If the cursor is outside the visible area, or the target system does not support reading the cursor position, the variable contains the value -1.

CRSPOS

This system variable contains the current column number the cursor is in, starting at 0. If the cursor is outside the visible area, or the target system does not support reading the cursor position, the variable contains the value -1.

The system variable provides the same information as the function POS and is included for reasons of name analogy with CRSLIN.

CSNG

Syntax: CSNG ( <numeric expression> )
Return: Single

The function converts the value passed into a Single value.

DATETIME$

Syntax: DATETIME$ ( <format string> )
Format string:simple string expression
Return: String

The function DATETIME$ returns a string with the current date and/or the current time. You specify the appearance of the string with a format string. In the format string, certain letters or groups of letters serve as placeholders for the individual elements of the date or the time. The returned string corresponds to the format string, with the placeholders replaced accordingly.

The placeholders can be written in either upper or lower case. All characters that are not placeholders are copied unchanged into the returned string.

The following placeholders are possible:

PlaceholderMeaning
Dday, one or two digits
DDday, always two digits
Mmonth, one or two digits
MMmonth, always two digits
Yyear, one digit (units only)
YYyear, two digits (tens and units)
YYYYyear, four digits
Hhour (0 to 23), one or two digits
HHhour (0 to 23), always two digits
MIminute, always two digits
Ssecond, one or two digits
SSsecond, always two digits


Example:

PRINT "Heute ist der ";DATETIME$("D.MM.YYYY.")
PRINT "Datum heute: ";DATETIME$("DD.MM.YYYY")
PRINT "Akt. Zeit: ";DATETIME$("H:MI:SS")
PRINT "Datum / Zeit: ";DATETIME$("YYYY-MM-DD HH:MI:SS")

Caution: The function can only return a meaningful string if the computer on which the compiled BASIC program is running also has a clock. By default, an attempt is made to read the date and time from the real-time clock of a connected GIDE. If no GIDE is connected, or the target system supports neither a GIDE nor any other way of reading the system time, an empty string is returned.

DECVAL

Syntax: DECVAL ( <string> )
String:simple string expression
Return: Decimal

The function DECVAL attempts to read the contents of a string as a number and returns its numeric value as a Decimal value. The function sets the error variables ERR and ERR$. These, especially the ERR variable, can be used to check whether the function was successful:

ERR valueMeaning
E_OK the number could be read
E_DIGITS_TRUNCATED The number could be read, but contains too many decimal places that do not fit into the Decimal data type. These decimal places were truncated, i.e. the returned value does not exactly correspond to the number in the string passed.
E_INVALID invalid characters read, return value is 0
E_OVERFLOW numeric overflow, i.e. the number has too many digits before the decimal point, return value is 0

For converting a string into another numeric data type, there are the functions INTVAL (identical to VAL), LNGVAL and SNGVAL.

DEEK

Syntax: DEEK ( <address> )
Address:Integer expression
Return:Integer

The function reads two consecutive bytes from memory starting at the specified address and returns them as a 16-bit value. The first byte is the least significant.

DIV10

Syntax: DIV10 ( <value> )
Value:Decimal expression
Return:Decimal

Decimal numbers can be divided by 10 very quickly by shifting the decimal point one place to the left. That is exactly what the function DIV10 does. This makes it considerably faster than dividing by 10 using the division operator. Since this fast division is only possible with decimal numbers, the function can only be used with the Decimal data type.

DIV2

Syntax: DIV2 ( <value> )
Value:Integer, Long or Single expression
Return: same data type that was passed

Just as decimal numbers can be divided by 10 very quickly by shifting the decimal point, binary numbers can be divided by 2 very quickly. That is what the function DIV2 is for. Since this fast division is only possible with binary numbers, the function can only be used with the data types Integer, Long and Single.

EOF

Syntax: EOF ( <channel> )
EOF ( # <channel> )
Channel: Integer expression
Return:Integer

The function tests whether the end of the input channel or file has been reached. This sets the error variables ERR and ERR$.

For files, the function only reliably returns TRUE once an attempt has been made to read past the end of the file.

ERR

The system variable ERR contains the last error code. The value 0 (constant E_OK) means that no error occurred in the last statement or function that affects the error variable. A value other than 0 stands for an error. Error code constants are available for evaluating the ERR system variable.

The ERR system variable is reset at the beginning of each BASIC statement in which the system variable is itself set or affected by the statement or by function calls. This ensures that no error condition is lost even when several function calls within one statement affect the error variable. The following example illustrates this:

OPEN #1,"datei.dat"
...:REM Pruefen, ob Oeffnen der Datei erfolgreich war
PRINT "Hex=";HEX$(VAL(INPUT$(5,#1));" Text=";INPUT$(10,#1)
IF ERR THEN
  PRINT ERR$
ENDIF


The file datei.dat begins with two data fields, each with a fixed, predefined field length. The first field is 5 bytes in size and contains a number in text form. The second field, 10 bytes in size, contains a string. In the first PRINT statement, the following happens in order:
  1. The first data field is read from the file as a string.
  2. The string that was read is converted into a numeric value.
  3. This value is converted into a hexadecimal number and output on the screen.
  4. The second data field is read from the file and output.

Both read operations, as well as the conversion into a numeric value, can fail and affect the ERR variable. If, for example, the first data field contained something that cannot be interpreted as a number, the VAL function sets the ERR system variable. If the subsequent reading of the second data field is then successful, the error information from the VAL function should nevertheless not be lost. And that is exactly what is ensured by resetting the ERR system variable only at the beginning of the relevant statement. In the example above, the ERR variable (apart from at program start) is reset to zero only at the beginning of the first PRINT statement. Since the subsequent IF statement only reads the ERR variable and does not set it, no reset takes place there, and, as intended, you read the error information from the preceding statement.

Another case where this behavior is important is calculations with the DECIMAL data type. You can safely perform several individual DECIMAL calculations within one statement and then test whether decimal places were truncated in the process (IF ERR=E_DIGITS_TRUNCATED THEN ...). If the result had to be shortened in one of the calculations, the ERR system variable is guaranteed to be set accordingly, even if subsequent DECIMAL calculations within the same statement completed correctly.

Caution! The fact that the ERR system variable is reset at the beginning of the relevant statement must be taken into account when reading it. If the ERR variable is both read and set within one statement, the error information from the preceding statement is lost. The statements in a THEN or ELSE branch of an IF or ELSEIF statement count as separate statements in this respect, i.e. you can safely evaluate the error status of the preceding statement in the condition of an IF or ELSEIF statement and then use statements in the THEN or ELSE branch that affect the ERR system variable again.

ERR$

The system variable ERR$ contains the last error text. In combination with the system variable ERR, error handling can be implemented quite simply and still conveniently for the user, e.g.:

...:'Funktion oder Anweisung, die die Fehlervariablen setzt
IF ERR THEN
  PRINT ERR$
ELSE
  ...:'kein Fehler aufgetreten
ENDIF

Caution! If you use the system variable ERR$, the compiled program becomes correspondingly larger, since all error messages that can occur also have to be compiled into the program. If you are aiming for as small a program as possible and can do without the detailed error texts, you should evaluate only the error code variable ERR and not use ERR$.

Caution! Regarding the resetting of the system variable ERR$, the same applies as for the system variable ERR.

EXP

Syntax: EXP ( <value> )
Value:numeric expression
Return: Single

The function EXP is the exponential function with base e (see constant EULER) and is thus the inverse function of the natural logarithm (see function LN). For exponentiation with any base, there is the function POW. Please also read the notes on accuracy of the mathematical functions!

FIX

Syntax: FIX ( <numeric expression> )
Return: same data type that was passed

The function returns the integer part of the value passed, i.e. the part before the decimal point.

FRAC

Syntax: FRAC ( <value> )
Value:numeric expression
Return: same data type that was passed

The function returns the fractional part of the value passed. The result is always greater than or equal to zero, even if the value passed is less than zero.

Caution! If you pass the function a Single value and output both the value passed and the result on the screen, the decimal digits shown for the two numbers may differ. This is because the binary stored values do not necessarily correspond exactly to the displayed or entered decimal numbers (see approximate values under the Single data type), and these values are rounded to 6 decimal places when output.

Example:

PRINT FRAC(654.321)

Mathematically, the example should return 0.321, but 0.320984 is displayed. This is because the number 654.321 cannot be stored exactly as such using the Single data type, and the resulting error component is magnified enough by separating out the fractional part and converting it into a new floating-point number that it becomes visible in the output. The FRAC function in combination with the Single data type is therefore intended primarily for internal calculations. So

PRINT FIX(654.321)+FRAC(654.321)

again yields the value 654.321 (FIX returns the integer part). The following program shows that the split into an integer and a fractional part is numerically exact. To remove all doubt, the integer part is converted with CINT into an Integer value and then with CSNG back into a Single value.

DIM A AS SINGLE
DIM V AS INTEGER
DIM N AS SINGLE
A=654.321
V=CINT(FIX(A))
N=FRAC(A)
IF CSNG(V)+N=A THEN PRINT "OK":ELSE:PRINT "nicht OK"

With the Decimal data type, this effect does not occur, since the values are stored numerically exactly. So

PRINT FRAC(654.321D)

yields exactly the value 0.321. The appended D gives the number the Decimal data type.

HEX$

Syntax: HEX$ ( <value> )
HEX$ ( <value> , <number of digits> )
Value:Integer or Long expression
Number of digits:Integer
Return:String

The function HEX$ generates a string that represents the value passed as a hexadecimal number. Negative values are represented in two's complement. If the second argument is omitted, the generated string is four characters long for an Integer value and eight characters long for a Long value.

The optional second argument can be used to specify the length of the hexadecimal number to be generated. Possible values are 0 to 4 for an Integer expression and 0 to 8 for a Long expression. With a value of 0, the hexadecimal number is generated without leading zeros, with as many digits as are needed to represent the value completely. With a digit count greater than 0, the hexadecimal number has as many digits as specified, starting from the right, i.e. with the least significant digits.

HIBYTE

Syntax: HIBYTE ( <value> )
Value:Integer expression
Return:Integer

The function returns only the value of the high-order byte of the value passed, i.e. the return value is always in the range 0 to 255.

The function HIBYTE has the same effect as (<value> SHR 8) AND &H00FF, but generates shorter and faster program code.

HIWORD

Syntax: HIWORD ( <value> )
Value:Long expression
Return:Long

The function returns only the value of the high-order 16 bits of the Long value passed, i.e. the return value is always in the range 0 to 32767.

The function HIWORD has the same effect as (<value> SHR 16) AND &H0000FFFF, but generates shorter and faster program code.

H_CHAR

The system variable contains the height of the screen in character positions, i.e. the number of visible text lines is returned. If this value is not clearly defined, or if the target system allows different values (e.g. with CP/M), the variable contains the value -1.

A 0 is returned if the SCREEN statement has set a graphics screen that does not permit text output.

H_PIXEL

This system variable contains the height of the fully graphics-capable screen in pixels. If no full graphics mode is available, the value 0 is returned. In that case, the graphics commands cannot be used.

INKEY$

The function checks whether a key is currently pressed. If so, the function returns a string containing the character entered. Otherwise, an empty string is returned. INKEY$ has no arguments.

IN
INP

Syntax: IN ( <address> )
INP ( <address> )
Address:Integer expression
Return:Integer

The functions IN and INP read a byte from the input port specified by the address and return the value of the byte.

Both functions are identical. For reasons of compatibility with various BASIC dialects, both function names are supported.

Caution! Although the microprocessor officially only supports 8-bit input/output addresses, using 16-bit addresses is possible. The compiler translates the statement into program code that, due to the undocumented behavior of the microprocessor, also makes a 16-bit input/output address take effect.

INPUT$

Syntax: INPUT$ ( <count> )
INPUT$ ( <count> , <channel> )
INPUT$ ( <count> , # <channel> )
Count: Integer expression in the range 0 to 255
Channel: Integer expression
Return:String

There are two variants of this function, with and without a channel number. In the variant without a channel number, the specified number of characters is read from the keyboard and returned as a string. Control keys (e.g. cursor keys, Enter) are not evaluated. Instead, the corresponding control codes appear in the string. Nothing is output on the screen.

In the variant with a channel number, the function reads the specified number of characters from the input channel or the file and returns them as a string. This sets the error variables ERR and ERR$.

Caution! Null bytes serve as terminators for strings, i.e. if a null byte is read, the returned string contains only the bytes up to the first null byte read. Nevertheless, as many bytes are read from the input channel as were specified in the first argument. So if the returned string is shorter than the number of bytes read, and the error variable ERR contains the value 0 (constant E_OK, no error occurred), then a null byte was read after the string. This also makes it possible, in general, to read binary files. The example shows how a file is read byte by byte and output as a hex dump on the screen:

INPUT "Datei:";F$
OPEN F$ FOR BINARY INPUT AS #1
IF ERR THEN
  PRINT ERR$
ELSE
  N=0
  WHILE NOT EOF(#1)
    B=ASC(INPUT$(1,#1))
    IF ERR THEN
      PRINT ERR$:EXIT
    ELSE
      PRINT CHR$(32);HEX$(B,2);
      N=N+1
      IF N=8 THEN N=0:PRINT
    ENDIF
  WEND
  PRINT
  IF ERR THEN PRINT ERR$
  CLOSE #1
ENDIF

INSTR

Syntax: INSTR ( <string to search in> , <string to search for> )
INSTR ( <position> , <string to search in> , <string to search for> )
Position:Integer expression
String to search in: simple string expression
String to search for: simple string expression
Return:Integer

The function searches the first string passed for the second string passed and returns the position where it was found. If the second string is not contained in the first, 0 is returned. If a position was specified, the search starts from that position.

Examples:

PRINT INSTR("ABCD","C")

returns 3.

PRINT INSTR(3,"KASKADE","K")

returns 4.

Caution! With this function, there are differences in argument order between the various BASIC dialects. In most of the internationally common BASIC dialects, the first string is the one to be searched and the second is the one to search for. For this reason, JKCEMU implements it the same way. In KC-BASIC, however, it is exactly the other way around. So if you want to compile or port KC-BASIC programs, you must swap the two strings.

INT

Syntax: INT ( <numeric expression> )
Return: Single

The function rounds the value passed down to the next smaller whole number. If the value passed is already a whole number, the same value is returned.

Examples:

INT( 2.3 ) returns 2
INT( -2.0 ) returns -2
INT( -2.3 ) returns -3
INT( -3.1D ) returns -4

For values greater than or equal to 0, the function returns the same results as FIX.

INTVAL

Syntax: INTVAL ( <string> )
INTVAL ( <string> , <number base> )
String:simple string expression
Number base: Integer expression with the value 2, 10 or 16
Return: Integer

The function INTVAL is identical to the function VAL and is described there. The function name INTVAL makes it clear that an Integer value is returned and exists for reasons of name analogy with DECVAL (returns Decimal), LNGVAL (returns Long) and SNGVAL (returns Single).

IS_TARGET

The function IS_TARGET determines whether the program was compiled for a specific target system. This lets you write portable BASIC programs while still adapting them to very specific characteristics of the target system. The function is usually called with a constant for the target system. The following example demonstrates its use:

IF IS_TARGET(TARGET_KC85) THEN PRINT "Ich bin ein KC85/2..5 oder HC900"
IF IS_TARGET(TARGET_Z9001) THEN PRINT "Ich bin ein KC85/1, KC87 oder Z9001"
IF IS_TARGET(TARGET_Z1013) THEN PRINT "Ich bin ein Z1013"

Caution! The function IS_TARGET also returns TRUE if compiling for a derived target system and testing against the more general target system, i.e. if, for example, the target system TARGET_KC85_4 (KC85/4..5 with support for both video memories) is set in the compiler options, the function returns TRUE for both TARGET_KC85 and TARGET_KC85_4.

Caution! The function IS_TARGET does not determine which type of computer the program is actually running on, but for which type of computer the BASIC program was compiled. For example, a program can be compiled for the AC1 but still run on an LLC2, if it does not use anything AC1-specific. The function IS_TARGET(TARGET_AC1) would then still return TRUE, and IS_TARGET(TARGET_LLC2) would return FALSE.

JOYST

Syntax: JOYST ( <joystick number> )
Joystick number: Integer expression with a value >= 0
Return:Integer

The function reads the current status of the specified joystick. The first joystick has the number 0. The bit assignment of the return value differs between the individual target systems and should therefore be evaluated using the following constants:

ConstantMeaning
JOYST_LEFT joystick pushed left
JOYST_RIGHT joystick pushed right
JOYST_UP joystick pushed up
JOYST_DOWN joystick pushed down
JOYST_BUTTON1 action button 1 pressed
JOYST_BUTTON2 action button 2 pressed
JOYST_BUTTONS action button 1 or 2 pressed

The JOYST function returns an Integer value in which each set bit stands for a specific action. Several bits can be set at the same time, e.g. the bits for left and up, when the joystick is pushed to the upper left. The joystick constants are defined such that the respective bit for the action in question is set. With the help of the AND operator, the individual actions can be tested:

A=JOYST(0)
IF A AND JOYST_LEFT THEN PRINT "links"
IF A AND JOYST_RIGHT THEN PRINT "rechts"
IF A AND JOYST_DOWN THEN PRINT "runter"
IF A AND JOYST_UP THEN PRINT "hoch"
IF A AND JOYST_BUTTON1 THEN PRINT "Feuer 1"
IF A AND JOYST_BUTTON2 THEN PRINT "Feuer 2"
IF A AND JOYST_BUTTONS THEN PRINT "Feuer 1 oder 2"

On a target system that supports only one fire button per joystick, the constant JOYST_BUTTONS has the same value as JOYST_BUTTON1, and JOYST_BUTTON2 is 0. On systems that offer no joystick support, the JOYST function always returns 0, and the joystick constants also all have the value 0.
