1. Data Type of the Return Value

Functions whose name ends with a $ character return a string. All others have a numeric return value, whose data type is given in the respective table in the Return row. System variables whose name ends with a $ character contain a string, all others an integer value.

2. Arguments

The arguments, or parameters, are written in parentheses after the function name. For functions without arguments (e.g. INKEY$) these parentheses are omitted.

3. System Variables

System variables behave like functions without arguments. They can be read but not written to directly. System variables are set by the system. Some can also be set with the help of special statements (e.g. XPOS and YPOS via the MOVE statement).

Since system variables behave like functions from the software developer's point of view, they are listed and described here in the function overview.

4. Accuracy of the Mathematical Functions

For the mathematical functions  ATN,  COS,  EXP,  LN,  POW,  SIN,  SQR and  TAN the respective result is calculated using an iterative approximation method. For this reason, and because of the limited accuracy of the Single data type, these functions usually do not deliver the mathematically exact result, but rather a value that comes very close to it. As a rule, the accuracy is 6 decimal places, which also corresponds to the accuracy with which values of the Single data type are displayed. However, this accuracy cannot be guaranteed in every case. Especially at the boundaries, e.g. for very small or very large numbers or near zero crossings, the accuracy can be lower.

For the trigonometric functions, which expect an angle in radians as their argument, the accuracy also degrades if the angle lies outside the normal range of 0 to 2π (especially if it lies far outside that range), since it must first be converted back into that range.

6. Description of the Functions and System Variables

Elements enclosed in angle brackets serve as placeholders and are to be replaced accordingly.

ABS

Syntax: ABS ( <value> )
Value: numeric expression
Return: same type as the value passed in

The function returns the absolute value of the value passed in.

ASC

Syntax: ASC ( <string> )
String:simple string expression
Return:Integer

The function returns the code of the first character in the string passed in. If the string is empty, 0 is returned.

ASM

Syntax: ASM ( <string> [, <string> [, ...]] )
String:string literal
Return:Integer

The ASM function inserts one or more assembler lines into the assembler text generated by the compiler. Unlike the ASM statement, the ASM function returns the value in the HL register to the BASIC program. Combined with the MEMSTR$ function, it can also be used to return strings created in your own assembler routines to the BASIC program.

The example shows a possible use of the ASM function in combination with USR, in order to pass a parameter to the assembler routine this way and have it return a numeric value:

DEF USR0 = ASM(" LD HL,meine_negation")
PRINT USR0(123)
END

ASM "meine_negation:"
ASM " LD HL,0000H"
ASM " OR A"
ASM " SBC HL,DE"
ASM " RET"

In the second example, the assembler routine returns the string ABC:

PRINT MEMSTR$( ASM(" CALL meine_routine") )
END

ASM CODE "meine_routine:"
ASM CODE " LD HL,mein_string"
ASM CODE " RET"
ASM DATA "mein_string: DB 'ABC',0"

Attention! Please read the notes on including your own assembler source code!

ATN

Syntax: ATN ( <value> )
Value: numeric expression
Return: Single

The function calculates the arc tangent of the value passed in. Please also read the notes on the accuracy of the mathematical functions!

BIN$

Syntax: BIN$ ( <value> )
BIN$ ( <value> , <number of digits> )
Value:Integer or Long expression
Number of digits:Integer
Return:String

The BIN$ function creates a string that represents the value passed in as a binary number. Negative values are represented as two's complement. If the second argument is omitted, the string created is 16 characters long for an Integer value and 32 characters long for a Long value.

With the optional second argument, the length of the binary number to be created can be specified. Possible values are 0 to 16 for an Integer expression and 0 to 32 for a Long expression. With a value of 0, the binary number is created without leading zeros, using as many digits as are necessary to represent the value in full. With a digit count greater than 0, the binary number has as many digits as specified, counted from the right, i.e. starting with the least significant digits.

CDEC

Syntax: CDEC ( <numeric expression> )
Return: Decimal

The function converts the value passed in into a Decimal value. If the conversion is not possible, e.g. because the magnitude of the value passed in is too large, the program aborts with an overflow error.

CHR$

Syntax: CHR$ ( <character code> )
Character code:Integer expression
Return:String

The CHR$ function creates a string consisting of only the one character that corresponds to the character code passed in (usually an ASCII code). If the value 0 is passed in, the string returned is empty.

Attention! With the PRINT and LPRINT statements, CHR$(0) outputs a null byte.

CINT

Syntax: CINT ( <numeric expression> )
Return: Integer

The function converts the integer part of the value passed in into an Integer value. The fractional part is lost in the process. If the conversion is not possible because the magnitude is too large, the program aborts with an overflow error.

CLNG

Syntax: CLNG ( <numeric expression> )
Return: Long

The function converts the integer part of the value passed in into a Long value. The fractional part is lost in the process. If the conversion is not possible because the magnitude is too large, the program aborts with an overflow error.

COS

Syntax: COS ( <angle> )
Angle: numeric expression with the angle in radians
Return: Single

The function calculates the cosine of the angle, which must be given in radians. Please also read the notes on the accuracy of the mathematical functions!

CRSLIN

This system variable contains the current line number on which the cursor is positioned, starting at 0. If the cursor is outside the visible area, or the target system does not support reading the cursor position, the variable contains the value -1.

CRSPOS

This system variable contains the current column number on which the cursor is positioned, starting at 0. If the cursor is outside the visible area, or the target system does not support reading the cursor position, the variable contains the value -1.

The system variable provides the same information as the function POS and is included for the sake of naming symmetry with CRSLIN.

CSNG

Syntax: CSNG ( <numeric expression> )
Return: Single

The function converts the value passed in into a Single value.

DATETIME$

Syntax: DATETIME$ ( <format string> )
Format string:simple string expression
Return: String

The DATETIME$ function returns a string with the current date and/or the current time. You determine the appearance of the string with a format string. In the format string, certain letters or letter groups serve as placeholders for the individual elements of the date and/or the time. The string returned corresponds to the format string, with the placeholders replaced accordingly.

The placeholders can be written in either upper or lower case. All characters that are not placeholders are copied unchanged into the string returned.

The following placeholders are possible:

PlaceholderMeaning
Dday, one or two digits
DDday, always two digits
Mmonth, one or two digits
MMmonth, always two digits
Yyear, one digit (units only)
YYyear, two digits (tens and units)
YYYYyear, four digits
Hhour (0 to 23), one or two digits
HHhour (0 to 23), always two digits
MIminute, always two digits
Ssecond, one or two digits
SSsecond, always two digits


Example:

PRINT "Heute ist der ";DATETIME$("D.MM.YYYY.")
PRINT "Date today: ";DATETIME$("DD.MM.YYYY")
PRINT "Current time: ";DATETIME$("H:MI:SS")
PRINT "Date / time: ";DATETIME$("YYYY-MM-DD HH:MI:SS")

Attention: The function can only return a meaningful string if the computer on which the compiled BASIC program is running also has a clock. By default, the function tries to read the date and time from the real-time clock of a connected GIDE. If no GIDE is connected, or the target system supports neither a GIDE nor any other way of reading the system time, an empty string is returned.

DECVAL

Syntax: DECVAL ( <string> )
String:simple string expression
Return: Decimal

The DECVAL function tries to read the content of a string as a number and returns its numeric value as a Decimal value. The function sets the error variables ERR and ERR$. These, especially the ERR variable, can be used to check whether the function was successful:

ERR valueMeaning
E_OK the number could be read
E_DIGITS_TRUNCATED The number could be read, but contains too many decimal places that do not fit into the Decimal data type. These decimal places were truncated, i.e. the value returned does not exactly correspond to the number in the string passed in.
E_INVALID invalid characters encountered, return value is 0
E_OVERFLOW numeric overflow, i.e. the number has too many digits before the decimal point, return value is 0

For converting a string into a different numeric data type, there are the functions INTVAL (identical to VAL), LNGVAL and SNGVAL.

DEEK

Syntax: DEEK ( <address> )
Address:Integer expression
Return:Integer

The function reads two consecutive bytes from main memory starting at the specified address and returns them as a 16-bit value. The first byte is the low-order one.

DIV10

Syntax: DIV10 ( <value> )
Value:Decimal expression
Return:Decimal

Decimal numbers can be divided by 10 very quickly by shifting the decimal point one place to the left. That is exactly what the function DIV10 does. This makes it considerably faster than dividing by 10 with the division operator. Since this fast division is only possible with decimal numbers, the function can only be used with the Decimal data type.

DIV2

Syntax: DIV2 ( <value> )
Value:Integer, Long or Single expression
Return: same data type that was passed in

Just as decimal numbers can be divided by 10 very quickly by shifting the decimal point, binary numbers can be divided by 2 very quickly. That is what the function DIV2 is for. Since this fast division is only possible with binary numbers, the function can only be used with the data types Integer, Long and Single.

EOF

Syntax: EOF ( <channel> )
EOF ( # <channel> )
Channel: Integer expression
Return:Integer

The function tests whether the end of the input channel or the file has been reached. In doing so, the error variables ERR and ERR$ are set.

For files, the function only reliably returns TRUE once an attempt has been made to read past the end of the file.

ERR

The system variable ERR contains the last error code. The value 0 (constant E_OK) means that no error occurred during the last statement or function that affects the error variable. A value other than 0 indicates an error. For evaluating the error variable ERR, there are error code constants.

The ERR system variable is reset at the beginning of every BASIC statement in which the system variable is set or affected by the statement itself or by function calls. This ensures that no error state is lost even if several function calls within one statement affect the error variable. The following example illustrates this:

OPEN #1,"datei.dat"
...:REM Check whether opening the file succeeded
PRINT "Hex=";HEX$(VAL(INPUT$(5,#1));" Text=";INPUT$(10,#1)
IF ERR THEN
  PRINT ERR$
ENDIF


The file datei.dat begins with two data fields, each with a fixed, predefined field length. The first field is 5 bytes in size and contains a number in text form. The second field, 10 bytes in size, contains a string. In the first PRINT statement, the following happens in order:
  1. The first data field is read from the file as a string.
  2. The string read is converted into a numeric value.
  3. This value is converted into a hexadecimal number and output to the screen.
  4. The second data field is read from the file and output.

Both of the read operations, as well as the conversion into a numeric value, can fail and affect the ERR variable. If, for example, the first data field contained something that cannot be interpreted as a number, the VAL function would set the ERR system variable. If the subsequent reading of the second data field then succeeds, the error information from the VAL function must not be lost. And that is exactly what is ensured by resetting the ERR system variable only at the beginning of the relevant statement. In the example above, the ERR variable (apart from at program start) is reset to zero only at the beginning of the first PRINT statement. Since the following IF statement only reads the ERR variable and does not set it, no reset takes place there, and, as desired, you read the error information from the preceding statement.

Another case where this behavior is important is calculations with the DECIMAL data type. You can safely perform several individual DECIMAL calculations within one statement and afterward test whether decimal places were truncated in the process (IF ERR=E_DIGITS_TRUNCATED THEN ...). If the result had to be truncated in any one of the calculations, the ERR system variable is guaranteed to be set accordingly, even if subsequent DECIMAL calculations in the same statement completed correctly.

Attention! The resetting of the ERR system variable at the beginning of the relevant statement must be kept in mind when reading it. If, within one statement, the ERR variable is both read and set, the error information from the preceding statement is lost. The statements in a THEN or ELSE branch of an IF or ELSEIF statement are considered separate statements in this regard, i.e. you can safely evaluate the error status of the preceding statement in the condition of an IF or ELSEIF statement and then use statements in the THEN or ELSE branch that again affect the ERR system variable.

ERR$

The system variable ERR$ contains the last error text. Combined with the system variable ERR, error handling can be made quite simple while still being comfortable for the user, e.g.:

...:'Function or statement that sets the error variables
IF ERR THEN
  PRINT ERR$
ELSE
  ...:'kein Fehler aufgetreten
ENDIF

Attention! If you use the system variable ERR$, the compiled program becomes correspondingly larger, since all error messages that can occur also have to be compiled into the program. If you want as small a program as possible and can do without the detailed error texts, you should evaluate only the error code variable ERR and not use ERR$.

Attention! Regarding the resetting of the system variable ERR$, the same applies as for the system variable ERR.

EXP

Syntax: EXP ( <value> )
Value:numeric expression
Return: Single

The function EXP is the exponential function with base e (see constant EULER) and thus forms the inverse function of the natural logarithm (see function LN). For exponentiation with an arbitrary base, there is the function POW. Please also read the notes on the accuracy of the mathematical functions!

FIX

Syntax: FIX ( <numeric expression> )
Return: same data type that was passed in

The function returns the integer part of the value passed in, i.e. the part before the decimal point.

FRAC

Syntax: FRAC ( <value> )
Value:numeric expression
Return: same data type that was passed in

The function returns the fractional part of the value passed in. The result is always greater than or equal to zero, even if the value passed in is less than zero.

Attention! If you pass a Single value to the function and output both the value passed in and the result to the screen, the decimal digits shown for the two numbers can differ. This is because the values stored in binary do not necessarily correspond exactly to the decimal numbers displayed or entered (see the approximated values for the Single data type), and these values are rounded to 6 decimal places for output.

Example:

PRINT FRAC(654.321)

Mathematically, the example should return 0.321, but 0.320984 is displayed instead. This is because the number 654.321 cannot be stored exactly as such with the Single data type, and the resulting error component is magnified during the separation of the fractional part and its conversion into a new floating-point number, to the point where it becomes visible in the output. The FRAC function used with the Single data type is therefore intended mainly for internal calculations. For example,

PRINT FIX(654.321)+FRAC(654.321)

again yields the value 654.321 (FIX returns the integer part). With the following program you can see that the separation into integer and fractional parts is numerically exact. To remove all doubt, the integer part is converted with CINT into an Integer value and then back into a Single value with CSNG.

DIM A AS SINGLE
DIM V AS INTEGER
DIM N AS SINGLE
A=654.321
V=CINT(FIX(A))
N=FRAC(A)
IF CSNG(V)+N=A THEN PRINT "OK":ELSE:PRINT "nicht OK"

With the Decimal data type, this effect does not occur, since the values are stored numerically exactly. For example,

PRINT FRAC(654.321D)

yields exactly the value 0.321. The appended D gives the number the Decimal data type.

HEX$

Syntax: HEX$ ( <value> )
HEX$ ( <value> , <number of digits> )
Value:Integer or Long expression
Number of digits:Integer
Return:String

The function HEX$ creates a string that represents the value passed in as a hexadecimal number. Negative values are represented as two's complement. If the second argument is omitted, the string created is four characters long for an Integer value and eight characters long for a Long value.

With the optional second argument, the length of the hexadecimal number to be created can be specified. Possible values are 0 to 4 for an Integer expression and 0 to 8 for a Long expression. With a value of 0, the hexadecimal number is created without leading zeros, using as many digits as are necessary to represent the value in full. With a digit count greater than 0, the hexadecimal number has as many digits as specified, counted from the right, i.e. starting with the least significant digits.

HIBYTE

Syntax: HIBYTE ( <value> )
Value:Integer expression
Return:Integer

The function returns only the value of the high-order byte of the value passed in, i.e. the return value is always in the range 0 to 255.

The function HIBYTE has the same effect as (<value> SHR 8) AND &H00FF, but produces shorter and faster program code.

HIWORD

Syntax: HIWORD ( <value> )
Value:Long expression
Return:Long

The function returns only the value of the high-order 16 bits of the Long value passed in, i.e. the return value is always in the range 0 to 32767.

The function HIWORD has the same effect as (<value> SHR 16) AND &H0000FFFF, but produces shorter and faster program code.

H_CHAR

The system variable contains the height of the screen in character positions, i.e. the number of visible text lines is returned. If this value is not clearly defined, or if the target system allows different values (e.g. with CP/M), the variable contains the value -1.

A 0 is returned if the SCREEN statement was used to set a graphics screen that does not allow text output.

H_PIXEL

This system variable contains the height of the fully graphics-capable screen in pixels. If no full graphics mode is available, the value 0 is returned. In that case, the graphics commands cannot be used.

INKEY$

The function checks whether a key is currently being pressed. If so, the function returns a string containing the character entered. Otherwise, an empty string is returned. INKEY$ has no arguments.

IN
INP

Syntax: IN ( <address> )
INP ( <address> )
Address:Integer expression
Return:Integer

The functions IN and INP read a byte from the input port specified by the address and return the value of the byte.

Both functions are identical. For reasons of compatibility with various BASIC dialects, both function names are supported.

Attention! Although the microprocessor officially only supports 8-bit input/output addresses, it is possible to use 16-bit addresses. The compiler translates the statement into program code that, due to the undocumented behavior of the microprocessor, also causes a 16-bit input/output address to take effect.

INPUT$

Syntax: INPUT$ ( <count> )
INPUT$ ( <count> , <channel> )
INPUT$ ( <count> , # <channel> )
Count: Integer expression in the range 0 to 255
Channel: Integer expression
Return:String

There are two variants of the function, with and without a channel number. In the variant without a channel number, the specified number of characters is read from the keyboard and returned as a string. Control keys (e.g. cursor keys, Enter) are not evaluated. Instead, the corresponding control codes appear in the string. No output to the screen takes place.

In the variant with a channel number, the function reads the specified number of characters from the input channel or the file, and returns them as a string. In doing so, the error variables ERR and ERR$ are set.

Attention! Null bytes serve as terminators for strings, i.e. if a null byte is read, the string returned contains only the bytes up to the first null byte read. Nevertheless, as many bytes are read from the input channel as were specified in the first argument. So if the string returned is shorter than the number of bytes read, and the error variable ERR contains the value 0 (constant E_OK, no error occurred), then a null byte was read after the string. This also makes it possible, in general, to read binary files. The example shows how a file is read byte by byte and output to the screen as a hex dump:

INPUT "File:";F$
OPEN F$ FOR BINARY INPUT AS #1
IF ERR THEN
  PRINT ERR$
ELSE
  N=0
  WHILE NOT EOF(#1)
    B=ASC(INPUT$(1,#1))
    IF ERR THEN
      PRINT ERR$:EXIT
    ELSE
      PRINT CHR$(32);HEX$(B,2);
      N=N+1
      IF N=8 THEN N=0:PRINT
    ENDIF
  WEND
  PRINT
  IF ERR THEN PRINT ERR$
  CLOSE #1
ENDIF

INSTR

Syntax: INSTR ( <string searched> , <string sought> )
INSTR ( <position> , <string searched> , <string sought> )
Position:Integer expression
String searched: simple string expression
String sought: simple string expression
Return:Integer

The function searches the first string passed in for the second string passed in and returns the position of the match. If the second string is not contained in the first, 0 is returned. If a position was specified, the search starts at that position.

Examples:

PRINT INSTR("ABCD","C")

returns 3.

PRINT INSTR(3,"KASKADE","K")

returns 4.

Attention! With this function, there are differences in argument order between the various BASIC dialects. In most internationally common BASIC dialects, the first string is the one searched and the second is the one sought. For this reason, this is also how it is implemented in JKCEMU. In KC-BASIC, however, it is exactly the other way around. So if you want to compile or port KC-BASIC programs, you must swap the two strings.

INT

Syntax: INT ( <numeric expression> )
Return: Single

The function rounds the value passed in down to the next smaller whole number. If the value passed in is already a whole number, the same value is returned.

Examples:

INT( 2.3 ) returns 2
INT( -2.0 ) returns -2
INT( -2.3 ) returns -3
INT( -3.1D ) returns -4

For values greater than or equal to 0, the function returns the same results as FIX.

INTVAL

Syntax: INTVAL ( <string> )
INTVAL ( <string> , <number base> )
String:simple string expression
Number base: Integer expression with the value 2, 10 or 16
Return: Integer

The function INTVAL is identical to the function VAL and is described there. The function name INTVAL makes it clear that an Integer value is returned, and it exists for the sake of naming symmetry with DECVAL (returns Decimal), LNGVAL (returns Long) and SNGVAL (returns Single).

IS_TARGET

The function IS_TARGET determines whether the program was compiled for a specific target system. This lets you write portable BASIC programs while still adapting them to very specific characteristics of the target system. You usually call the function with a constant for the target system. The following example demonstrates its use:

IF IS_TARGET(TARGET_KC85) THEN PRINT "Ich bin ein KC85/2..5 oder HC900"
IF IS_TARGET(TARGET_Z9001) THEN PRINT "Ich bin ein KC85/1, KC87 oder Z9001"
IF IS_TARGET(TARGET_Z1013) THEN PRINT "Ich bin ein Z1013"

Attention! The function IS_TARGET also returns TRUE when compiling for a derived target system and testing against the more general target system, i.e. if, for example, the compiler options have the target system TARGET_KC85_4 (KC85/4..5 with support for both video memories) set, the function returns TRUE for both TARGET_KC85 and TARGET_KC85_4.

Attention! The function IS_TARGET does not determine which type of computer the program is actually running on, but rather which type of computer the BASIC program was compiled for. For example, a program can be compiled for the AC1 but still run on an LLC2, if it does not use anything AC1-specific. The function IS_TARGET(TARGET_AC1) would then still return TRUE and IS_TARGET(TARGET_LLC2) would return FALSE.

JOYST

Syntax: JOYST ( <joystick number> )
Joystick number: Integer expression with a value >= 0
Return:Integer

The function reads the current status of the specified joystick. The first joystick has the number 0. The bit layout of the return value differs between the various target systems and should therefore be evaluated using the following constants:

ConstantMeaning
JOYST_LEFT joystick pushed left
JOYST_RIGHT joystick pushed right
JOYST_UP joystick pushed up
JOYST_DOWN joystick pushed down
JOYST_BUTTON1 action button 1 pressed
JOYST_BUTTON2 action button 2 pressed
JOYST_BUTTONS action button 1 or 2 pressed

The JOYST function returns an Integer value in which each set bit stands for a particular action. Several bits can be set at the same time, e.g. the bits for left and up, when the joystick is pushed to the upper left. The joystick constants are defined such that the respective bit for the relevant action is set. With the help of the AND operator, the individual actions can be tested:

A=JOYST(0)
IF A AND JOYST_LEFT THEN PRINT "links"
IF A AND JOYST_RIGHT THEN PRINT "rechts"
IF A AND JOYST_DOWN THEN PRINT "runter"
IF A AND JOYST_UP THEN PRINT "hoch"
IF A AND JOYST_BUTTON1 THEN PRINT "Feuer 1"
IF A AND JOYST_BUTTON2 THEN PRINT "Feuer 2"
IF A AND JOYST_BUTTONS THEN PRINT "Feuer 1 oder 2"

On a target system that only supports one fire button per joystick, the constant JOYST_BUTTONS has the same value as JOYST_BUTTON1, and JOYST_BUTTON2 is 0. On systems that offer no joystick support at all, the JOYST function always returns 0, and the joystick constants also all have the value 0.

MUL10

Syntax: MUL10 ( <value> )
Value:numeric expression
Return: same data type that was passed in

Decimal numbers can be multiplied by 10 very quickly by shifting the decimal point one place to the right. That is exactly what the function MUL10 does in combination with the Decimal data type. This makes it considerably faster than multiplying by 10 with the multiplication operator.

However, the function can also be used with the data types Integer, Long and Single, which are not based on the decimal system. In that case, the multiplication by 10 is achieved through four additions. This does not have the same speedup effect as with the Decimal data type, but it is still faster than using the multiplication operator.

Specifically, for the operation B = A * 10, the following steps are carried out:

B = A + A
B = B + B
B = B + A
B = B + B


MUL2

Syntax: MUL2 ( <value> )
Value:Integer, Long or Single expression
Return: same data type that was passed in

Just as decimal numbers can be multiplied by 10 very quickly by shifting the decimal point, binary numbers can be multiplied by 2 very quickly. That is what the function MUL2 is for. It can only be used with the data types Integer, Long and Single, but not with Decimal.

OCT$

Syntax: OCT$ ( <value> )
OCT$ ( <value> , <number of digits> )
Value:Integer or Long expression
Number of digits:Integer
Return:String

The function OCT$ creates a string that represents the value passed in as an octal number. Negative values are represented as two's complement. If the second argument is omitted, the string created is six characters long for an Integer value and eleven characters long for a Long value.

With the optional second argument, the length of the octal number to be created can be specified. Possible values are 0 to 6 for an Integer expression and 0 to 11 for a Long expression. With a value of 0, the octal number is created without leading zeros, using as many digits as are necessary to represent the value in full. With a digit count greater than 0, the octal number has as many digits as specified, counted from the right, i.e. starting with the least significant digits.

There are two variants of the function. The first variant, without an argument, i.e. without parentheses, returns a random Single value greater than 0 and less than 1.0. ROUND

Syntax: ROUND ( <value> )
ROUND ( <value> , <mode> )
ROUND ( <value> , <mode> , <decimal places> )
Value: Decimal value to be rounded,
In the syntax variant with only one argument, a Single value can also be given.
Mode: One of the constants:
  • ROUND_HALF_UP (round the magnitude up, i.e. away from zero)
  • ROUND_HALF_EVEN (round to the even number)
  • ROUND_HALF_DOWN (round the magnitude down, i.e. toward zero)
The mode can also be given as a variable expression (e.g. a variable or function call). However, the value must correspond to one of the three constants.
Decimal places: number of decimal places to keep (Integer)
Return: same data type that was passed in for value

The function rounds a Single or Decimal value. The data type is not changed by this. Single values can only be rounded to whole numbers, Decimal values can also be rounded to a specified number of decimal places. In addition, for Decimal, specifying a rounding mode is also possible.

If the number of desired decimal places is greater than or equal to the actual number, nothing happens. The number of desired decimal places can also be negative. In that case, rounding occurs to tens, hundreds, etc. If all digits are "rounded away," the function returns 0.

Examples:
BASIC codeOutput
PRINT ROUND( 1.234 ) 1
PRINT ROUND( 1.4 ) 1
PRINT ROUND( 2.6 ) 3
PRINT ROUND( 1.234D, ROUND_HALF_DOWN, 2 ) 1.23
PRINT ROUND( 1.234D, ROUND_HALF_UP, 2 ) 1.24
PRINT ROUND( 1.23400D, ROUND_HALF_UP, 3 ) 1.234
PRINT ROUND( 1.23401D, ROUND_HALF_UP, 3 ) 1.235
PRINT ROUND( -1.2345D, ROUND_HALF_EVEN, 3 ) -1.234
PRINT ROUND( 1.23451D, ROUND_HALF_EVEN, 3 ) 1.235
PRINT ROUND( 12345D, ROUND_HALF_EVEN, -1 ) 12340
PRINT ROUND( 123450D, ROUND_HALF_EVEN, -2 ) 123400
PRINT ROUND( 123451D, ROUND_HALF_EVEN, -2 ) 123500

USR

Syntax: USR <function number> ( <argument> )
Function number:0...9
Argument:Integer expression
Return:Integer value

USR calls one of 10 possible functions that you can freely implement in machine code. The address must have been set beforehand with the statement DEF USR. The argument is passed to the user function in the DE register. The user function itself must end with a return instruction. The value that is in the HL register when the function ends is returned to the BASIC program.

The keyword USR and the function number can be written either together or separately, e.g.:

PRINT USR 0 (123)
PRINT USR0 (123)
PRINT USR 0(123)
PRINT USR0(123)

Unlike the CALL statement, with USR you can pass a value to the machine code subroutine and have it return one.

VAL

Syntax: VAL ( <string> )
VAL ( <string> , <number base> )
String:simple string expression
Number base: Integer expression with the value 2, 10 or 16
Return: Integer

The function VAL tries to read the content of a string as a number and returns its numeric value as an Integer. If a number base is specified, the function expects a binary, decimal or hexadecimal number according to that base. Without the second argument, a decimal number is always expected. Numbers with any other base are not supported.

For hexadecimal numbers, the letters A to F can be written in either upper or lower case.

The VAL function sets the error variables ERR and ERR$. These, especially the ERR variable, can be used to check whether the function was successful:

ERR valueMeaning
E_OK the number could be read
E_INVALID invalid characters encountered, return value is 0
E_OVERFLOW numeric overflow, i.e. the number is too large or too small, return value is 0

The example shows the VAL function in combination with the error variable ERR:

DO
  INPUT "Input:";E$
  V=VAL(E$,2)
  IF ERR=E_OK THEN PRINT "Binaerzahl, Dezimalwert=";V
  V=VAL(E$,10)
  IF ERR=E_OK THEN PRINT "Dezimalzahl, Dezimalwert=";V
  V=VAL(E$,16)
  IF ERR=E_OK THEN PRINT "Hexadezimalzahl, Dezimalwert=";V
LOOP

Note: In classic BASIC dialects that are not strictly typed, the function VAL can return different data types depending on the string passed in. Since the JKCEMU BASIC compiler, however, is strictly typed, the data type to be returned must already be known at compile time. And that type is Integer. If you want to convert larger numbers that lie outside the range of the Integer data type, you can use DECVAL, LNGVAL and SNGVAL. DECVAL and SNGVAL are also suitable for floating-point numbers. By analogy with the names DECVAL, LNGVAL and SNGVAL, there is also the function INTVAL, which returns Integer and is identical to VAL.

VARPTR

Syntax: VARPTR ( <variable> )
Return: Integer

The function VARPTR returns the address of the variable or the variable array element passed in. This makes it possible, for example, to access BASIC variables from your own assembler routines.

If the variable passed in is an array variable, you must specify the specific element whose address is to be returned.

Attention! With the statements POKE and DOKE, you can assign a value to the variable. However, please never assign a value to a string variable in this way! This can throw the internal memory management into disarray. And if you assign a value to a Decimal variable with POKE or DOKE, the variable must absolutely have a valid BCD format afterward! Otherwise, it is possible for a division using this variable to hang in an infinite loop.

W_CHAR

The system variable contains the width of the screen in character positions, i.e. the number of visible text columns is returned. If this value is not clearly defined, or if the target system allows different values (e.g. with CP/M), the variable contains the value -1.

A 0 is returned if the SCREEN statement was used to set a graphics screen that does not allow text output.

W_PIXEL

The system variable contains the width of the fully graphics-capable screen in pixels. If no full graphics mode is available, the value 0 is returned. In that case, the graphics commands cannot be used.

XPOS

The system variable contains the current X coordinate of the graphics cursor. Please also read the notes on graphics support!

YPOS

The system variable contains the current Y coordinate of the graphics cursor. Please also read the notes on graphics support!
