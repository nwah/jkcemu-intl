BASIC Compiler

User-Defined Functions and Procedures

User-defined functions and procedures allow programs to be structured far better than with the classic BASIC statements GOSUB and RETURN. User-defined functions return a value and are called in the same way as the BASIC functions. Procedures, on the other hand, do not return a value and are therefore treated like BASIC statements.

Structure of the BASIC Program

User-defined functions and procedures are implemented after the main program, i.e., the first FUNCTION or SUB statement ends the main program. From that point on, only comments and implementations of user-defined functions and procedures may follow.

The term main program refers to the first part of the BASIC program, where program execution begins.

Calling

User-defined functions and procedures are called by their name. This name must not be a reserved keyword. So that the compiler does not interpret a function or procedure name as a variable when it is used, a user-defined function or procedure must already be known to the BASIC compiler at the point it is called. This is the case if it was implemented further up in the BASIC program. If that is not possible (e.g. when called from the main program or in the case of recursion), the function or procedure must first be made known to the compiler with the DECLARE statement.

Local Variables

A special feature of user-defined functions and procedures is that they can declare and use local variables (see the LOCAL statement). These variables are newly created on each call of the function or procedure and are visible only within that function or procedure. This also applies to recursion, i.e., when a function or procedure calls itself, it has separate local variables at each call level. In that case, however, the stack area must be chosen large enough, since the local variables are created on the stack.

Within a user-defined function or procedure, the local variables must be created first, i.e., all LOCAL statements must immediately follow the FUNCTION or SUB statement. Only comments are still allowed in between.

The JKCEMU BASIC compiler does not support local array variables, i.e., only simple variables may be specified with LOCAL.

Within a user-defined function or procedure, both the local and the global, i.e., those used in the main program, variables are visible. However, if a local variable has the same name as a global one, the global variable is hidden and thus no longer visible.

Arguments

User-defined functions and procedures can have arguments. These are specified during declaration and implementation after the function or procedure name, as a comma-separated list of argument names enclosed in parentheses. Each argument can be followed by a type declaration using the keyword AS. If the type declaration is omitted, the data type is also derived from the argument name (integer or string, depending on whether the argument name ends with a $ character).

Within a function or procedure, the arguments are implemented as local variables, i.e., they can also be assigned a value. The only difference between these "argument variables" and variables declared with LOCAL is that argument variables are initialized "from the outside" when the function or procedure is called.

Return Value

User-defined functions return a value. The type of the return value can be specified with the keyword AS. If the type specification is omitted, the data type is derived from the function name: if it ends with a $ character, a string is returned, otherwise an integer value. The desired return value is assigned, syntactically, to a variable that has the same name as the function. Multiple assignments are possible. In that case, the last assignment is the one that counts. However, reading back the assigned return value is not possible within the function.

Example Programs

The first example shows the programming of a user-defined function with local variables. As a further special feature, a label is used in the DATA and RESTORE statements.

'Eingabe einer Zahl und Ausgabe als roemische Zahl
'Hauptprogramm

DECLARE FUNCTION roemische_zahl$(z)

DO
  INPUT "Zahl: ";Z
  IF Z>0 THEN
    PRINT "Roemische Zahl: ";roemische_zahl$(Z)
  ELSEIF Z=0 THEN
    PRINT "Ende"
    EXIT
  ELSE
    PRINT "Keine negative Zahl!"
  ENDIF
LOOP
END

'Zuordnung Dezimalzahl zu roemischer Zahl
roem_map:
  DATA 1000,"M",900,"CM",500,"D",400,"CD"
  DATA 100,"C",90,"XC",50,"L",40,"XL"
  DATA 10,"X",9,"IX",5,"V",4,"IV",1,"I"

'Implementierung der benutzerdefinierten Funktion
FUNCTION roemische_zahl$(z)
  LOCAL n,t$,rv$
  rv$=""
  RESTORE roem_map
  WHILE z>0
    READ n,t$
    WHILE z>=n
      z=z-n
      rv$=rv$+t$
    WEND
  WEND
  roemische_zahl$=rv$:'Rueckgabewert zuweisen
END FUNCTION


The second example shows a user-defined function in which both the argument and the return value contain a type declaration.

DECLARE FUNCTION kreisflaeche( radius AS SINGLE ) AS SINGLE

DIM r AS SINGLE

INPUT "Radius: ";r
PRINT "Kreisflaeche: ";kreisflaeche(r)
END

FUNCTION kreisflaeche( radius AS SINGLE ) AS SINGLE
   kreisflaeche = PI * radius * radius
END FUNCTION
