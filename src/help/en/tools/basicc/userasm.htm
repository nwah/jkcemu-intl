Although the BASIC compiler offers a wide range of functionality, not every requirement or programming task can be solved using BASIC alone. In such cases, you must write the desired functions in assembler and call them from the BASIC program. One option is to store the machine code of your own assembler routine in DATA lines, read it with READ during program execution, write it into working memory (RAM) with POKE or DOKE (e.g. after TOP), and then call the routine with CALL or USR. The example reads the current value of the R register in the microprocessor and displays it as a decimal number:

DEFUSR0=TOP
DATA &HED,&H5F,&H6F,&H26,&H00,&HC9
A=TOP
FOR I=1 TO 6
  READ B
  POKE A,B
  A=A+1
NEXT I
PRINT "R-Register: ";USR0(0)

This is a classic approach that is fairly straightforward. However, it is inefficient in terms of the memory it requires, and is therefore only suitable for smaller machine code routines. It can also become difficult if your own machine code is not relocatable and is therefore bound to fixed addresses.

1. The ASM Statement and ASM Function

The JKCEMU BASIC compiler offers the option, using the ASM statement and the ASM function, of including your own assembler source code directly in the BASIC program. This allows many things to be solved much more elegantly. The example from above then looks like this:

PRINT "R-Register: ";ASM(" CALL lese_Reg_R")
END
ASM "lese_Reg_R:"
ASM " LD A,R"
ASM " LD L,A"
ASM " LD H,0"
ASM " RET"

You can also do without the separate routine and read the R register like this:

ASM " LD A,R"
ASM " LD L,A"
ASM " LD H,0"
ASM " PUSH HL"
PRINT "R-Register: ";ASM(" POP HL")

The last example in particular makes it clear that including your own assembler source code directly interferes with the code generation of the BASIC compiler. For this reason: the ASM statement and the ASM function are intended only for experts who know exactly what they are doing!

There are no dependencies between the individual BASIC statements and functions with respect to the registers, i.e., you do not need to save any registers for the BASIC compiler when using the ASM statement and the ASM function.

2. Accessing BASIC Variables

Your own assembler routines can also access BASIC variables. You can find the address of a variable with the BASIC function VARPTR. Integer and Long variables are 2 or 4 bytes in size and store the numeric value as two's complement with the least significant byte first (little endian).

Decimal variables are 6 bytes in size and store the value as a packed BCD number in big-endian format (most significant byte first). The upper nibble of the first byte contains, in bits 4 to 6, the number of decimal places and, in bit 7, the sign. The lower nibble of the first byte, together with the 10 nibbles of the following five bytes, contain the 11 decimal digits.

Single variables are 4 bytes in size and store, in the first three bytes, the mantissa with the least significant byte first (little endian). Bit 7 of the most significant, and thus third, byte contains the sign. The exponent is stored in the fourth byte. In accordance with the IEEE 754 standard, it has an offset (bias) of 7Fh. If the exponent is zero, the entire Single value is zero, regardless of the mantissa. The value 0FFh is not allowed for the exponent. The special values defined in the IEEE 754 standard, +Infinity (positive infinity), -Infinity (negative infinity) and NaN (not a number), are not supported.

String variables are 2 bytes in size and contain a pointer to the actual string, which is terminated with a null byte.

Caution! Strings are stored in a dynamic memory area that is managed by the compiled program. So that this memory management does not get confused, you must never assign a value to a BASIC string variable in your own assembler routines!

If you want to generate strings in your own assembler routines and use them in BASIC, please return the start address of the string in the HL register to the calling BASIC program and convert the type there to String using the function MEMSTR$. You can now, for example, assign this string to a string variable in BASIC.

Caution! If, in your own assembler routines, you assign a value to a Decimal variable, that value must absolutely be in a valid BCD format! Otherwise, a division by such an invalid number can end up stuck in an infinite loop.

3. Optimizer

The BASIC compiler contains a global optimizer that goes through the generated assembler code and removes unnecessary instructions. In doing so, it can also modify assembler code generated using ASM statements and ASM functions. However, the optimizer only touches those assembler lines in which the instruction mnemonic is separated from the start of the line or the label by a tab character. So if you want to make sure the optimizer does not modify your assembler code, do not use tab characters in the ASM statements!
