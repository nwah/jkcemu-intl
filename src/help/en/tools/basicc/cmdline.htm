BASIC Compiler

Calling the BASIC Compiler from the Command Line

The JKCEMU BASIC compiler can also be called from the command line as a standalone program, without the actual emulator. Under Windows, you need to start the command prompt for this (search for cmd.exe if necessary). The command line for calling the BASIC compiler looks as follows (adjust the name and path of the JKCEMU JAR file accordingly):

java -jar jkcemu.jar --bc [options] <source file>

or

java -jar jkcemu.jar --basiccompiler [options] <source file>

The following options can be specified (case-sensitive!):
OptionMeaning
-h show help on the BASIC compiler options
-f <file> read further command line from a file

The command line can be quite long, possibly longer than supported by the command prompt or the operating system. For this reason, the command line can be read from a file.

When it reaches the -f option, the compiler opens the specified file and reads the further command line from it. Once the end of the file has been reached, the rest of the original command line is processed. The compiler thus behaves as if the contents of the file stood in the command line in place of the -f option.

Within the file, the individual command line arguments do not have to be on a single line, but can be split across multiple lines. If a command line argument contains spaces, it must be enclosed in double quotes so that the compiler processes it as a single argument.
-g output the line number if aborted due to an error (generates additional program code)
-o <output file> The generated program code is written to the specified file. The format of the output file depends on the extension (*.com; *.bin; *.hex; *.kcc; *.tap; *.z80).
If the option is omitted, the output file has the same name as the source file, except for the extension. The extension is then either *.s (if the option -S was specified) or *.com (if the target system is CPM with start address 0100h) or *.bin (in all other cases).
-t <system> specify the target system,
This option must be specified. Possible keywords are:
  • AC1
  • CPM
  • HUEBLER
  • KC85
  • KC85_4
  • KRAMER
  • LLC2_HIRES
  • SCCH
  • Z1013
  • Z1013_64X16
  • Z1013_KRT
  • Z1013_ZX
  • Z9001
  • Z9001_KRT
The keywords can be written in upper or lower case.
-A <start address>
-A <start address>:<BSS address> 		specify the start address for the program code and, if applicable, also for the BSS area (Block Storage Segment: variables, memory cells, stack) (hexadecimal),
If the option is omitted, the following start address applies depending on the target system:
  • 0100h for CPM, HUEBLER and all Z1013 target systems
  • 0300h for KC85, KC85_4, Z9001 and Z9001_KRT
  • 1000h for KRAMER
  • 2000h for AC1, LLC2_HIRES and SCCH
If the BSS address is not specified, the variables, the memory cells and, if a dedicated stack is used, that as well, are located directly behind the program code.
-D <driver list> This option specifies which drivers are to be included in the compiled program. For this, the drivers are given after the option, separated by commas. The driver list can also be enclosed in double quotes.

Examples:
 -D vdip
 -D crt,lpt
 -D "CRT,LPT"

The following drivers are available: CRT, FILE, LPT, VDIP
The case of the driver names does not matter.

If a driver is specified even though the BASIC program does not contain any statement or function that could use the driver (CRT, FILE, LPT and VDIP, for example, are only used by OPEN), the driver is not included.

If the -D option is not specified, all drivers that make sense are included.
-L <language> specify the language of the run-time messages (e.g. error messages),
The language is specified as a two-letter ISO code, where case does not matter. Possible languages are de (German) and en (English). If the option is omitted, run-time messages appear in German.
-M <number> specify the stack size,
With a stack size of 0, the system stack is used and thus no dedicated stack area is created.
-N <name> specify the program name,
This name is used to start the program on the target system (only relevant for KC85, HUEBLER, Z9001 and Z9001_KRT).
-B... specify the abort option:
OptionMeaning
-B0 CTRL-C does not abort the program
-B1 CTRL-C aborts the program only during input
-B2 CTRL-C aborts the program

If the option is omitted, -B2 is assumed automatically,

Caution! With the option -B2, the program will run correspondingly slower due to the constant keyboard polling!
-O... specify program code optimization:
OptionMeaning
-O1 disable stack checks
-O2 additionally disable array bounds checks
-O3 additionally prefer relative jumps

The option -O has the same effect as -O2.
If no program code optimization option was specified, all run-time checks are active (identical to -O0).
-S output assembler source code only,
In this case, the output file always has the format of a plain text file, regardless of its extension.
-W <keyword> specify the warnings that the compiler should output,
The following keywords are possible:
KeywordMeaning
ALL enable all warnings
NONASCII warn about non-ASCII characters
UNUSED warn about unused functions, procedures and variables
NONE do not output any warnings
