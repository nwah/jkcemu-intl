BASIC Compiler

Graphics

The language scope of the BASIC compiler also includes statements and functions for full graphics. All statements that draw on the screen and thus set or clear pixels are simply called graphics commands from here on. These graphics commands can only be used within a graphics environment. For this, the specific target system must support full graphics, and a graphics mode must be set.

If the target system does not support full graphics, the graphics commands cannot be compiled.

If full graphics is supported, it in turn depends on the target system whether graphics is available in the standard mode (SCREEN 0) or whether a graphics mode must first be set with the SCREEN statement. Please read the notes on the target systems.

The functions H_PIXEL and W_PIXEL return the height and width of the currently set screen mode. If these functions return the value 0, no graphics is available in the current screen mode.

With these two functions, as well as with the constants GRAPHICSCREEN and LASTSCREEN, the source code can be made portable to a certain extent. This refers to the ability to write the BASIC program so that it can be compiled without changes for different target systems while still having at least a similar appearance on every target system. To do this, you must not set the pixel coordinates as fixed values, but relative to the values returned by H_PIXEL and W_PIXEL. A graphics mode can be set in a portable way like this:

 SCREEN GRAPHICSCREEN

The prerequisite, of course, is that the target system supports graphics at all.

Graphics commands

The following statements perform graphical operations or play a role with respect to graphics:
  • CIRCLE
  • DRAW
  • DRAWR
  • LABEL
  • LINE
  • MOVE
  • MOVER
  • PAINT
  • PEN
  • PLOT
  • PLOTR
  • PRESET
  • PSET
  • SCREEN

Colors

The BASIC compiler has statements for setting the color (BORDER, COLOR, INK , PAPER). However, not every target system supports colors. On target systems that do not offer color graphics, the statements for setting a color have no effect and also generate no program code, i.e. you can safely write portable BASIC programs with color support and compile them for a black-and-white target system without unnecessary program code being generated as a result.

The color numbers differ between the individual target systems. In order to still be able to write portable program code, there are constants for some commonly used colors, which you should also use.

Example program

The example outputs a framed text in graphics mode, draws a circle around it, fills it in, and uses XOR mode to invert an area of the screen. The program is written to be portable, i.e. it will run without changes on every target system that supports graphics.

DECLARE SUB boxed_text(x,y,t$)

CURSOR 0
SCREEN GRAPHICSCREEN
CLS

tx=W_PIXEL/5
ty=H_PIXEL/3
boxed_text(tx,ty,"Hallo")

cx=tx+((XPOS-tx)/2)
cy=ty+6
cr=((XPOS-tx)/2)+3
CIRCLE cx,cy,cr

PAINT cx,cy-cr+2

PEN PEN_XOR
LINE (cx-cr-2,cy-cr-2)-(cx+cr+2,cy+cr+2),BF

IF GRAPHICSCREEN<>0 THEN PAUSE 50
SCREEN 0
END

SUB boxed_text(x,y,t$)
  MOVE x+3,y+2
  LABEL t$
  LINE (x,y)-(XPOS,y+12),B
END SUB
