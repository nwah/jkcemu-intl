2. Description of the Statements

Elements enclosed in angle brackets serve as placeholders and must be replaced accordingly. Elements enclosed in square brackets are optional and can be omitted.

ASM

Syntax: ASM [ CODE ] <string> [, <string> [, ...]]
ASM DATA <string> [, <string> [, ...]]
ASM BSS <string> [, <string> [, ...]]
string:string literal

With the ASM statement, you can write your own assembler routines within the BASIC program. The specified strings are inserted unchanged into the assembler source code generated by the compiler.

The first form, with the keyword CODE, inserts the assembler text at the current position in the code segment. The keyword CODE can also be omitted. With the keyword DATA, the assembler code is appended to the data segment. The strings should therefore contain only the mnemonics DB and DW, or their equivalent pseudo-instructions. With BSS, the assembler code is written into the segment for the memory cells and should therefore contain only DS mnemonics.

In addition to the ASM statement, there is also the ASM function.

Attention! Please read the notes on including your own assembler source code!

BORDER

Syntax: BORDER <integer expression>

This statement sets the color of the screen border. The color number depends on the target system. To write portable source code, you can also specify the color with a constant, e.g.:

 BORDER GREEN

On a target system on which the border color cannot be set, the statement has no effect.

CALL

Syntax: CALL <address>
CALL * <hex address>
address:integer expression
hex address:address as a hexadecimal number

The CALL statement calls a machine code subroutine that begins at the specified address and must be terminated with a return instruction. Unlike the USR function, no values can be passed.

CIRCLE

Syntax: CIRCLE <X> , <Y> , <radius>
CIRCLE ( <X> , <Y> ) , <radius>
X: integer expression
Y: integer expression
radius: integer expression

The CIRCLE statement draws a circle with the center (X,Y) and the specified radius. The graphics cursor is not affected.

CLOSE

Syntax: CLOSE # <channel>
channel: integer expression with the value 1 or 2

The statement closes the specified I/O channel and sets the error variables ERR and ERR$. In the case of an output channel, any buffered data is still written before the channel is closed.

CLS

The CLS statement clears the screen and moves the cursor to the top left corner. If a window has been set up in the monitor program or via the corresponding system function, the CLS statement applies only to the window area.

COLOR

Syntax: COLOR <foreground color>
COLOR <foreground color> , <background color>
COLOR <foreground color> , <background color> , <border color>
foreground color: integer expression
background color: integer expression
border color: integer expression

The COLOR statement is used to set the foreground color and, optionally, also the background or border color. The colors can also be set individually with the statements INK, PAPER and BORDER.

CURSOR

Syntax: CURSOR <integer expression>

The CURSOR statement is used to turn the text cursor on and off. If the value 0 is passed, the statement turns the cursor off; any other value turns it on.

Attention! The CURSOR statement is not supported for all target systems (see the notes on target systems). If it is not supported for a particular system, it can nevertheless still be used when writing portable BASIC programs. In that case it simply has no effect.

DATA

Syntax: DATA <constant expression> [ , ... ]
constant expression: numeric or string literal

DATA is used to add data (numeric values or strings) to an application-wide data area. The values must be separated by commas and must be literals, i.e. numbers or strings enclosed in double quotes.

Reading, and thereby making use of, this data is done with the READ statement, e.g.:

FOR I=1 TO 12
  READ M$,N
  PRINT M$;":";N;"days"
NEXT I
END

DATA "Jan",31,"Feb",28,"Mar",31,"Apr",30,"May",31,"Jun",30
DATA "Jul",31,"Aug",31,"Sep",30,"Oct",31,"Nov",31,"Dec",30

Attention! Floating-point literals are by default stored with the data type Single. However, this cannot be read with a Decimal variable. If you want to specify values of the data type Decimal in a DATA statement, you must append a D to the number. This forces the data type Decimal.

DECLARE

Syntax: DECLARE FUNCTION <function name>
DECLARE FUNCTION <function name> ( <argument> [ , ... ] )
DECLARE FUNCTION <function name> AS <type>
DECLARE FUNCTION <function name> ( <argument> [ , ... ] ) AS <type>
DECLARE SUB <procedure name>
DECLARE SUB <procedure name> ( <argument name> [ , ... ] )
type: DECIMAL, FLOAT, INTEGER, LONG, SINGLE or STRING

This statement declares a user-defined function or procedure so that it can be called before its actual implementation (statements FUNCTION and SUB). Please also read the notes on user-defined functions and procedures!

DEF USR
DEFUSR

Syntax: DEF USR <function number> = <address>
DEFUSR <function number> = <address>
function number:0...9
address:integer expression

This statement sets the address for one of the ten possible USR functions. The address can be reassigned as often as desired during program execution.

DEF USR 0 = &H4000
PRINT USR 0 (123)

The individual parts can also be written partially or completely together, e.g.:

DEF USR0 = &H4000
DEFUSR 0 = &H4000
DEFUSR0 = &H4000

DIM

Syntax: DIM <Name> [, ... ]
DIM <Name> AS <type> [, ... ]
DIM <Name> ( <dimension> ) [, ... ]
DIM <Name> ( <dimension> ) AS <type> [, ... ]
DIM <Name> ( <dimension> , <dimension> ) [, ... ]
DIM <Name> ( <dimension> , <dimension> ) AS <type> [, ... ]
Name: name of the variable to be declared
type: DECIMAL, FLOAT, INTEGER, LONG, SINGLE or STRING
dimension:integer literal

This statement declares variables that can be used throughout the entire BASIC program (main program and user-defined procedures/functions) and therefore have global visibility. The variables can be either simple variables or one- or two-dimensional arrays. Array variables with more than two dimensions are not supported. For arrays, the individual dimensions are given in parentheses after the variable name. Each dimension value must be a concrete value. Variable dimension specifications are not possible. The number of elements in a dimension is one greater than the dimension value itself, since the first element has index 0.

After the name, or after the dimensions, a type can be specified with AS. If this is omitted, the type is derived from the name: if the name ends with a $ character, it is the type String, otherwise the type Integer.

Examples with a type specification:

DIM A AS INTEGER, grosse_zahl AS LONG, C(3) AS INTEGER, ein_text$(4,5) AS STRING

Examples without a type specification (only Integer and String possible):

DIM D, ein_feld(8), T$(4,5)

Attention! If a DIM statement declares several variables with and without a type specification, errors can easily result. In the following example, the variable A is created as an Integer array, the variable B as a Single array, and the variable C as a String array:

DIM A(10), B(20) AS SINGLE, C$(10)

To avoid errors, it is therefore advisable to explicitly specify the type for Integer and String as well:

DIM A(10) AS INTEGER, B(20) AS SINGLE, C$(10) AS STRING

Note: FLOAT is a synonym for SINGLE and thus declares a SINGLE variable.

The DIM statement must appear in the BASIC source code before the first use of the variable. This is independent of the actual program flow. The following example would work in a BASIC interpreter, but produces a syntax error on line 110 in the JKCEMU BASIC compiler, since at that point the DIM statement on line 200 has not yet been compiled, and the variable A on line 110 is therefore treated as a simple variable:

100 GOSUB 200
110 A(1,0)=12
120 ...
200 DIM A(10,20)
210 RETURN

The correct way is:

100 DIM A(10,20)
110 A(1,0)=12
120 ...

DO

The DO statement marks the beginning of a loop whose body is always executed at least once, i.e. the loop runs through at least one iteration in every case (unless the very first pass is already terminated with EXIT). The end of the loop is defined by the LOOP statement. There, a condition can be specified that controls how many times the loop repeats. Without a condition, the DO loop is an infinite loop.

DOKE

Syntax: DOKE <address> , <value>
address:integer expression
value:integer expression

The value of the second integer expression is written to memory, as two bytes, starting at the specified address.

DRAW

Syntax: DRAW <X> , <Y>
DRAW TO <X> , <Y>
DRAW ( <X> , <Y> )
DRAW TO ( <X> , <Y> )
DRAW STEP ( <X> , <Y> )
DRAW <macro>
X: integer expression
Y: integer expression
macro: simple string expression

There are three variants of the DRAW statement. The first variant, with a position specification, draws a line from the current position of the graphics cursor to the specified absolute position (the end point of the line). The graphics cursor moves along with it, i.e. after drawing it is positioned at the line's end point.

The second variant, with the keyword STEP, differs from the first only in that the line's end point is given not absolutely but relatively, i.e. this variant is identical to the DRAWR statement.

The third variant, with a string expression as the argument, is the so-called macro mode. It is used to draw complex figures. The string passed contains a macro, i.e. a sequence of commands that are processed one after another. Each individual command begins with a letter (case does not matter), which may be followed by an argument. There are eight commands for drawing a line in a particular direction:

H U E
\ | /
L - graphics cursor - R
/ | \
G D F


Directly after the letter, a number can be given to specify the length of the line to be drawn. If the number is omitted, only a single pixel is drawn.

Further commands are M and B. With M, a position is specified to which the line is drawn. The position specification follows directly after the letter and consists of the X coordinate, a comma, and the Y coordinate. If the X coordinate begins with a sign (+ or -), the position is treated as a relative position, otherwise as an absolute one.

The last available command, B, specifies that with the next command nothing is drawn; instead only the graphics cursor is moved accordingly.

The following table summarizes the macro commands of the DRAW statement:
Macro CommandMeaning
U Draw a line one pixel upward
U<count> Draw a line count pixels upward
D Draw a line one pixel downward
D<count> Draw a line count pixels downward
L Draw a line one pixel to the left
L<count> Draw a line count pixels to the left
R Draw a line one pixel to the right
R<count> Draw a line count pixels to the right
E Draw a line one pixel up and to the right
E<count> Draw a line count pixels up and to the right
F Draw a line one pixel down and to the right
F<count> Draw a line count pixels down and to the right
G Draw a line one pixel down and to the left
G<count> Draw a line count pixels down and to the left
H Draw a line one pixel up and to the left
H<count> Draw a line count pixels up and to the left
M<X>,<Y> Draw a line to the specified absolute position
M<sign><X>,[<sign>]<Y> Draw a line to the specified relative position
B do not draw with the next macro command; only move the graphics cursor

Example: drawing a row of adjacent houses:

H$="U25E15F15D25L30BR4U18R8D17BM+6,7U10R8D10L8"
FOR X=0 TO W_PIXEL STEP 40
  MOVE X,0
  DRAW H$
NEXT X

Attention! For all variants of the DRAW statement, the pixel at the starting point is not set. Drawing begins only with the first pixel after the starting point. This ensures that, when drawing polygons using DRAW macros or several consecutive DRAW statements, no pixel is ever set twice. This is especially important when using the XOR pen (see the PEN statement). Because of this behavior, there are also the separate statements MOVE and PLOT, and their variants MOVER and PLOTR. If you want to draw a closed polygon, you must set the graphics cursor with MOVE so that no pixel is drawn twice. For an open polygon, PLOT is recommended, so that no pixel is missing.

Please also read the notes on graphics support!

DRAWR

Syntax: DRAWR <X> , <Y>
DRAWR ( <X> , <Y> )
X: integer expression
Y: integer expression

The DRAWR statement draws a line from the current position of the graphics cursor to the position given by relative coordinates (the end point of the line). Otherwise, the same rules apply as for the DRAW statement.

END

Syntax: END
END FUNCTION
END SUB

If the END statement appears within a user-defined function or procedure, it terminates that function or procedure. In that case, the keyword FUNCTION or SUB can additionally be specified after END, depending on whether it is a function or a procedure. Outside of a function or procedure, the END statement terminates the BASIC program.

EXIT

Syntax: EXIT
EXIT DO
EXIT FOR
EXIT WHILE

An EXIT statement can be used to leave a loop early, i.e. the loop is aborted and program execution continues after the loop. Optionally, the keyword EXIT can also be followed by the type of the loop in question (either the keyword DO, FOR or WHILE).

I=0
DO
  I=I+1
  PRINT I
  IF I=5 THEN EXIT DO
LOOP
PRINT "End of loop"

FOR

Syntax: FOR <variable>=<start value> TO <end value> [ STEP <step size> ]
start value:integer expression
end value:integer expression
step size:integer expression

First, the start value is assigned to the variable, also called the loop variable. Program execution then continues with the first statement after the FOR statement. When the NEXT statement is reached, the step size is added to the variable. If the end value has not yet been reached, execution jumps back to the first statement after the FOR statement. Otherwise the FOR loop is exited, i.e. program execution continues after the NEXT statement.

If the step size is greater than 0, the end value is considered reached when the value of the variable is equal to or greater than the end value. If, on the other hand, the step size is less than 0, the end value is considered reached when the value of the variable is equal to or less than the end value.

The keyword STEP and the following step size can be omitted. In that case the step size is one.

Attention! The concrete memory location of the loop variable must already be determinable at compile time. This is the case for all simple variables. If, on the other hand, the loop variable is an element of an array variable, this condition is only met if the indexes are given as constant values, e.g.:

DIM A(5)
FOR A(2)=1 TO 10
...
NEXT A(2)

A variable index, on the other hand, is answered by the compiler with an error:

DIM A(5)
I=2
FOR A(I)=1 TO 10     Error!
...
NEXT A(I)

FUNCTION

Syntax: FUNCTION <function name>
FUNCTION <function name> ( <argument> [ , ... ] )
FUNCTION <function name> AS <type>
FUNCTION <function name> ( <argument> [ , ... ] ) AS <type>
type: DECIMAL, FLOAT, INTEGER, LONG, SINGLE or STRING

This statement begins the implementation of a user-defined function. This implicitly also ends the main program. The function ends with the END FUNCTION statement.

Please also read the notes on user-defined functions and procedures!

GOSUB

Syntax: GOSUB <line number>
GOSUB <label>

This statement calls a subroutine that begins at the specified location. The subroutine must be terminated with RETURN.

GOTO

Syntax: GOTO <line number>
GOTO <label>

This statement causes a jump to the specified location, i.e. program execution continues from there.

Attention! The GOTO statement dates from a time when BASIC did not yet support structured programming. However, the JKCEMU BASIC compiler offers, with alternative loop types (DO...LOOP..., WHILE...WEND) including the corresponding control statement EXIT, as well as multi-line IF constructs, various options for structured programming that make the use of GOTO largely, if not entirely, unnecessary. It is therefore advisable, when developing new software, to avoid using GOTO and instead make use of the possibilities of structured programming.

IF

Syntax: IF <condition> [ THEN ] <statements> [ : ELSE : <statements> ]
IF <condition> [ THEN ] <line number> [ : ELSE : <statements> ]

IF <condition> [ THEN ]
  <statements>
  <statements>
[ ELSEIF <condition> THEN
  <statements>
  <statements> ]
[ ELSEIF <condition> THEN
  <statements>
  <statements> ]
[ ELSE
  <statements>
  <statements> ]
ENDIF
condition:integer expression

The IF statement represents a conditional program branch. If the condition is satisfied, the statements after THEN are executed. If not, the condition after the first ELSEIF is checked and, if satisfied, the statements following it are executed. If that condition is also not satisfied, the next ELSEIF is checked, and so on. If none of the conditions were satisfied, the statements after ELSE are executed.

Any number of ELSEIF branches is allowed. ELSEIF can also be omitted entirely. The ELSE branch is likewise optional and can be omitted. The keyword THEN can also be omitted, but this is not recommended, for the sake of readability and in view of the syntax customary in other BASIC dialects.

A condition is satisfied when the integer expression yields a value not equal to 0. The condition does not necessarily have to contain a comparison operator. However, comparison operators are particularly well suited for conditions, since they return an integer value (see comparison operators).

The IF statement comes in a single-line and a multi-line variant. In the single-line variant, the IF statement ends at the end of the line, e.g.:

100 IF A=0 THEN PRINT "Zero" : ELSE : PRINT "not zero"
110 IF A<100 THEN GOTO 200

As already mentioned above, the keyword THEN can be omitted. However, if it is present and is directly followed by a number, that number is treated as the line number of a GOTO statement, e.g.:

100 IF A<100 THEN 200

If nothing more follows on the line after the condition, or after the keyword THEN, the IF statement is recognized as multi-line, i.e. in that case there must be an ENDIF.

IF A=1 THEN
  PRINT "one"
ELSEIF A=2 THEN
  PRINT "two"
ELSEIF A=3 THEN
  PRINT "three"
ELSE
  PRINT "none of these"
ENDIF

IF statements can be nested within each other:

IF A=0 THEN
  IF B=0 THEN
    PRINT "A and B are zero."
  ELSEIF B=1 THEN
    PRINT "A=0 and B=1"
  ENDIF
ELSE
  PRINT "A is not zero."
ENDIF

INCLUDE

Syntax: INCLUDE "file name"

This statement inserts the specified file into the source code at the current position, i.e. this file is compiled along with it and thus becomes part of the BASIC program. The file name can be given with or without a path. If the path is omitted, the included file is searched for in the same directory, or, if the source code was typed into the text editor and has not yet been saved, in the current directory. If a path is given, it can be either relative or absolute. The notation of the path (drive, separator) depends on the operating system on which JKCEMU is running. However, it is also possible to specify the path in an operating-system-independent way, although only as a relative path. In that case, the slash (/) must be used as the separator.

Examples:
Absolute path on Windows: INCLUDE "C:\basic\bibliothek.bas"
Absolute path on Linux/Unix: INCLUDE "/home/benutzer/basic/bibliothek.bas"
Relative path on Windows: INCLUDE "..\bibliothek.bas"
Relative, operating-system-independent path (Linux/Unix/Windows): INCLUDE "../bibliothek.bas"

Attention! No further BASIC statement may follow the INCLUDE statement on the same line. In addition, included files cannot themselves include any further files, i.e. nested INCLUDE statements are not allowed.

INK

Syntax: INK <integer expression>

This statement sets the foreground color. The color number depends on the target system. To write portable source code, you can also specify the color with a constant, e.g.:

 INK YELLOW

On a target system without color support, the statement has no effect.

INPUT

Syntax: INPUT [ <string literal> ; ] <variable> [ ; ... ]
INPUT # <channel> , <variable> [ , ... ]
channel: integer expression with the value 1 or 2

There are two variants of the INPUT statement, with and without a channel number. The variant without a channel number reads input from the keyboard and stores the values entered in variables. For this, the statement can contain several sections, separated by semicolons. Each section represents a separate input. Each section can consist of either just a variable, or a string literal followed by a semicolon and a variable. If a string literal is present, it is output first. Otherwise a question mark appears, prompting for input. Pressing the ENTER key assigns the entered number, or the entered text, to the variable. If the variable is a numeric variable, the input must correspond to a valid number. If it does not, an error message appears and the user is prompted to enter the value again. In the case of a string variable, leading spaces are stripped, and the text starting from the first non-space character is stored in the variable.

The INPUT variant with a channel number reads text sections from the specified input channel and stores them in the specified variables. Several variables can be specified. For each variable, one text section is read and stored in the variable. If the variable is a numeric variable, the text section is converted to a numeric value, which is then stored. Leading and trailing spaces are ignored during the conversion. If the text section cannot be converted to a number, the error variables are set accordingly and a 0 is assigned to the variable.

The text sections are separated by commas and end-of-line characters. Both the DOS/Windows line-ending format (end-of-line bytes 0Dh/0Ah) and the Unix/Linux format (end-of-line byte 0Ah) are recognized as line endings. When reading a text section, reading continues up to and including the separator character or end of line. If the input stream, or the file, already ends before the separator or end-of-line character, the error variables are set to "end of file reached".

LABEL

Syntax: LABEL <string expression>

This statement outputs text in graphics mode. Before doing so, the graphics cursor must have been moved to the desired position, e.g. with the MOVE statement. After the output, the graphics cursor is positioned after the text, i.e. several consecutive LABEL statements output the text seamlessly one after another.

MOVE 10,10
LABEL "ABC"
LABEL "DEF"
LINE 10,7,XPOS-3,7

Example: output of continuous, underlined text

On systems with a separate text and graphics SCREEN, the LABEL statement is the only way to output text in graphics mode. Please also read the notes on graphics support!

LET

Syntax: [ LET ] <variable> = <expression>

The keyword LET can be omitted.

LINE

Syntax: LINE <X1> , <Y1> , <X2> , <Y2>
LINE ( <X1> , <Y1> ) - ( <X2> , <Y2> )

LINE <X1> , <Y1> , <X2> , <Y2> , B
LINE ( <X1> , <Y1> ) - ( <X2> , <Y2> ) , B

LINE <X1> , <Y1> , <X2> , <Y2> , BF
LINE ( <X1> , <Y1> ) - ( <X2> , <Y2> ) , BF
X1: integer expression
Y1: integer expression
X1: integer expression
Y2: integer expression

In the variant without the argument B or BF, the statement draws a line from the point (X1,Y1) to the point (X2,Y2). If, on the other hand, the argument B is given, a rectangle appears with the four corner points (X1,Y1), (X1,Y2), (X2,Y1) and (X2,Y2). With the argument BF, a filled rectangle is drawn.

The LINE statement does not affect the graphics cursor. Please also read the notes on graphics support!

LINE INPUT

Syntax: LINE INPUT [ <string literal> ; ] <string variable>
LINE INPUT # <channel> , <string variable>
channel: integer expression with the value 1 or 2

The LINE INPUT statement is used to enter, or read, a line of text. In the variant without a channel number, the text is entered via the keyboard. Unlike the INPUT statement, leading spaces are not stripped, i.e. the entered line of text is stored unchanged in the specified string variable. Optionally, a string literal can be specified, which is output as a prompt. If this string literal is omitted, unlike the INPUT statement, no question mark appears.

In the variant with a channel number, a line of text is read from the specified input channel. Both the DOS/Windows line-ending format (end-of-line bytes 0Dh/0Ah) and the Unix/Linux format (end-of-line byte 0Ah) are recognized as line endings. The statement reads the line of text up to and including the end of line, but stores the text without the end-of-line bytes in the variable. Since the statement searches for the end of line, when reading the last line the error status is usually set to "end of file reached", i.e. the text stored in the variable is valid both with ERR=E_OK and with ERR=E_EOF. With any other error status, an empty string is written to the variable.

Example: reading a text file and printing it to the screen line by line:

INPUT "File:";F$
OPEN F$ AS #1
IF ERR THEN
  PRINT ERR$
ELSE
  DO
    LINE INPUT #1,S$
    PRINT S$
  LOOP UNTIL ERR OR EOF(#1)
  IF ERR THEN PRINT ERR$
  CLOSE #1
ENDIF

LOCAL

Syntax: LOCAL <Name> [, ... ]
LOCAL <Name> AS <type> [, ... ]
Name: name of the variable to be declared
type: DECIMAL, FLOAT, INTEGER, LONG, SINGLE or STRING

This statement declares one or more local variables within a function or procedure. If the data type is omitted, the type is derived from the name of the variable: if the variable name ends with a $ character, a local string variable is declared, otherwise a local Integer variable. Local array variables are not possible.

Note: FLOAT is a synonym for SINGLE and thus declares a SINGLE variable.

Local variables hide global variables of the same name, i.e. if a local variable has the same name as one in the main program, the variable in the main program cannot be accessed from within the function/procedure.

Local variables are created on the stack. The stack must therefore be dimensioned large enough. If a function/procedure calls itself (recursion), the local variables are created anew with each call, i.e. there are separate local variables for each call.

LOCATE

Syntax: LOCATE <row> , <column>
row: integer expression with a value >= 0
column: integer expression with a value >= 0

The LOCATE statement positions the cursor at the specified position. The top left corner has the position (0,0).

Attention! The LOCATE statement is not supported for all target systems (see the notes on target systems).

LOOP

Syntax: LOOP
LOOP UNTIL <condition>
LOOP WHILE <condition>
condition: integer expression

The LOOP statement marks the end of a loop that was previously opened with the DO statement.

The DO...LOOP loop comes in three different forms. If nothing further is specified after the keyword LOOP, it is an infinite loop:

DO
  PRINT "Infinite loop"
LOOP

With the keyword UNTIL, a condition can be specified. The loop terminates as soon as the condition is satisfied:

I=1
DO
  PRINT I
  I=I+1
LOOP UNTIL I=10

The opposite is achieved with the keyword WHILE. In that case the loop runs for as long as the specified condition is satisfied. The loop therefore terminates as soon as the condition is no longer satisfied:

I=1
DO
  PRINT I
  I=I+1
LOOP WHILE I<10

LPRINT

Syntax: LPRINT
LPRINT <section>
LPRINT <section> <separator>
LPRINT <section> <separator> <further sections>
LPRINT <section> <separator> <further sections> <separator>
section: string expression or integer expression
separator: comma or semicolon

The LPRINT statement performs output to the printer. Its arguments are identical to those of the PRINT statement in the version without a channel number.

Attention! The LPRINT statement is not supported for all target systems (see the notes on target systems).

MOVE

Syntax: MOVE <X> , <Y>
MOVE TO <X> , <Y>
MOVE ( <X> , <Y> )
MOVE TO ( <X> , <Y> )
MOVE STEP ( <X> , <Y> )
X: integer expression
Y: integer expression

The MOVE statement sets the graphics cursor to the specified position. In the variant with the keyword STEP, the graphics cursor is positioned not absolutely but relatively, i.e. this variant is identical to the MOVER statement.

Please also read the notes on graphics support!

MOVER

Syntax: MOVER <X> , <Y>
MOVER ( <X> , <Y> )
X: integer expression
Y: integer expression

The MOVER statement moves the graphics cursor by the specified X and Y value, i.e. the position given is relative. Please also read the notes on graphics support!

NEXT

Syntax: NEXT [ <variable> ]

The loop variable has the step size added to it (see the FOR statement). If the end value has not yet been reached, execution jumps back to the beginning of the FOR loop. Otherwise the FOR loop is exited.

The NEXT statement must not be called without a preceding FOR!

Specifying a variable is optional. However, if a variable is given, it must be the same one as in the corresponding FOR statement.

ON...GOSUB

Syntax: ON <selector> GOSUB <line number> , <line number> [ , <line number> [ , ... ] ]
ON <selector> GOSUB <label> , <label> [ , <label> [ , ... ] ]
selector:integer expression >= 0

This statement calls one subroutine from a list of subroutines, with the selection made based on the value of the expression after the keyword ON. If the value is 1, the subroutine at the first line number or label after the keyword GOSUB is called; for the value 2, the second, and so on. For the value 0, or a value greater than the number of line numbers given, no subroutine is called.

Example with BASIC line numbers:

100 ON A GOSUB 1000,2000,3000
...
1000 PRINT "SUB 1":RETURN
2000 PRINT "SUB 2":RETURN
3000 PRINT "SUB 3":RETURN

Example with labels:

ON A GOSUB up1,up2,up3
...
up1:
  PRINT "SUB 1":RETURN
up2:
  PRINT "SUB 2":RETURN
up3:
  PRINT "SUB 3":RETURN

ON...GOTO

Syntax: ON <selector> GOTO <line number> , <line number> [ , <line number> [ , ... ] ]
ON <selector> GOTO <label> , <label> [ , <label> [ , ... ] ]
selector:integer expression >= 0

This statement jumps to a line that is selected from a list of BASIC line numbers or labels according to the value of the expression after the keyword ON. If the value is 1, execution jumps to the first line after the keyword GOTO; for the value 2, to the second, and so on. For the value 0, or a value greater than the number of line numbers given, no jump occurs, i.e. in that case program execution continues with the next line.

Example with BASIC line numbers:

100 ON A GOTO 1000,2000,3000
...
1000 PRINT "A was 1":END
2000 PRINT "A was 2":END
3000 PRINT "A was 3":END

Example with labels:

ON A GOTO up1,up2,up3
...
up1:
  PRINT "A was 1":END
up2:
  PRINT "A was 2":END
up3:
  PRINT "A was 3":END

OPEN

Syntax: OPEN <device/file name> AS # channel
OPEN <device/file name> FOR <mode> AS # channel number
OPEN <device/file name> FOR BINARY <mode> AS # channel number
device/file name: simple string expression
mode: INPUT, OUTPUT or APPEND
channel: integer expression with the value 1 or 2

This statement opens an input or output channel to the specified device or file. The modes have the following meaning:

Mode Meaning
INPUT input channel
OUTPUT output channel,
If a file was specified, it is newly created. Any existing file is deleted in the process.
APPEND output channel,
If a file was specified, the data is appended to the file. The contents of any existing file are not deleted.

If no mode is specified, the default mode applies, which you can find in the following table:

Device Meaning Supported modes Default mode
CRT: screen OUTPUT OUTPUT
LPT: printer OUTPUT OUTPUT
A: to P: drives in the file system INPUT, OUTPUT, APPEND INPUT
V: USB storage on the VDIP module INPUT, OUTPUT, APPEND INPUT

If the keyword BINARY is specified before the mode, the I/O channel is opened in binary mode, otherwise in text mode. There is only a difference between these two modes when accessing a file system that does not offer byte-exact file lengths (see file system). For reasons of portability, however, you should always specify the keyword BINARY when dealing with binary files.

When opening a file for writing (modes OUTPUT and APPEND) on the device V: (USB storage), the current system time is included as the timestamp for the last modification, but only if the system time can be read. This is only the case if the function DATETIME$ returns a non-empty string. Otherwise, no timestamp is included when the file is opened or created.

For an input channel, the statements INPUT and LINE INPUT as well as the functions EOF and INPUT$ can be used. For an output channel, the PRINT statement is available. When you are finished working with the channel, it must be closed again with CLOSE. After that, the channel can be opened again with a different device or a different file. A total of two channels are available (1 and 2).

The OPEN statement sets the error variables ERR and ERR$.

Example: saving numbers to the file ZAHLEN.TXT in the top-level directory on the USB storage:

OPEN "V:\ZAHLEN.TXT" FOR OUTPUT AS #1
IF ERR THEN
  PRINT ERR$
ELSE
  FOR I=1 TO 10
    PRINT #1,I
    IF ERR THEN PRINT ERR$:EXIT
  NEXT I
  CLOSE #1
  IF ERR THEN PRINT ERR$
ENDIF

Attention! The file was only reliably saved if no error occurred either while writing to the file (statement PRINT #) or while closing the file (statement CLOSE).

Examples of reading a file can be found with the LINE INPUT statement and the INPUT$ function.

OUT

Syntax: OUT ( <port> ) = <value>
OUT <port> , <value>
port:integer expression
value:integer expression

The OUT statement outputs a value to an output port. The first expression specifies the output address, the second expression determines the value to be output, whereby only the lower 8 bits are relevant.

Attention! Although the microprocessor officially supports only 8-bit I/O addresses, the use of 16-bit addresses is possible. The compiler translates the statement into program code that, due to the undocumented behavior of the microprocessor, also makes a 16-bit I/O address effective.

PAINT

Syntax: PAINT <X> , <Y>
PAINT ( <X> , <Y> )
X: integer expression
Y: integer expression

The PAINT statement fills the area in which the specified point lies. The area consists of all connected pixels that are set to the background color. This statement sets these pixels to the currently configured foreground color. If the pixel at the starting position already has the foreground color, or if the starting position lies outside the screen area, nothing happens. The graphics cursor is not affected by this statement.

Example: drawing two circles of different sizes, with the gap between them filled in, producing a circle with a thick outline:

CLS
X=W_PIXEL/2
Y=H_PIXEL/2
R1=H_PIXEL/4
R2=H_PIXEL/3
CIRCLE (X,Y),R1
CIRCLE (X,Y),R2
PAINT X-R2+(R2-R1)/2,Y

To execute, the PAINT statement requires temporary storage. For this, a free area of the string memory is used. The more often the area to be filled must be broken down into sub-areas, e.g. when filling around corners, the more memory is required. If the memory area used from the string memory is not sufficient, the program aborts with a corresponding error message.

PAPER

Syntax: PAPER <integer expression>

This statement sets the background color. The color number depends on the target system. To write portable source code, you can also specify the color with a constant, e.g.:

 PAPER BLUE

On a target system without color support, the statement has no effect.

PASSWORD INPUT

Syntax: PASSWORD INPUT [ <string literal> ; ] <string variable>

The PASSWORD INPUT statement is used to enter a password. The characters entered are not shown in plain text on the screen, but are echoed as asterisks instead. Optionally, a string literal can be specified, which is output as a prompt.

PAUSE

Syntax: PAUSE
PAUSE <integer expression>

This statement pauses the program. Pressing the space bar resumes the program. Optionally, a wait time in tenths of a second can be specified. In that case, the program resumes automatically after this time, even if the space bar was not pressed.

Attention! The wait time only approximately matches the specified value and depends significantly on the clock frequency. The value 30 therefore corresponds to only roughly a wait time of 3 seconds.

PEN

Syntax: PEN <integer expression>

This statement sets the pen used for drawing. A pen represents a particular way in which pixels are set. There are four different pens. A constant is defined for each pen.

PenConstantMeaning
0 PEN_NONE Pen raised,
Nothing happens with this pen. Nothing is drawn and nothing is erased.
1 PEN_NORMAL Drawing,
The pixels to be drawn are set to the foreground color. Any text and graphics already on the screen are thus overwritten. This pen is the "normal" drawing pen and is set automatically when the program starts.
2 PEN_ERASER Erasing,
The pixels to be drawn are set to the background color.
3 PEN_XOR XOR mode,
For each pixel to be drawn, a check is made whether it is already set. If so, the pixel is erased (set to the background color). If not, it is drawn normally (set to the foreground color). As a result, text and graphics already on the screen remain visible, but inverted.

Please also read the notes on graphics support!

PLOT

Syntax: PLOT <X> , <Y>
PLOT TO <X> , <Y>
PLOT ( <X> , <Y> )
PLOT TO ( <X> , <Y> )
PLOT STEP ( <X> , <Y> )
X: integer expression
Y: integer expression

The PLOT statement positions the graphics cursor and sets the pixel there. This makes the PLOT statement well suited, e.g. in combination with the DRAW statement, for drawing open polygons.

In the variant with the keyword STEP, relative coordinates are given. This variant is identical to the PLOTR statement.

Please also read the notes on graphics support!

PLOTR

Syntax: PLOTR <X> , <Y>
PLOTR ( <X> , <Y> )
X: integer expression
Y: integer expression

The PLOTR statement moves the graphics cursor by the specified X and Y value and sets the pixel there. The position given is relative. Otherwise, what was written for the PLOT statement applies.

POKE

Syntax: POKE <address> , <value>
address:integer expression
value:integer expression

The memory cell specified by the address is written with the lower 8 bits of the value of the second integer expression.

PRESET

Syntax: PRESET <X> , <Y>
PRESET ( <X> , <Y> )
X: integer expression with a value >= 0
Y: integer expression with a value >= 0

The PRESET statement resets a pixel on the screen to the background color. The pen set with the PEN statement plays no role in this. The position of the graphics cursor is not changed. Please also read the notes on graphics support!

PRINT

Syntax: PRINT
PRINT <section>
PRINT <section> <separator>
PRINT <section> <separator> <further sections>
PRINT <section> <separator> <further sections> <separator>
PRINT # <channel>
PRINT # <channel> , <section>
PRINT # <channel> , <section> <separator>
PRINT # <channel> , <section> <separator> <further sections>
PRINT # <channel> , <section> <separator> <further sections> <separator>
channel: integer expression with the value 1 or 2
section: string expression or integer expression
separator: comma or semicolon

The PRINT statement outputs numbers, text and/or a line break to the screen or to an output channel. The output goes to the output channel if the number of the output channel was specified after a hash sign. In that case, the error variables ERR and ERR$ are also set. Without a channel number, the output goes to the screen.

The PRINT statement can contain several sections, separated by commas or semicolons. A section serves to output either a string or a numeric value, depending on whether the section contains a string expression or a numeric expression.


The CHR$ Function

With the function CHR$, any byte, including null bytes, can be output. If you pass the function the value 0, it normally returns an empty string. However, this does not apply if the CHR$ function is a stand-alone section in the PRINT statement. In that case, the byte whose value was passed to the CHR$ function is always output, even if the value is 0. The example shows writing a binary file that consists of only a single null byte:

OPEN "datei.bin" FOR BINARY OUTPUT AS #1
IF ERR THEN
  PRINT ERR$
ELSE
  PRINT #1,CHR$(0);
  CLOSE #1
ENDIF


The SPC Function

The SPC function is used to output a specific number of spaces. You pass the function the number of spaces as an argument, written in parentheses. The example shows the output of 10 spaces between the angle brackets:

PRINT ">";SPC(10);"<"

What is special about the SPC function is that it is only available within the PRINT statement. For this reason it is described here rather than among the regular BASIC functions.

The SPC function has the same effect as the function SPACE$. However, the SPC function is particularly better suited for outputting many spaces, since it does not use the internal string processing and is therefore also not subject to its size limit.


Right- and Left-Aligned Output

Strings are always output left-aligned. For numeric sections, the alignment depends on the preceding separator. If the section is separated from the previous section by a comma, the number is output right-aligned in a field 14 characters wide. Otherwise, the output is left-aligned. The following examples demonstrate this:

left-aligned output right-aligned output
A=12
PRINT "A=";A 		A=12
PRINT "A=",A

With left-aligned output, the first position contains either the sign or a space. If the space is undesired, you must convert the number to a string before output and strip the leading spaces:

A=12
PRINT "A=";LTRIM$(STR$(A))

If a section outputting a decimal number is followed by another section, that section is separated from the number by a space, in line with common BASIC dialects. If this space is undesired, the number must be converted to a string in this case as well. The following example shows how to output the percent sign directly after the number:

P=17
PRINT "Share: ";STR$(P);"%"


Line Break

By default, the PRINT statement moves the cursor to the beginning of the next line after outputting all sections. This line break can be suppressed by ending the statement with a comma or semicolon:

PRINT "A and ";
PRINT "B are on the same line"

PSET

Syntax: PSET <X> , <Y>
PSET ( <X> , <Y> )
X: integer expression with a value >= 0
Y: integer expression with a value >= 0

The PSET statement sets a pixel on the screen using the pen configured with the PEN statement. The position of the graphics cursor is not changed. Please also read the notes on graphics support!

READ

Syntax: READ <variable> [ , ... ]

READ reads the next value from the data area that was created with the DATA statements and writes it to the specified variable. Several variables can be given, separated by commas, in which case several values are read as well. Each value read must match the data type of the specified variable, or be convertible to it (see implicit type conversions).

REM

The rest of the program line is treated as a comment and thus ignored. Instead of the keyword REM, an exclamation mark or an apostrophe (quote character) can also be used.

RESTORE

Syntax: RESTORE
RESTORE <line number>
RESTORE <label>

RESTORE sets the read position of the READ statement to the first data field of the first DATA statement that appears on the specified line, or after the specified label, e.g.:

RESTORE Wochentage
FOR I=1 TO 7
  READ A$
  PRINT A$
NEXT I
END

Wochentage:
  DATA "Mon","Tue","Wed","Thu","Fri","Sat","Sun"

If no line number or label is given, RESTORE sets the read position to the first data field of the first DATA statement in the BASIC program, i.e. the read position is reset to the value it had at the start of the program.

Attention! If a label is given, it must be the label that stands directly before the DATA statement in question. If there is another label or a BASIC line number between the given label and the DATA statement, the compiler reports an error.

RETURN

This statement ends a subroutine that was called with GOSUB. Program execution then continues after the calling GOSUB statement. The RETURN statement must not be called without a preceding GOSUB!

SCREEN

Syntax: SCREEN <integer expression>

The SCREEN statement can be used to set a screen or graphics mode. Which modes, and how many, are available depends on the target system. Please read the notes on target systems for this!

SCREEN 0 sets the default mode, which offers the ability to output text and is always available. Whether graphics statements are also possible in this mode again depends on the specific target system. On some systems, the hardware switches between text and graphics mode. In such cases, several modes are available, e.g. SCREEN 0 for text mode and SCREEN 1 for graphics mode. The constant LASTSCREEN contains the highest screen number that can be used with SCREEN.

Another relevant constant is GRAPHICSCREEN, which contains the number of the graphics-capable screen. This lets you set the graphics mode in a simple and portable way, provided the target system supports graphics:

 SCREEN GRAPHICSCREEN

If the SCREEN statement is called with the number of the screen mode you are already in, nothing happens.

SELECT CASE

Syntax: SELECT CASE <integer expression>
  CASE <value list> <statements>
  [ CASE <value list> <statements> ]
  [ CASE ELSE <statements> ]
END SELECT
value list: comma-separated list of integer literals and/or integer constants,
can also be just a single value

With this statement, an integer expression is tested against constant values. If a value matches, the statements after that value or value list are executed and the SELECT CASE statement is exited. If none of the given values match, the statements after CASE ELSE, if present, are executed.

Example: dice game:

N=0
DO
  W=FALSE
  P=RND(6)+1
  SELECT CASE P
    CASE 1 PRINT "one point"
    CASE 2 PRINT "two points"
    CASE 3 PRINT "three points"
    CASE 4 PRINT "four points"
    CASE 5 PRINT "five points"
    CASE 6 PRINT "six points -> roll again":W=TRUE
  END SELECT
  N=N+P
LOOP WHILE W
PRINT "Total rolled:";N

Example: color evaluation:

BUNT=FALSE
SELECT CASE POINT(X,Y)
  CASE BLACK
    PRINT "black"
  CASE WHITE
    PRINT "white"
  CASE RED,GREEN,BLUE
    PRINT "primary color"
    BUNT=TRUE
  CASE ELSE
    PRINT "mixed color"
    BUNT=TRUE
END SELECT


Note: The SELECT CASE statement can also be written on a single line. In that case, a colon must be placed as a statement separator before each CASE branch and before END SELECT. However, for the sake of readability, it is strongly recommended to use one of the multi-line formats shown in the two examples.

SUB

Syntax: SUB <procedure name>
SUB <procedure name> ( <argument> [ , ... ] )

This statement begins the implementation of a user-defined procedure. This implicitly also ends the main program. The procedure ends with the END SUB statement.

Please also read the notes on user-defined functions and procedures!

SWAP

Syntax: SWAP <variable_1> , <variable_2>

This statement swaps the contents of two variables. This is more efficient than three self-written LET statements. The SWAP statement is especially beneficial when swapping the contents of string variables, since in that case the dynamic memory management of string processing is not invoked.

Example:

DIM T$(2) AS STRING
T$(1)="Text 1"
T$(2)="Text 2"
SWAP T$(1),T$(2)
PRINT "T$1=";T$(1)
PRINT "T$2=";T$(2)

WAIT

Syntax: WAIT <I/O address> , <mask> [ , <inversion> ]
I/O address:integer expression
mask:integer expression
inversion:integer expression

This statement waits for a particular state to occur at the input port specified by the first parameter. To do this, it continuously reads from this input port and ANDs the value read, bit by bit, with the mask. If the result is 0, it reads again. The function thus waits until one of the bits read and selected by the mask is set.

So that you can also wait for bits to be cleared, there is an optional third parameter. For all bits that are set there, the inverse logic applies, i.e. the function waits until one of the bits read is 0.

The WAIT function waits until the following expression yields a value not equal to 0:

(<value read> XOR <inversion>) AND <mask>

WEND

This statement marks the end of a loop that was previously opened with the WHILE statement.

WHILE

Syntax: WHILE <condition>
condition:integer expression

The WHILE statement marks the beginning of a pre-test loop, i.e. before each pass through the loop, a check is made whether the condition is satisfied. If so, the statements in the loop are executed. If not, execution jumps to the end of the loop (see WEND). Every WHILE loop must be closed with WEND.

I=1
WHILE i<10
  PRINT I
  I=I+1
WEND
