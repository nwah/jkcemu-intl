Disassembler

With the disassembler, also called a reassembler, you can translate the bytes located in the emulator's working memory into assembler syntax.

  • 2. Creating a Breakpoint/Logpoint in the Debugger
  • 3. Generating Assembler Source Code

1. Disassembling a Memory Range

After starting the disassembler, you need to enter the start and end address of the memory range to be disassembled. Then choose the menu item File → Disassemble, and the disassembly listing is displayed in the window. You can now save or print this listing. Undocumented processor instructions are marked with an asterisk at the beginning of the mnemonic.

You can also start the actual disassembly by pressing the Enter key, as long as the cursor is in the input field for the end address.

Optionally, you can import a label table (e.g. from an assembler) in order to also see labels or logical names in the disassembler.

Caution! The memory range disassembled is the one the microprocessor sees at that point in time. If the emulated system has several memory banks overlapping in that address range, you must make sure yourself that the correct bank is switched in.

Caution! The disassembler is not able to understand the semantics of the disassembled program code, i.e., non-executable data areas are not recognized as such. All bytes in the memory range to be disassembled are therefore always interpreted as machine instructions of the microprocessor, regardless of whether they actually represent executable program code.

2. Creating a Breakpoint/Logpoint in the Debugger

In the context menu (right mouse button) you find a menu item with which you can create a breakpoint/logpoint on a program address in the Debugger. The address over which you opened the context menu is then adopted into the new breakpoint/logpoint. The same applies to the optional name, if you have imported labels into the disassembler and opened the context menu over such a label.

3. Generating Assembler Source Code

The disassembler is able to generate assembler source code from the disassembly listing. You find the functions for this in the File menu (→ Open as Source Code in Text Editor... or → Export as Source Code...).

When generating assembler source code, assembler labels are also generated. These consist of a prefix and the corresponding address in hexadecimal form. You are asked for the prefix before the source code is generated, i.e., you can specify it yourself. However, the prefix must conform to the naming conventions for assembler labels.

Caution! Undocumented processor instructions that are marked with an asterisk in the disassembly listing no longer contain an asterisk in the generated assembler listing, so that the assembler does not report a syntax error. If the undocumented instruction is merely a different byte sequence for a documented instruction, this automatically converts the undocumented instruction into a documented one.

4. Settings

The font for the disassembler output can be changed in the JKCEMU Settings window, on the Fonts/Icons tab, under Font for code areas.
