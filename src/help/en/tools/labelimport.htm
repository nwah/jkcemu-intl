Importing Labels

Debugger and Disassembler offer the ability to import a label table (e.g. from an assembler). In the debugger, a breakpoint/logpoint is created for each label, so this is equivalent to importing breakpoints/logpoints as well. Since you usually do not want to stop at every label, the imported breakpoints/logpoints are initially disabled by default, i.e., stopping and logging are switched off. If needed, you must enable the individual breakpoints/logpoints manually.

The label table does not have to conform to a strict format: for each line, the first two groups of digits/letters are evaluated. One of them must be a four-digit hexadecimal number, which may have an H appended. Case does not matter. This hexadecimal number is interpreted as an address. The other group of digits/letters is accordingly the label, provided it contains only letters, digits, the underscore and/or the dollar sign, e.g.:

 1234Label1
 2345hLabel2
 ABCDLabel3
 BCDEhLabel4
 0CDEFLabel5
 0FFFFhLabel6
 0BCDELabel7
 Label83456
 Label94567h


Spaces and tabs before the first group of digits/letters do not matter and are simply ignored:

 1234Label1
    2345h Label2
 ABCDLabel3


If the label comes before the address, it may also be terminated with a colon, e.g.:

 Label8:3456
 Label9:4567h


Text after the address and the label (e.g. a comment) is ignored. Accordingly, lines like the following are also possible:

  1234 Label1 Comment
  2345h Label2 ;Comment


If a line contains only a four-digit hexadecimal number without a label, it is still imported into the debugger and a breakpoint/logpoint is created for it there. The disassembler, on the other hand, cannot do anything with a single address and ignores such a line.

All other lines are ignored. Accordingly, it usually does not matter either if the label table contains other text before or after it.
