1. Assembler Options

The assembler options let you control how the assembler works, in particular with regard to the supported mnemonics and syntax and what should be done with the generated program code. You set the assembler options in a window that appears the first time the assembler is started. You can also call up and change the options at any time using the menu item Assemble With....

The options are self-explanatory. However, an explanation can be found in the section Command Line. Contrary to the description given there, when the assembler is called from the text editor, the optional assembler listing is not written to a file but is instead displayed in the text editor, where it can be saved manually.

Among other things, the assembler options also let you specify a file to which the generated program code is written. The format of the file is determined by the file extension (*.tap produces a KC-TAP file).

Caution! With KCC, KCM and KC-TAP files, there are differences between KC85/1, KC87 and Z9001 on the one hand and HC900 and KC85/2..5 on the other. To ensure that the assembler generates the correct file format, it takes its cue from the system currently being emulated. If JKCEMU is currently emulating a KC85/1, KC87 or Z9001, the file type COM is entered in the file header, and KC-TAP files start with block number 0. In all other cases, no file type is entered. In addition, KC-TAP files then start with block number 1, in accordance with the HC900 and KC85/2..5 conventions.

If you have several assembler source files open in the text editor, the assembler options are managed separately for each source file.

2. Assembler Output and Error Messages

All assembler output, i.e. messages about the progress of processing, error messages, warnings and, if specified in the assembler options, the output of the label table, appear in a separate window that is opened each time the assembler is started, or brought to the front of the desktop. You can double-click on error messages and warnings to jump directly to the corresponding location in the source code.

3. General Syntax

3.1. Upper and Lower Case

Except for character and string literals, the assembler does not distinguish between upper and lower case, i.e. the mnemonics of the instructions and the registers can be written in either upper or lower case. For labels, you specify in the assembler options whether upper and lower case should be distinguished.

3.2. Structure of an Assembler Source Line

The general syntax of a source line is:

[label[:]] [mnemonic [argument_1[,argument_2[,...]]]] [;comment]


Expressions in square brackets are optional. A label must begin at the start of a line. An assembler instruction (given by a mnemonic) must not begin at the start of a line, i.e. if the line does not contain a label, the mnemonic must be preceded by at least one space or a tab. An exception is formed by the instructions for conditional assembly. These can be placed at the start of a line, but can also be indented.

3.3. Labels

Labels have a numeric value and are defined by being placed at the start of an assembler line. If this line contains the pseudo-instruction EQU, the label receives the value of the expression following EQU, otherwise the value of the current address.

Labels can be used as jump targets or in numeric expressions.

Labels can contain letters, digits, the underscore, the @ character and the question mark. However, digits and the question mark are not allowed at the start of a label.

Caution! To support conditional assembly, the assembler automatically always defines the label __JKCEMU__ with the value -1 (all bits set).

3.4. Assembler Instructions

Assembler instructions are written in the form of a mnemonic. The assembler understands the following instructions:
  • pseudo-instructions
  • processor instructions according to Zilog syntax (if allowed in the assembler options)
  • processor instructions according to Robotron syntax (if allowed in the assembler options)
  • undocumented processor instructions (if allowed in the assembler options)

3.5. Comments

Comments begin with a semicolon. Everything from the semicolon to the end of the source line is treated as a comment and is not evaluated by the assembler. This does not apply, however, if the semicolon appears within a character literal or a string literal. In that case, the semicolon does not mark a comment.

4. Pseudo-Instructions

The assembler understands the following pseudo-instructions:

ALIGN 1 or 2 numeric expressions Align the current address to a power of two, e.g. to 2, 4, 8, 16, etc.
Example:
  ORG 8000H
  DB 1
  ALIGN 100H  ;Current address now 8100H

Optionally, the byte to pad with can also be specified as the second argument:
  ORG 8000H
  DB 1
  ALIGN 4,0FFH  ;Inserts 3 bytes of FFh.

The specified file is inserted unchanged at the current position in the generated program code. The file name can be given with or without a path, and both an absolute and a relative path are allowed. The instruction TITLE is a synonym for the pseudo-instruction NAME and therefore has the same meaning as that instruction.

  CPU U880
U880UNDOC 0 The pseudo-instruction U880UNDOC allows the Robotron mnemonics/syntax as well as undocumented instructions. This overrides the assembler options set in the Mnemonics/Syntax group. The instruction has the same meaning as:
  CPU U880UNDOC
Z80 0 The pseudo-instruction Z80 allows exclusively the Zilog mnemonics/syntax and thereby overrides the assembler options set in the Mnemonics/Syntax group. The instruction has the same meaning as:
  CPU Z80
Z80UNDOC 0 The pseudo-instruction Z80UNDOC allows the Zilog mnemonics/syntax as well as undocumented instructions. This overrides the assembler options set in the Mnemonics/Syntax group. The instruction has the same meaning as:
  CPU Z80UNDOC

All pseudo-instructions can also be written with a leading period, e.g. .ORG, .DB and so on. In that case, the pseudo-instruction is also allowed to appear at the start of a line.

6. Undocumented Processor Instructions

Some opcodes cause the microprocessor to execute instructions that are not documented by the manufacturer. Here, the U880 processor behaves exactly like the Z80 CPU.

The assembler supports these undocumented instructions if you enable this in the assembler options. Since these instructions are documented by neither Zilog nor Robotron, no official mnemonic or syntax exists for them. For this reason, the mnemonics and syntax of these undocumented processor instructions are specific to the JKCEMU assembler and are described below.

Many 8-bit register instructions can also be applied to the low or high byte of either of the two index registers. For this, the assembler understands the following names for the index sub-registers:

This instruction reads a byte from the input port whose address is in register C, and sets the flag register accordingly. The value read itself is not kept.

7. Numeric Expressions

Numeric expressions are used everywhere a numeric value is required. In the assembler instruction

  LD A,3

the 3, for example, is a numeric expression, specifically a numeric literal. However, numeric expressions can also be more complex and contain operations, functions, character literals and labels. In addition, numeric expressions can be nested arbitrarily deep using parentheses.

7.1. Numeric Literal

Numeric literals begin with a digit and can end with a letter that specifies the base of the number. The following letters are possible:

Hexadecimal numbers can also be written in two other syntax variants:
  • % followed by the hexadecimal number
  • X followed by the hexadecimal number enclosed in single quotes

7.2. Character Literal

A character literal is a character enclosed in single quotes, e.g. 'A'. A character literal can be used within a numeric expression.

7.6. Current Address

The current address is represented by the $ character. So if, in an expression, you need the value of the program counter (register PC) at the start of the current assembler line, write the character: $

8. Character Strings

A character string (string literal) consists of one or more characters enclosed in single or double quotes. String literals can only be used with the pseudo-instructions BINCLUDE, DB, DEFB, DEFM, DFB and INCLUDE.

9. Conditional Assembly

Conditional assembly means that parts of the source code are only assembled if a particular condition is met.

A source code section subject to conditional assembly begins with an IF statement, which comes in several variants. The ENDIF statement marks the end of the corresponding source code section, and thus closes the IF statement.

Between IF and ENDIF, the ELSE statement can optionally also appear. The source code between ELSE and ENDIF is only assembled if the section between IF and ELSE is not assembled, and vice versa.

The table describes the various IF statements for conditional assembly:
Statements/SyntaxDescription
IF <numeric_expression>
IFT <numeric_expression>
 The following source code is assembled if the value of the numeric expression is not equal to 0.
IFE <numeric_expression>
IFF <numeric_expression>
 The following source code is assembled if the value of the numeric expression equals 0.
IFDEF <label> The following source code is assembled if the specified label exists.
IFNDEF <label> The following source code is assembled if the specified label does not exist.

The statements for conditional assembly can be placed either at the start of a line or indented. Furthermore, conditional assemblies can also be nested.

The JKCEMU assembler automatically defines the label __JKCEMU__ with the value -1 (all bits set). This lets you detect whether the program is being assembled with the JKCEMU assembler.

Example:

  DB 'This program was assembled with'
IFDEF __JKCEMU__
  DB ' the JKCEMU '
ELSE
  DB ' another '
ENDIF
  DB 'assembler'


10. Command Line

The assembler can also be called from the command line as a standalone program, without the emulator. Under Windows, you need to start the command prompt for this. The command line for calling the assembler looks as follows (adjust the name and path of the JKCEMU JAR file accordingly):

java -jar jkcemu.jar --as [options] <source file>

or

java -jar jkcemu.jar --assembler [options] <source file>

The following options can be specified (case-sensitive!):
OptionMeaning
-h show help on the assembler options
-f <file> read further command line from a file

The command line can be quite long, possibly longer than supported by the command prompt or the operating system. For this reason, the command line can be read from a file.

When it reaches the -f option, the assembler opens the specified file and reads the further command line from it. Once the end of the file has been reached, the rest of the original command line is processed. The assembler thus behaves as if the contents of the file stood in the command line in place of the -f option.

Within the file, the individual command line arguments do not have to be on a single line, but can be split across multiple lines. If a command line argument contains spaces, it must be enclosed in double quotes so that the assembler processes it as a single argument.
-l generate an assembler listing,
The file for the assembler listing has the same path and the same base name as the output file (see option -o). However, the extension is: .lst
-n <number> number of lines per page for the assembler listing,
This option is only useful together with the option -l and causes a page break character and a table header to be inserted automatically into the assembler listing after the specified number of lines. If the option is omitted or the value 0 is specified, no automatic page breaks are generated.
-o <output file> The generated program code is written to the specified file. The format of the output file depends on the extension (*.bin; *.hex; *.kcc; *.kcm; *.tap; *.z80) and on whether the option -9 is specified.
If the option -o is omitted, the output file has the same name as the source file, except for the extension. The extension is: *.bin
-t output the label table,
The label table is written to standard output, unless you have also specified the option -l. In that case, the label table is appended to the assembler listing.
-9 If, with the option -o, a KCC, KCM or TAP file was specified, it is generated in the format for a Z9001, KC85/1 and KC87 (file type COM entered, and for TAP files the first block has number 0). If the option -9 is omitted, KCC, KCM and TAP files are generated in the format for HC900 and KC85/2..5.
-C distinguish upper and lower case for labels
-D <label> define a label with the value -1 (all bits set)
-D <label=value> define a label with the specified value,
The value is given as a decimal, hexadecimal, octal or binary number (see Numeric Literal).
-J translate relative jumps that are too large into absolute ones,
This option causes relative jump instructions with too large a jump distance to not result in an error, but instead to be translated into absolute jump instructions. In that case, a warning is issued.
However, the option has no effect on the DJNZ instruction, since there is no functionally equivalent instruction with an absolute jump for it. Simulating the DJNZ instruction using other CPU instructions also cannot be implemented in a way that is functionally one hundred percent exact, since DJNZ does not affect any CPU flags.
-U allow undocumented instructions
-R allow only Robotron mnemonics/syntax
-Z allow only Zilog mnemonics/syntax
