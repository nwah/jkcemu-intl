Image Viewer/Image Editor

The image viewer is used to display, convert, and save images. The distinguishing feature of the JKCEMU image viewer is that it also supports the file and image formats of some of the emulated systems, including converting images into these formats. For this reason, the image viewer also offers a number of common image editing functions.

The image viewer can also be started as a standalone program without the emulator. To do so, specify the option --iv or --imageviewer on the command line when starting JKCEMU. In addition, an image file can be given after it, which is then displayed in the image viewer.

1. File Formats

The file formats supported by the image viewer depend on the Java runtime environment being used. This usually supports the formats BMP, GIF, JPEG, PNG, and WBMP, as well as TIFF from Java 9 on. Furthermore, the JKCEMU image viewer also handles the IFF/ILBM format. This is the standard graphics format of the Commodore Amiga and has the file extensions *.iff, *.ilbm, and *.lbm

The JKCEMU image viewer can generate images for some of the emulated systems. Depending on the system, these are saved either in a special file format or as a memory image file (see Exporting).

2. Opening and Displaying a File

There are several ways to open a file:
  • Menu item File → Open
  • Click the leftmost icon in the toolbar
  • Drag a file with drag&drop into the image viewer and drop it there
  • Double-click an image file in the File Browser

Furthermore, with the menu item Edit → Paste you can also bring an image that is on the clipboard into the image viewer.

Besides the file formats mentioned above, you can also open A5105 image files with 16 colors (*.scr) and LLC2 HIRES image files (*.pix, 16384 bytes in size).

After opening, the file is displayed. If the checkbox next to the item Fit Window to Image Size is checked in the Settings menu, the window is enlarged or reduced accordingly. This setting, along with the background color, which can likewise be set in that menu, is also stored permanently when you save the JKCEMU settings.

In the toolbar you find icons for rotating and scaling the image. Both of these apply only to the display and do not change the actual image. Clicking the icon to the right of the scaling icon fits the image to the current window size.

On the right of the toolbar are two arrows that take you to the previous or next image. This lets you click your way through all the supported image files in the same directory.

2.1. KC85/4 Image Files

KC85/4 images (this also applies to the KC85/5) consist of two files each: one for the pixel data (*.hip; *.pip) and one for the color information (*.hif; *.pif). If you open one of the two files, the corresponding second file is automatically loaded as well. If the color file does not exist, only the pixel file is loaded and the image is displayed in black and white.

The file filter Supported Image Files (...) in the file selection dialog (File Type selection) shows only the pixel files, so as to avoid clutter. If you want to see the color files as well, you must switch the file filter to All Files.

3. Saving a File

The displayed image can be saved in one of the file formats mentioned above with the menu item File → Save As... or the second icon in the toolbar. This way, images can be converted to other file formats. Note, however, that not all image properties can be saved in all formats. Some file formats support no transparency or only limited transparency, while others have a limited number of colors (GIF, for example, can save at most 256 colors). Depending on the image and the selected file format, saving may therefore resolve the transparency, reduce the number of colors, or abort the save with an error message. In the last case, you must first convert the image with the editing functions into an image format compatible with the file format before you can save it.

The WBMP format has particularly severe limitations. It can only be saved in black and white and only in certain sizes.

3.1. JPEG Parameters When Saving

Via the menu item Settings → JPEG Parameters When Saving... you can specify parameters for saving JPEG files and thereby influence how the files are generated. If the JPEG implementation of the Java runtime environment being used does not support some or all of these parameters, the JPEG files are saved with the respective default values.

3.1.1. Quality

You can specify the quality of the JPEG files when saving. From a technical point of view, this specifies how much the data should be compressed. Since JPEG is a lossy compression method, the more the data is compressed, the more detail is lost. So the higher the quality is to be, the lower the compression rate must be and the larger the saved JPEG files become. With the setting Default, the files are saved the way the JPEG implementation of the Java runtime environment being used does by default.

3.1.2. Forcing Progressive Mode

This mode affects how the image data is arranged in the file. You should only set this parameter if you know its effect on JPEG file generation as well as on reading and displaying such JPEG files.

3.1.3. Generating Optimized Huffman Tables

Normally, standard Huffman tables are used. With this parameter, you specify that Huffman tables optimized specifically for the JPEG files being saved should be generated. This can somewhat reduce the amount of compressed data. However, this also means the JPEG files always contain their own Huffman tables, which in turn makes the files larger. You should therefore only set this parameter if you know its effect on JPEG file generation.

4. Exporting

In the submenu File → Export As there are functions for saving the displayed image in a special format of one of the emulated systems. To do so, the image must first be converted with the corresponding function in the submenu Edit → Convert To. This adjusts both the resolution and the colors. To achieve better results, these steps can also be carried out manually (see Image Editing) before you call the conversion function.

Depending on the emulated system, the converted image can be saved as
  • a special image file,
  • a memory image file for the video RAM, and/or
  • a memory image file with a program for displaying the image
In the case of a special image file, you find information on how the image files can be displayed in the notes on the emulation of the respective system (see A5105 image files and LLC2 HIRES image files).

5. Additional Information (EXIF Data)

Some image files contain additional information, such as a description or the date the image was taken. The JKCEMU image viewer supports reading and writing such additional information, also called metadata, in GIF, IFF/ILBM, JPEG/JPG, and PNG files. The table shows which additional information is supported for which file formats:

File Format Supported Additional Information
GIF
  • Comment
IFF/ILBM
  • Name
  • Description/Remark
  • Author
  • Copyright
JPEG/JPG
  • EXIF data
Note: JKCEMU reads most of the generally applicable entries from the EXIF data and also saves them again. Manufacturer-specific EXIF entries, however, are ignored.
PNG
  • Title
  • Description
  • Author
  • Copyright
  • Comment
  • Software
  • Date and time of capture or image creation
Note: The PNG format offers the three chunk types tEXt, iTXt, and zTXt for storing text information. Of these, JKCEMU uses exclusively the tEXt chunk.

To display the additional information, select the image properties in the File menu. The additional information can also be removed or changed to a limited extent.

Where possible, the additional information is shared between the individual file formats. For example, if you open an IFF/ILBM file in which the field Description/Remark is filled in, this text is saved as EXIF data in the entry Description when the image is saved as a JPEG/JPG file. When saved as a GIF file, the text is found again as a comment in the file. It also works the same way in the other direction.

6. Image Editing

The image editing functions mainly serve to adjust images so that they can be displayed on some of the systems emulated by JKCEMU. An exception is the Round Corners... function. This is used for post-processing screenshots.

After an image editing function has been applied, a new image is internally generated and displayed. You can go back to the old image, i.e. to the unedited image or to the previous editing step (menu item Edit → Undo). This discards the changes made by the last image editing function. The complete image editing history can be found in the submenu Edit → History. There, too, you can go back one or more editing steps with a click.

You find the image editing functions in the Edit menu:

6.1. Rotating

As the name suggests, you can rotate the image. Unlike the icons in the toolbar, this function rotates not the display but the actual image, and not only in 90° steps, but in ¼° steps. After rotating, the image has become larger, exactly large enough for the rotated image to fit exactly.

Rotation by an angle other than a multiple of 90° creates areas in the image with no content. In the dialog that appears when you call the function, you specify at the bottom, under Background, whether these areas should become transparent, white, gray, or black.

Caution! If you rotate an image with transparent areas, the background setting also affects these areas.

6.2. Cropping

Cropping an image works like this:
  1. Using the mouse, with the first (usually left) mouse button held down, select the area you want to keep.
  2. Call the menu item Edit → Crop.... A dialog window appears.
  3. In the dialog, you can adjust the selected area pixel-precisely by changing the values in the 4 input fields.
  4. In the dialog, click the button Crop.

You can also open the dialog first and then select the area with the mouse in the image viewer window. This is particularly useful when the color used for the selection does not stand out clearly enough from the image. In that case, please select a different color for the selection in the dialog.

If the area to be selected should correspond to a particular aspect ratio, you can specify that in the Aspect Ratio selection field.

Caution! In the list of aspect ratios, the LLC2 is found under 4:3. However, this computer has a resolution of 512x256 pixels, i.e. 2:1. The screen output on the TV/monitor, however, is in 4:3, i.e. the pixels are not square. For this reason, you must crop an image for the LLC2 to 4:3 and then scale it to 2:1 (see the next section as well as Converting the Image Format for LLC2 HIRES), so that it is reproduced largely without distortion on the LLC2.

6.3. Scaling

To scale an image, choose the menu item Edit → Scale.... A dialog window appears in which you enter the new width and/or the new height and then click Scale.

If the aspect ratio should be kept during scaling, check the corresponding option. In that case, the corresponding new height is calculated automatically when you change the width, and vice versa.

Caution! Scaling can create new colors. This is especially noticeable with a monochrome black/white image. When adjacent black and white pixels are merged, gray intermediate values result. Since these newly created colors cannot always be represented in an image with indexed colors, the scaled image no longer has an indexed color model. If you need one, however, you can create one again with the menu item Reduce and Index Colors....

Caution! Unlike the scaling in the toolbar, the menu item Scale... changes the actual image.

6.4. Sharpening

To sharpen the image, call the menu item Edit → Sharpen.... This opens a dialog window offering several degrees of sharpening. You can try these one by one. Clicking a sharpening degree immediately sharpens the image accordingly. Once you have found the optimal sharpening degree, confirm with OK.

6.5. Flipping

This function flips the image horizontally, i.e. the sides are swapped. If you want to flip the image vertically, first rotate it by 90°, flip it, and rotate it back with -90°.

6.6. Rounding Corners

This function is used for post-processing screenshots, especially screenshots that show exactly one window. On some operating and window systems, windows have rounded corners. A screenshot taken with JKCEMU, on the other hand, has no rounded corners, so the corners may be considered a cosmetic flaw. With the Round Corners function you eliminate this flaw by making the pixels in the corners transparent, i.e. see-through. You only need to specify how many pixels from each respective corner should be made transparent.

Caution! Rounding the corners results in an image with transparency. So that the transparency is not lost, you must select a format that supports transparency (e.g. PNG) when saving the image.

6.7. Brightness, Contrast, Colors

To change the brightness, the contrast, and the color saturation, call the menu item Edit → Brightness, Contrast, Colors.... A dialog window appears with sliders and input fields for setting these properties. You can change the values both with the slider and with the input field below it.

On the right-hand side of the dialog window you find sliders and input fields for the three primary colors red, green, and blue (RGB color model). With these, you can change the respective red, green, and blue value in all pixels of the image. If you move all three sliders equally, this corresponds to a change in brightness.

You can see the effect of the sliders immediately. For this, a preview image with 256 indexed colors is generated first. This is necessary for a performant preview, because with every change to a value, only the 256 entries in the color palette need to be changed, not every pixel in the preview image. However, generating the preview image can take a few seconds. Clicking the Apply button then computes the actual new image, which, again, depending on the image size, can also take a few seconds.

6.8. Reducing and Indexing Colors

This function indexes the colors of the image by applying a color palette. The color palette to be applied can be determined from the image, chosen from several predefined ones (A5105, KC85/4 HIRES, grayscale, black/white), or imported from a file. Since the color palette contains only a limited number of colors, applying a color palette, i.e. indexing, usually also means reducing the colors.

6.8.1. Determining a Color Palette

This function uses a modified octree method to determine a color palette that covers the colors contained in the image as well as possible. You only need to specify how many colors the palette should have (maximum 256).

6.8.2. Importing a Color Palette

With this function you import a color palette from a file. The file can be a Paintshop Pro or IFF/ILBM color palette file, or a supported image file that contains a color palette.

The ability to import also lets you use your own color palettes. Since a Paintshop Pro color palette file is a text file with a fairly simple format, you can, following this format, simply type your own color palette into a text editor, save it as a *.pal file, and then import it. The line-ending bytes must match the DOS/Windows format (bytes 0Dh/0Ah, which can be produced under Mac/Linux/Unix in the JKCEMU text editor with Save As...).

A Paintshop Pro color palette file has the following structure:

LineValue/Meaning
1JASC-PAL
20100
3Number of colors as a decimal number
4 Red, green, and blue value of the first color, as three decimal numbers each separated by a space
5 Red, green, and blue value of the second color, as three decimal numbers each separated by a space
63rd color, etc.

The file for the KC85/4 HIRES color palette (colors black, red, cyan, and white) thus looks like this:

JASC-PAL
0100
4
0 0 0
255 0 0
0 255 255
255 255 255


Caution! Unlike importing a color palette as described further below, here the image is recreated based on the imported color palette. Any existing assignment of pixels to color palette indexes is not necessarily preserved.

6.8.3. Dithering

Applying a color palette reduces the number of colors, and thus also the quality of the image. Especially when reducing to very few colors, the loss of quality is considerable. With dithering, it is possible to visually counteract this loss of quality. Missing colors are simulated by cleverly placing neighboring pixels of different colors. In that case, the human eye perceives mixed colors that are not actually present in the image at all. Dithering works particularly well when the image has so many pixels that the eye does not perceive the individual pixels.

Specifically, dithering works as follows: The first pixel is given the color from the color palette that comes closest to the original pixel color. The difference between the original and the new color is a color error. This color error, i.e. the respective difference amount for the three primary colors red, green, and blue, is distributed to the next pixels. For the second and subsequent pixels, the original color is then added to the proportional color error, the closest matching color is again looked up, a new error portion is again calculated, this is again distributed to the following pixels, and so on.

There are various dithering algorithms that differ in the way they distribute the respective color error. The JKCEMU image viewer includes three algorithms. Which algorithm gives the best result is a matter of personal taste and should be tried out on a case-by-case basis.

6.8.3.1. Floyd-Steinberg

The Floyd-Steinberg algorithm was published in 1976 by the two gentlemen of the same name. The algorithm distributes the respective color error in odd fractions to the next pixel to the right and to three pixels in the next row. Floyd-Steinberg dithering delivers good results and is essentially the standard method.

6.8.3.2. Sierra 3

After the publication of the Floyd-Steinberg algorithm, various other algorithms were proposed by different people that are supposed to deliver a somewhat better image quality. One of these algorithms is Sierra-3. The 3 in the name means that the color error is distributed over three pixel rows (instead of just two, as with Floyd-Steinberg). This results in somewhat finer transitions and gradations. Overall, though, the difference in quality compared to Floyd-Steinberg is fairly small, as it is with all other dithering algorithms published after Floyd-Steinberg. The JKCEMU image viewer includes Sierra-3 as a representative of the three-row dithering algorithms.

6.8.3.3. Atkinson

Atkinson worked at Apple and played a major part in the development of Apple graphics software. He published a dithering algorithm that differs from the other algorithms in one significant way: Atkinson does not distribute the entire color error to the following pixels, but only three quarters of it. This reduces color bleeding, i.e. the transfer of a color portion to the following pixels.

This difference is also noticeable visually. Bright and dark areas are less interspersed with pixels of a different color, which makes the areas appear more homogeneous and increases the contrast. For this reason, the Atkinson algorithm is also included in the JKCEMU image viewer.

6.9. Converting to Black/White

In the submenu Edit → Convert to Black/White, you find functions for converting the image to grayscale or to a monochrome black/white image. The latter is possible by threshold as well as by dithering. When converting to grayscale, any existing transparency is preserved; when converting to a monochrome black/white image, it is not.

6.10. Inverting

The Invert function creates a kind of negative image, which is only useful for special applications, though. For this, each of the three primary colors in every pixel is inverted. The JKCEMU image viewer uses the RGB color model with a resolution of one byte per primary color, i.e. each primary color is represented with a value from 0 to 255. When inverting, this value is converted as follows:

New value = 255 - old value

So, for example, if a pixel has the RGB color value [38,72,165], it becomes the color [217,183,90].

6.11. Removing Transparency

The JKCEMU image viewer can handle images that contain transparent pixels. However, there are functions where transparency gets in the way or is not supported at all. For example, saving transparent images is not possible in the BMP and WBMP formats, and is only possible in certain cases in the IFF/ILBM format. For this reason, there is the menu item Edit → Remove Transparency..., which can only be called when the displayed image contains transparency. The function simply replaces the transparent pixels with the color you specify in the dialog. With the option color stored in the pixels, the transparent pixels are displayed fully opaque, using the color that is stored in the pixels themselves. Even if a pixel is fully transparent, it still contains a color value, which is then used.

6.12. Color Palette

With this menu item, for an image with indexed colors, you can view, change, export, and import the color palette. When changing and importing, only the color values in the palette are changed. The assignment of pixels to the indexes in the color palette remains unchanged. This way, you can swap colors and create false-color images.

The simplest way to change a color is to manually enter a new color value as a hexadecimal number in the column New ARGB Value (hex). To do so, double-click the table cell, enter the value, and then press Enter. The 8-digit color value contains, from left to right, the alpha value followed by the values for the primary colors red, green, and blue.

The alpha value specifies the opacity of the color. At the value 00, the color is fully transparent, i.e. it has no opacity at all. At the value FF, the color is fully opaque, i.e. no transparency. If you enter only 6 or fewer hexadecimal digits, the original alpha value is kept.

With the Color... button you can select the color from a predefined palette or from the most recently imported color palette. For this, a table row for which the color value is to be changed must be selected first.

The color palette can be exported to either of two file formats:
  • Paintshop Pro color palette file
  • IFF/ILBM file without image data
Neither format supports alpha values, i.e. the alpha values are not exported.

The IFF/ILBM format is actually meant for storing images, but is also used, without image data, for storing color palettes. The format can in principle also store alpha values, but only in the image data, not in the color palette. For this reason, the color palette is also exported without alpha values in the IFF/ILBM format.

Color palettes can be imported from the two formats mentioned above as well as from other supported image formats that contain a color palette or color table. When importing, the colors are matched to the original colors as closely as possible. If you do not like the automatic matching, you can change it with the Color... button. Alpha values are not imported, i.e. the original alpha values are preserved.

Caution! Unlike importing a color palette as described further above, here only the colors are swapped. The existing assignment of pixels to color palette indexes is preserved.

7. Converting an Image to the Format of an Emulated System

With the menu items in the submenu Edit → Convert To you convert the image to the format of a system emulated by JKCEMU, referred to below as the target system. This conversion applies only to the image format, i.e. to the resolution and to the colors. The matching file format is only created when you export the image. However, converting the image format beforehand is a necessary prerequisite for that.

When converting to the format of the target system, the image is first scaled to the necessary size. If the aspect ratio does not match, black bars are inserted on the left and right or top and bottom. In the second step, the colors are converted to the color palette of the target system. For this, the closest matching color from the color palette is simply taken for each pixel. If the target system has block graphics, the third step determines the best-matching block graphics symbols.

7.1 Manually Converting the Image Format

The automatic conversion of an image to the format of the target system does not always deliver the result you want. In particular, adjusting the aspect ratio by means of black bars is not always to your liking. For this reason, it is sometimes better to carry out the individual conversion steps manually. To achieve the best possible results, the steps should be carried out in the following order:
  1. Rotate
    only necessary if needed, e.g. to compensate for a skewed angle

  2. Crop
    Switch off the option Keep aspect ratio and instead select the correct aspect ratio of the target system, or ensure it yourself

  3. Scale to the pixel resolution of the target system

  4. Sharpen
    only if needed

  5. Adjust colors
    If the target system supports colors, you usually have to boost the contrast and the color saturation considerably, and then adjust the brightness so that a colorful and balanced image results (all these functions are in the menu item Brightness, Contrast, Colors). After that, call the menu item Reduce and Index Colors, select the correct color palette there, and convert the colors to the color palette of the target system, either with or without dithering.
    If the target system does not support colors, use one of the two functions in the submenu Convert to Black/White to create a monochrome image. It may be useful to adjust the brightness and contrast of the image first.

  6. call the corresponding menu item in the submenu Edit → Convert To

The order is particularly important when applying dithering, because after dithering the image should no longer be scaled.

7.2 Converting the Image Format for LLC2 HIRES

The LLC2 has a resolution of 512x256 pixels, i.e. 2:1. However, the screen output is usually in 4:3. For this reason, the image must be distorted accordingly so that it is then displayed correctly again in the 4:3 presentation. The menu item Edit → Convert To → LLC2 HIRES format (512x256, monochrome) with adjustment for 4:3 display does this automatically. However, if you perform the image format conversion yourself, you must also ensure the necessary distortion yourself. To do so, please follow the order given in the previous section and note the following:
  • Crop:
    Select the aspect ratio 4:3 and crop the image to 4:3 accordingly.

  • Scale:
    Switch off the option Keep aspect ratio and scale the image to 512x256 pixels. This produces the necessary distortion.

  • Convert:
    Call the menu item LLC2 HIRES format (512x256, monochrome) without adjustment for 4:3 display. The adjustment (distortion) has already been done during scaling.



8. Further Functions

While an image is displayed, besides the functions described in the other sections you can also:
  • copy the image to the clipboard
  • print the image
  • view the image properties

You find the corresponding menu items under File, and, for copying to the clipboard, under Edit.
