1. Preliminary Remarks

On some of the computers emulated by JKCEMU, data is stored on magnetic tape, i.e. on a cassette. In principle, this is also possible in the emulator with the help of the audio functions, but files can be stored much more conveniently in the file system of the computer running the emulator, which is why this is usually how it is done instead. JKCEMU supports several file formats for this.

Caution! On the emulated computers, saving and loading BASIC programs is handled by the BASIC interpreter rather than by the operating system or monitor program. BASIC files also frequently have a different format. For this reason, a different procedure is required for BASIC programs. Please read about this here.

2. Loading a File

There are three ways to load a file from the file system into the emulator:
  1. via a file selection dialog
  2. using the File Browser
  3. via drag&drop

2.1. Loading a File via the File Selection Dialog

This classic way of loading a file is done via the File menu, menu item Load.... A file selection box appears, in which you can select the file.

Depending on your choice (see Settings), JKCEMU offers you its own file selection dialog or the operating system's file selection box. The JKCEMU file selection dialog is optimized for the specifics of the emulator. If you have selected a file that contains header data with a load address, you can load it into working memory by clicking Load. If the file contains an executable machine code program and a start address is stored in its header data, clicking the Start button loads the file into working memory and starts it immediately. The third option, Load With..., lets you enter load options, such as different load addresses.

If you use the operating system's file selection box, after selecting a file you are always taken to the mode for entering the load options.

2.1.1. Load Options

The load options include the choice of file format, the load addresses, and, in the case of a Headersave file while a Z1013 is being emulated at the same time, whether the Headersave header data should additionally be copied to the address range of working memory reserved for it. The load options are entered in a separate window.

For some file formats, the load addresses are stored in the file (header data), so that you do not need to specify a start and end address explicitly. However, if you want to load the file to a different location in working memory, you must enter the corresponding start address. The field for the end address can be left empty.

The load options also let you load a file in a format other than the one that was automatically detected. For example, there are Z1013 files that have a file header compatible with Headersave, but that does not contain the Headersave identifier. As a result, the file is not recognized as a Headersave file. In that case, however, it can still be loaded as one. But you must be absolutely certain of what you are doing with such things! Misuse can cause the program running in the emulator to crash and thus lead to data loss.

If a Z1013 is currently being emulated and you want to also load the header data of a Headersave file, when loading it, into the address range of working memory reserved for it, enable the corresponding option.

2.2. Loading via Drag&Drop

In the File Browser, select a file, drag it with the mouse button held down over the emulator window, and drop it there. So that you do not accidentally load a file this way and thereby destroy data in the emulator's working memory, the window for entering the load options always appears as a safety measure.

Note: On some platforms or operating systems, drag&drop also works across program boundaries, i.e. you can also select a file in another program, e.g. a file manager, drag it into JKCEMU, and drop it there.

3. Starting a Program

Starting a program requires that the corresponding program file has been loaded first. If the program file contains a start address, you can have the program started immediately as you load it. Otherwise, you must start the program manually through the operating system or the monitor program.

4. Saving a File

In the File menu, click on the item Save. A window appears in which you enter the addresses of the range to be saved, select the file format, and, depending on the selected file format, specify the header data.

You must fill in the Start Address and End Address fields in hexadecimal. These values are automatically used as header data, provided the selected file format supports header data. However, you can also specify different addresses as header data, which are then only used when loading the file.

If a Z1013 is currently being emulated and you want to also load the header data of a Headersave file, when saving it, into the address range of working memory reserved for it, enable the corresponding option.

Clicking the Save button brings up a file selection dialog. Here you specify the name of the file to be saved.

4.1. Automatic File Name Extension

If you specified a file name without an extension when saving, the file extension is appended automatically, provided it is clear which extension the file being saved must have. For this, you must use the JKCEMU or Java/Swing file selection dialog (see Settings) and have selected a file filter (File Type choice) that allows exactly one file extension.

Automatic file name extension applies not only when saving programs, but everywhere in JKCEMU when saving a file.
