Settings

You make the settings for the emulator in a separate window, which you open via the menu Extra → Settings... of the main window. In addition, some of the tools built into JKCEMU have their own settings. You reach those settings via the menu of the respective tool.

All further explanations on this help page refer to the settings for the emulator, which you find in the separate window. Changes to these settings only take effect after they have been applied. To do that, press the Apply button.

1. Grouping of the Individual Settings

The individual settings are grouped by topic. You find each group on a separate subpage, which you reach via the tabs at the top edge.

1.1. System

In this area you specify the system to be emulated, i.e. the type of computer to be emulated. For some systems there are various configuration options, which you can influence on the right-hand side in the Options area. For notes on how the individual computer types are emulated, see Emulated Systems.

1.2. Speed

Here you specify which clock frequency should be emulated. By default, the original speed of the emulated system is imitated. However, you can also specify a different value.

The emulator tries to reach the desired speed, but not to exceed it. However, should the available processing power not be sufficient for that, a correspondingly lower clock frequency is emulated.

1.3. Confirmations

Here you specify which actions should only be carried out after confirming a safety prompt.

1.4. Screen Output

Brightness, margin, and all other settings that relate exclusively to the screen output are found in this group.

1.4.1. Margin Around Screen Output

You can create a margin around the screen output by dragging the main window larger. However, if you then choose a different scaling of the screen output, or select a different system to be emulated in the settings, the emulator adjusts the main window to the new requirements, which makes the margin disappear again. With this option you can specify a default margin that is automatically created in such cases.

1.4.2. Refresh Cycle for Screen Updates

The emulator cyclically updates the screen output according to the changes in the screen refresh memory or the video RAM. A shorter refresh cycle produces a smoother screen output. However, this also increases the demand for processing power.

1.5. Window Scaling

On high-resolution screens, the windows sometimes look rather small. For this reason, JKCEMU offers the option of having the windows scaled larger. The scaling is based on a feature that was introduced with Java 9. For this reason, a Java runtime environment in version 9 or higher is required for scaling.

By default, Java (from version 9 on) scales the windows automatically on high-resolution screens. However, JKCEMU offers the option of changing this default behavior. You can switch the scaling off, leave the Java default behavior as is, or set a fixed scaling. For fixed scaling, you enter any percentage value into the corresponding input field and press Enter. On some operating systems, however, only scaling in 100% steps is supported.

Scaling can look a bit unattractive, though, when the objects being scaled have hard edges. This is the case, for example, with the screen output of the emulated systems as well as with the icons. For this reason, JKCEMU offers yet another option for high-resolution screens, namely adjusting the size of the fonts and icons.

1.6. Fonts/Icons

Fonts and font sizes can be freely chosen. For this purpose, the graphical objects are divided into various groups, and for each group the fonts can be set separately. Furthermore, for the icons you can choose between two display sizes.

1.7. Appearance

JKCEMU was developed with the Java programming language, which is based on a cross-platform concept. Some people want an application to look the same under every operating system, while others prefer an application to adapt to the look of the respective platform. Java accommodates these different demands by being able to present itself in various appearances. JKCEMU therefore offers this option as well.

Which appearances are supported on which platform depends on the respective Java version. As a rule, though, these are at least the cross-platform appearance Metal and an appearance adapted to the local operating system.

If only a single appearance is available, i.e. if no selection is possible, the Appearance subwindow in the settings is not offered at all.

1.8. Network

The network must be configured in order to use it (see here). In the original, this is done with a special program. In the emulation, JKCEMU can do this work for you. You find the necessary settings here.

If you want to stay as close to the original as possible and forgo configuration by JKCEMU, then leave the input fields empty and switch off the option Automatically determine the IP addresses of the fields left empty.

1.9. Miscellaneous

In this group you find the settings that cannot be meaningfully placed in any other group.

1.9.1. File Selection Dialog

JKCEMU comes with its own file selection dialog. It is tailored to the needs of the emulator. For example, as soon as you click a file you can see its relevant information in the status bar, provided the file type is supported by JKCEMU. Furthermore, the JKCEMU file selection dialog offers file filters, i.e. the option of selecting a context-dependent file type. If you select a file type, only the files matching that type are displayed. In addition, provided you want to save the file and the selected file type allows exactly one file extension, the automatic file name extension is also active.

A disadvantage could be that the JKCEMU file selection dialog is possibly not adapted to special peculiarities of the operating system (e.g. quick access to special libraries and folders, or direct access to the network). For this reason, you have the option of using the operating system's standard file selection box instead of JKCEMU's own. However, when you click a file, it does not display its relevant information and it also does not support file filters. In addition, it is possible that the operating system's file selection dialog has its own management of the most recently used directories and thus ignores the directory specified by JKCEMU.

In addition, JKCEMU offers the option of using the Java/Swing file selection dialog. While this likewise does not display any relevant information when you click a file, it does at least offer file filters and thus also the automatic file name extension when saving. The Java/Swing file selection dialog is thus positioned between the JKCEMU and the operating system's own file selection dialog.

Caution! The Java/Swing file selection dialog tries to imitate the original file selection dialog of the configured appearance, both in look and function. If, for example, you have set the Windows appearance under Windows, the Java/Swing file selection dialog accordingly looks very similar to Windows' native selection dialog. If you have set a different appearance, the Java/Swing file selection dialog sometimes presents itself completely differently.

1.9.2. Configuration Directory

Here, for your information, you see the full path of the configuration directory, i.e. the directory in which JKCEMU stores its settings and profiles as well as, under Windows, a DLL. To determine this directory, the emulator evaluates the environment variable APPDATA. If this environment variable is not set, the location for your own files is used.

You can also delete the directory (button Delete All Settings and Reset JKCEMU...). JKCEMU then behaves at the next start as if it were being started on the computer for the first time.

2. Saving and Loading Settings

You can save your settings in the form of profiles and load them again. Saving is only possible after the settings have been applied.

If the name of such a profile is specified as an argument when starting the emulator, JKCEMU starts right away with these settings. Otherwise, the emulator tries to load the profile standard. You should therefore save your most frequently used settings under this name.

A profile can also still be applied after the emulator has been started. You find the corresponding menu item for this in the JKCEMU main window under Extra → Apply Profile....

Caution! When a profile is saved, all settings are saved, both the settings for the actual emulator as well as the positions, sizes, and settings of all windows and tools currently open. It is also saved which audio functions are currently active. If you start JKCEMU again with such a saved profile, all these settings are applied. However, apart from the windows necessary for the actual emulation, no further windows are opened.

Caution! If you subsequently load a profile via the menu item Extra → Apply Profile..., not all settings are applied. Specifically, the saved window positions for windows already open are not applied, since that could cause the windows to jump around, which would be very confusing. Furthermore, the audio functions saved in the profile are not automatically activated, since this could also be disruptive.

2.1. Exporting and Importing Profiles

Profiles can be exported and imported, e.g. in order to exchange them with other JKCEMU users. The export and import functions are available in the dialog for loading or applying a profile.

3. Resetting Settings

If you have ever changed settings and do not know how to set them correctly again, then you need to reset the settings. You do this by deleting the corresponding profile and then closing the emulator. This applies in particular to the profile standard as well.

To delete a profile, press the button Load Profile.... In the selection dialog that then appears, you find the button for deleting.

A more far-reaching way to reset the settings is to delete the entire configuration directory (button Delete All Settings and Reset JKCEMU...). If you delete this directory, JKCEMU starts the next time as if it were being started on the computer for the first time.
