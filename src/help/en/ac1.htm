AC1

The amateur computer AC1 is a development by Frank Heyder and other radio amateurs, published from late 1983 onward as construction instructions in the magazine Funkamateur. Over time, the AC1 was continuously developed further, which, however, also led to the development lines diverging. Besides the development line around Frank Heyder of the Amateur Computer Club Berlin (ACC), there was also a competing line from Eckard Ludwig of the Studio Computer Club Halle (SCCH), which was later continued by Jürgen Beisler of the AC1 Club Leipzig. The SCCH developments are not fully compatible with those of the ACC development line (e.g. monitor programs and character sets), but they significantly increased the AC1's capabilities and also attempted to curb the resulting proliferation of incompatible variants. Furthermore, the SCCH developments were also adapted for the LLC2, which led to a certain compatibility between the (SCCH) AC1 and the (SCCH) LLC2.

In 2010, a new edition of the AC1 project (AC1-2010) appeared, which combined elements of the SCCH line with new developments and modules.

1. Emulated Hardware

In principle, the AC1 exists in three different expansion levels: the original AC1 (Ur-AC1, the first published version), AC1-ACC (the further development by the Amateur Computer Club Berlin), and AC1-SCCH (the further development by the Studio Computer Club Halle). In addition, there is a design from 2010 called AC1-2010, which is partly based on the SCCH concept.

Since the AC1 was published as construction instructions, many other configurations and further developments can also be found.

Emulated:
  • Ur-AC1:
    • 4 KByte ROM for the monitor program and Mini-BASIC
    • 1 KByte static RAM (SRAM)
    • 1 KByte video RAM for 64x16 characters
    • CTC with connections between all four channels (0→1, 1→2, and 2→3)
    • cassette recorder connection
  • AC1-ACC:
    • 4 KByte ROM for the monitor program and Mini-BASIC
    • 2 KByte static RAM (SRAM)
    • 64 KByte RAM
    • 2 KByte video RAM for 64x32 characters
    • CTC with connections between all four channels (0→1, 1→2, and 2→3)
    • cassette recorder connection
  • AC1-SCCH:
    • Everything as with the AC1-ACC,
      but the ROM contains a 4 KByte monitor program instead, so the Mini-BASIC interpreter is dropped.
    • "write-through" to the 64 KByte RAM when ROM is switched into the relevant address range
    • SCCH module 1 (additional ROM)
    • SCCH module 3 (additional RAM)
    • SCCH inverse circuit
    • character set switching (only with monitor program 10/88 and color graphics)
    • graphics key (F2)
    • switching the monitor program ROM in and out via OUT 16h/17h as per AC1-Info 11/1988
    • V24 interface with printer
  • AC1-2010:
    • Everything as with the AC1-ACC,
      but the ROM contains a 4 KByte monitor program instead, so the Mini-BASIC interpreter is dropped.
    • "write-through" to the 64 KByte RAM when ROM is switched into the relevant address range
    • AC1-2010 ROM banks
    • SCCH inverse circuit
    • inverting the entire screen via system PIO B3
    • graphics key (F2)
    • V24 interface with printer
  • Optional:
    • color graphics
    • RAM floppy according to the magazine Mikroprozessortechnik, issue 3/1988, at I/O base address E0h
    • floppy disk module with 4 floppy disk drives
    • GIDE with up to two hard disks at I/O base address 80h
    • K1520 sound card
    • KCNet-compatible network card at I/O base address C0h
    • USB port (Vinculum VDIP module) at I/O base addresses DCh and FCh
    • 1 joystick

1.2. 64 KByte RAM

With AC1-ACC, AC1-SCCH, and AC1-2010, 64 KByte RAM is emulated. The lower 8 KByte overlap the ROM for the monitor program, the video RAM, and the SRAM, and can be switched in and out again via I/O ports 1Ch to 1Fh, and, on the AC1-SCCH, also via I/O port 14h.

Caution! On the AC1-SCCH and AC1-2010, the 64 KByte RAM can also be written even when ROM is switched into the relevant address range (so-called "write-through").

1.3. Color Graphics

Optionally, the color graphics card developed by Heiko Poppe and Ralph Hänsel is emulated, which also offers clock frequency and character set switching as well as an inverse mode. The color memory overlaps the character memory and contains a foreground and a background color per character. The color memory is switched in and out via the readable input/output port F0h, which can also be used to switch the clock frequency.

If the color graphics emulation is activated, the monitor program must also initialize the color memory. Otherwise you will only see a random colorful pattern. Since, however, most of the AC1 monitor programs integrated into JKCEMU do not know about color graphics and therefore also do not initialize the color memory, the emulator does this automatically on every RESET, but only for the relevant integrated monitor programs. If you have loaded the monitor program as an external file, it must also support color graphics itself, or you must switch off the color graphics emulation.

1.5. SCCH Module 1

SCCH module 1 provides additional ROM, specifically:
  • 8 KByte for the Graphics/Sound BASIC interpreter
  • 8 KByte for program package X
  • 256 or 512 KByte for the ROM disk, depending on the setting

The module is controlled via output port 14h:


Bit 0: switch in program package X in the range E000-FFFF
Bit 1: switch in Graphics/Sound BASIC in the range 4000-5FFF
Bit 3: switch in a segment of the ROM disk in the range C000-FFFF or 8000-FFFF,
bits 0, 4, 5, and 6 determine the corresponding 16K or 32K segment.

JKCEMU does not supply any content for program package X or the ROM disk. You must specify this yourself in the settings by loading ROM files.

1.6. SCCH Module 3

Depending on how it is populated, SCCH module 3 provides 64, 128, 256, 320, or 512 KByte of additional RAM, which can be switched into main memory via I/O commands. Specifically, bits 0 to 3 of I/O port 15h select one of 16 possible 64 KByte blocks, which is then switched in as read-only, write-only, or read/write (in which case only 32 KByte), according to bits 4 to 7 of the same I/O port.

The address space for the additional RAM amounts to 1 MByte (16 x 64 KByte). Although the original module can only be populated with a maximum of 512 KByte, JKCEMU emulates the theoretically possible 1 MByte. This has the advantage that software using this additional RAM does not need to be specially configured for use in JKCEMU, because at every address where the respective software expects RAM, it will also find RAM in JKCEMU.

1.7. SCCH Inverse Circuit

The SCCH inverse circuit recognizes the bytes with the values 10h and 11h in the video RAM. At 11h, the inverse display is switched on, and at 10h it is switched off again. Regardless of this, the inverse display is always switched off at the end of a line.

1.8. Inverse Key (F1)

In the original, the SCCH inverse circuit also contains a switch with which the entire screen can be inverted. JKCEMU emulates this switch with the F1 key. Although not common in the original, the inverse switch is also emulated on the Ur-AC1 and the AC1-ACC.

1.9. Graphics Key (F2)

With the graphics key (F2), it is possible to enter graphics characters via the keyboard. However, this must also be supported accordingly by the respective application program. The Graphics/Sound BASIC included in JKCEMU supports the graphics key.

1.10. Character Set Switching

Character set switching is only emulated with monitor program 10/88 and with color graphics. Via the system PIO, you can switch between the SCCH character set or the AC1-2010 character set (PIO B3=0) and the AC1-ACC character set (PIO B3=1). The switching also works if you have specified an alternative character set file in the settings. If this file is larger than 2 KByte, switching occurs between the lower and the upper 2 KByte.

1.11. V24 Interface with Printer

The additional PIO (I/O addresses 08-0Bh) with the V24 interface implemented through it and a printer connected to it are emulated. The printer interface is set to the parameters that the integrated SCCH monitor programs assume after a RESET. This way, characters can be output on the emulated printer using the functions of the SCCH monitor programs without having to change the V24 parameters.

To easily try out the printer emulation, in an SCCH monitor program you can use Ctrl-X to additionally route the screen output to the printer. Use Ctrl-Y to switch this off again.

1.12. AC1-2010 ROM Banks

On the AC1-2010, additional ROM can be switched into main memory. By outputting the value 10h, 20h, 40h, or 60h to output port 0Fh, one of four possible ROM banks of the PIO2 card is switched into the address range 2000h to 27FFh. The value 0 switches the ROM bank out. You can specify the content of these ROM banks in the settings by loading an 8 KByte ROM file. If you have not loaded such a ROM file, the first bank contains a floppy disk management program and the second a management program for further ROM banks, which can be switched in starting at address A000h. These further ROM banks are described further below. Back to the four ROM banks on the PIO2 card: the following commands are available in the AC1-2010 monitor program for switching these banks in and out:

1.13. Joystick

If the joystick checkbox is checked in the AC1 settings, a joystick is emulated according to the SCCH circuit. With this circuit, switching between keyboard and joystick is done via the system PIO, port B, bit 1. If an AC1 program reprograms the system PIO and does not take the joystick circuit into account while doing so, keyboard input may no longer be possible under certain circumstances. In that case, you must switch off the joystick emulation.

1.14. Tape and Tone Output

You can make the tone signals output at the emulated cassette recorder connection (PIO 1, port B, bit 6) audible, or record them and then save them to a file, in the Audio/Tape window on the Tape Output tab. The Loudspeaker tab is responsible for the tone signals output via bit 0 (loudspeaker connection). A further tab appears if you have activated the emulation of the K1520 sound card.

1.14.1. Tone Output via CTC Channel 0

Optionally, tone output via CTC channel 0 is also emulated. Analogous to the LLC2, PIO 1, port B, bit 0 locks (low level) or unlocks (high level) a flip-flop. If this flip-flop is unlocked, every pulse output on CTC channel 0 causes a change in phase and thus half a tone cycle at the loudspeaker connection.

3. BASIC

3.1. Saving, Loading, and Opening BASIC Programs

JKCEMU offers special support for saving and loading BASIC programs as well as for opening BASIC programs residing in main memory in the text editor. You will find the corresponding functions in the File menu.

The following BASIC interpreters are supported:
  • Mini-BASIC version 2.1
  • AC1-8K-BASIC version 1.1
  • AC1-12K-BASIC version 2.1 (High Precision Extended Version)
  • AC1-BASIC6
  • BACOBAS version 2 (BASIC only, not BASICODE)
  • BACOBAS version 3 (BASIC only, not BASICODE)
  • SCCH-BASIC version 3.2 (Graphics/Sound BASIC)

When saving BASIC programs, a window appears for selecting the file format. Please save Mini-BASIC programs as Headersave files (*.z80) with file type b, and the other BASIC programs as BASIC/RBASIC program files, or alternatively also in Headersave format with file type B.

If you save a BASIC program in a different file format, JKCEMU will no longer recognize, when later loading the file, that it is a BASIC program, and will not adjust the system cells of the BASIC interpreter accordingly. The loaded program cannot then be used.

3.2. Graphics/Sound BASIC

The Graphics/Sound BASIC interpreter version 3.2 is available in SCCH mode and resides in a background ROM in the address range 4000-5FFF. By default, this address range contains RAM. Via bit 1 of I/O port 14h, the ROM can be brought into the foreground, making the BASIC interpreter visible in this address range.

With the SCCH monitor programs integrated in the emulator, you can call up BASIC directly with the command b (cold start). This also brings the BASIC ROM into the foreground. You perform a warm start of the interpreter with the command r.

4. Miscellaneous

4.1. Pasting Text from the Clipboard

Pasting text from the clipboard is usually done by simulating, for each character to be pasted, the pressing of the corresponding key or key combination. This principle is quite slow. For the AC1, there is an option in the settings called Paste text by intercepting the system call. With this option, the emulator listens at address 1802h, the entry point for the system function for reading a character from the keyboard. When this system function is called, JKCEMU checks whether a character should be pasted. If so, it writes the next character to be pasted into the corresponding processor register and simulates a RETURN instruction. If the operating system or the application program does not query the keyboard via this entry point, pasting text will not work, and you will have to switch the option off. You must also switch off the option when using a different operating system (e.g. a CP/M-compatible one).
