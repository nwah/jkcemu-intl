HC900 and KC85/2...5

The computers HC900, KC85/2, KC85/3 and KC85/4 were manufactured at VEB Mikroelektronik Mühlhausen. The KC85/2 is actually just a renamed HC900. However, since the operating system was further developed over time, the devices produced as KC85/2 usually contained a newer operating system version, namely CAOS 2.2 instead of HC900-CAOS. Furthermore, the circuit boards of the KC85/3 were already used for manufacturing the last KC85/2 units. This resulted in a functional difference, undocumented anywhere at the time, in how the two ROM chips were switched in and out. For these reasons, the HC900 and KC85/2 are emulated as separate systems, with the KC85/2 emulation imitating the undocumented behavior of the devices produced last.

The KC85/3 is a KC85/2 extended with additional ROM. Besides the new operating system version CAOS 3.1, the BASIC interpreter contained in the ROM is the main distinguishing feature.

A genuine hardware advancement is the KC85/4. RAM and ROM were enlarged and the video hardware was reworked. Combined with the again-new operating system version CAOS 4.x, the latter led to a significant increase in graphics performance.

The KC85/5, on the other hand, never officially existed. The circuit board of the KC85/4 is already designed for memory chips with a larger capacity. A KC85/5 is therefore understood to be a KC85/4 with RAM expanded to 320 KByte (256 + 64) and 48 KByte ROM, as well as a new operating system version that can manage this additional memory.

1. Emulated Hardware

The base units are emulated, as well as, optionally, the floppy disk extensions D004 and D008 including the hard disk extension GIDE, and some modules.

The emulated memory amounts to:
  • HC900, KC85/2:
    • 4 KByte ROM
    • 32 KByte RAM including video RAM
  • KC85/3:
    • 16 KByte ROM
    • 32 KByte RAM including video RAM
  • KC85/4:
    • 20 KByte ROM
    • 128 KByte RAM including video RAM
  • KC85/5:
    • 48 KByte ROM
    • 320 KByte RAM including video RAM
For the KC85/2, the real behavior of the devices produced last regarding the switching in/out of the two ROM chips is emulated:
  • I/O address 88h bit 0 switches ROM F000h-F7FFh.
  • I/O address 88h bit 7 switches ROM E000h-E7FFh.

For the KC85/4, the CAOS ROM C000h-CFFFh, which is normally only 4 KByte in size, can also be emulated with 8 KByte (C000h-DFFFh) by loading a ROM file larger than 4 Kbyte in the settings.

1.1.1. Faster Keyboard Input by Writing Directly into the Keyboard Buffer

The original keyboard control is relatively sluggish due to the special hardware and the interrupt-driven key code decoding. JKCEMU emulates the original keyboard control completely, which is why it also feels rather sluggish in the emulation. Enabling the option Faster keyboard input by writing directly into the keyboard buffer bypasses the emulation of the keyboard control, and the characters entered are written directly into the keyboard buffer, taking into account the key code mapping entered in the CAOS or MicroDOS/ML-DOS keyboard table. This makes the keyboard feel noticeably smoother.

Caution! Enabling the option, however, also means that the emulator no longer reproduces the original behavior exactly. This can possibly cause problems with some programs. So if you are using a program that has problems with keyboard input, you must disable the option.

1.2.2. M006

Module M006 is only available for the HC900 and the KC85/2 and contains the BASIC interpreter as well as the operating system HC901-CAOS. This operating system is a precursor version of CAOS 3.1, which was later used in the KC85/3. Once the KC85/3 had appeared and replaced the KC85/2, module M006 was also offered with CAOS 3.1. Such a newer M006 module effectively turns an HC900 or KC85/2 into a KC85/3, since the ROM content is exactly the same and so is the rest of the hardware. The only difference from a real KC85/3 is then that the ROM from the module is used, so you must not enable the ROMs in the base unit.

Since the newer M006 variant with CAOS 3.1, which is considerably rarer than the one with HC901-CAOS, is effectively equivalent to a KC85/3, and JKCEMU emulates the KC85/3 anyway, only the more common, older M006 variant is included in the emulator. However, if you still want to emulate an HC900 or KC85/2 with an M006 module with CAOS 3.1, you can do so as follows:
  1. Start the KC85/3 emulation in JKCEMU.
    Make sure that no alternative ROM contents have been specified in the settings!
  2. Using the menu File → Save..., save the address range C000 to FFFF as a memory image file without header (*.bin).
  3. Now open the settings and select HC900 or KC85/2.
  4. Add the ROM module M028 and select structure byte FC as well as the file you just saved. The M028 now corresponds exactly to an M006 module with CAOS 3.1.
  5. Click Apply

1.2.3. M052

Module M052 provides USB and network support. You can specify the module several times. In that case, you see one tab in the USB window for each M052, i.e., each module has its own directory for the emulated USB stick. However, the network support is only contained in the first module, i.e., from the second M052 onward only USB is emulated. This corresponds to the partial fitting of an M052 module as a pure USB module, which is also possible in the original.

For both emulated M052 versions (with and without network), you can load different external ROM files in the settings.

1.2.4. M066

Module M066 provides a sound generator based on the AY-3-8910 chip. The module has the following properties:

Name:M066
Structure byte:DCh
I/O addresses:
Write 38h:select sound register
Read 38h:read sound register
Write 39h:write sound register

If you have added a module M066 in the settings, an additional tab is shown in the Audio/Tape window, where you can control the sound output of the M066.

If you have added several M066 modules, only the first one can produce sound. This is also the case in the original, since the module cannot be switched off, and so the first M066 module always shadows any further M066 modules.

1.2.5. Modules in the D004/D008

If you have enabled D004 or D008 emulation and want to emulate modules in the D004 or D008 (slots F0 and F4), after adding the modules in the settings you must select the last or second-to-last module and then click the button Change and then the menu item Plug into D004/D008. With the menu item Plug into D001/D002, you can undo this again.

1.3. Printer

A printer is also emulated with the modules M003 and M021. With the V.24 module M003, all bytes output via SIO channel A are appended to the active print job (see Printing and Print Jobs). With the M021 module, the printer is connected to a Centronics interface. All bytes output via it are likewise appended to the active print job.

The Centronics interface of the M021 module is wired as follows:

M021 Centronics interface
Port A (I/O address 90h): Bit 6: Busy (active-high)
Bit 7: Strobe (active-low)
Port B (I/O address 91h): Data

To print, you must establish a data connection from the operating system to the M003 or M021 module. A corresponding driver takes care of that. CAOS 4.2 (KC85/4) contains a driver named V24OUT for the module M003. If you start this driver, the first M003 module is searched for and the channel for print output is opened to it.

From CAOS 4.5 (KC85/5) onward, there is the driver LSTDEV, which supports both M003 and M021. Calling LSTDEV without a parameter searches for the first M003 module and hooks it in. For the M021 module, you must enter

  LSTDEV 0

1.4. Sound Generators and Cassette Recorder Connection

You can listen to the audio signals output at the emulated cassette recorder connection, or record them and then save them to a file, in the Audio/Tape window, on the Tape Output tab. The Sound Generators in the Base Unit tab is responsible for the output of the two sound generators. There you can also switch between mono and stereo. In mono, you hear the mixed signal from both sound generators that is output at the video/TV connector in the original, which is also subject to the volume control. In stereo, you hear the signal that is output in the original at pins 1 and 4 of the TAPE socket, i.e., one sound generator on each channel, though in this case the volume is not controlled.

With the module M066, there is a further option for producing sound.

1.5. LEDs

You can see the state of the LEDs in the secondary display unit (menu item Extras → Secondary Display Unit...). This display shows the view of the base unit D001 as well as, if needed, the devices D002 and D004 or D008, including the LEDs.

For the KC85/4 and KC85/5, an LED for RAM 8 is also shown in the base unit. This LED does not exist on the original, but some KC85 users built such an LED into their base unit. For this reason, it is also emulated.

1.6. Floppy Disk Extensions D004 and D008

The floppy disk extension D004 is an add-on device that contains an 8 KByte ROM module (addressable via module slot FC) and its own processor system with a connection for floppy disk drives. The hard disk extension GIDE is also optionally available.

The D008 is a fully compatible further development of the D004 that by default runs at twice the clock frequency and additionally offers a 2 MByte RAM floppy. The GIDE is an integral part of the D008, i.e., it is always included and therefore cannot be switched off. Furthermore, the ROM module is four times as large and is addressed via bank switching. The bank is selected with bits 6 and 7 of the control byte.

The additional D008 functions are controlled via the following I/O addresses:

I/O addressMeaning
10h
Bit 0: Status of the RAM floppy (0: hidden, 1: shown)
Bit1 1...7: Number of the RAM floppy bank shown in the address range 8000h to BFFFh
11h Access to the DMA chip (not emulated, see further below)
12h Clock frequency of the D008 (0: 8 MHz, 1: 4 MHz),
The port is also readable, i.e., the current clock frequency can be determined by the program.


Caution! In the original, the D008 can optionally be fitted with a DMA chip. However, this is not emulated. Nevertheless, the LED for access to the DMA chip is emulated (visible in the secondary display unit). So if this LED lights up, an attempt is being made to access the DMA chip, which, however, will not work in the emulation.

Some of the tools integrated in JKCEMU can also be used with the D004/D008's own processor system. When you call up the debugger, disassembler, and memory editor, you are asked whether you want to access the main processor system (the one in the base unit) or the D004 or D008 processor system. It is also possible to open a tool twice, once for the main processor system and once for the D004 or D008 system.

Caution! The D004 or D008 processor system can be controlled from the main processor system. For example, it can also be reset (RESET) or completely deactivated (permanent RESET). If you have opened the debugger for the D004/D008 processor system and halted program execution there (e.g. at a breakpoint), it can still happen that the main processor system resets or even deactivates the D004 or D008. To prevent this, you should possibly also halt the main processor system, e.g. in the main window with the menu item File → Pause.

1.7. 512 KByte Flash-ROM

For the KC85/5, an optional 512 KByte Flash-ROM is emulated. For this, in the settings for the KC85/5, you must specify a ROM file with the content of this Flash-ROM. If no such ROM file is specified, no Flash-ROM is emulated either.

The Flash-ROM offers the option of managing eight different CAOS ROM sets and switching between them. The CAOS ROM sets are arranged consecutively in the Flash-ROM and each has the following structure:
  • 8 KByte CAOS ROM C
  • 8 KByte CAOS ROM E
  • 8 KByte alternative CAOS ROM C
  • 8 KByte alternative CAOS ROM E
  • 8 KByte BASIC/USER ROM level 0
  • 8 KByte BASIC/USER ROM level 1
  • 8 KByte BASIC/USER ROM level 2
  • 8 KByte BASIC/USER ROM level 3

I/O address 86h is used to control the Flash-ROM. A high level at bit 4 activates the two alternative CAOS ROMs. Switching between the CAOS ROM sets as a whole is done with a counter that advances by one on every low-to-high edge at bit 3. This counter is reset by a low-to-high edge at bit 2. Advancing further via bit 3 is only possible once bit 2 is at a low level again.

Programming the Flash-ROM content by software is not possible in the emulation.

3. Included Disk Images

  • CAOS system disk
  • MicroDOS system disk
To use the disk images, the emulation of the floppy disk extension D004 or D008 must be enabled and the corresponding disk must be inserted into the first emulated floppy disk drive.

3.1. CAOS System Disk

The CAOS system disk contains the programs needed to use floppy disks under the operating system CAOS. With

  JUMP FC

the software located on the disk is activated. The CAOS menu now contains the new entry FLOAD, with which system programs can be loaded from floppy disk. One of these system programs is BASEX. It establishes the floppy disk connection for the BASIC interpreter. For saving system programs to floppy disk, there is the program FSAVE.

3.2. MicroDOS System Disk

You start MicroDOS with

  JUMP FC

Drive A: is a RAM floppy, drive B: the first floppy disk drive. The directory listing is displayed with the command D, and not with DIR as is otherwise usual with CP/M-compatible operating systems.

Caution! The disk also contains the empty files G.COM and GO.COM. These are used to start a CP/M-compatible program that is already located in working memory. If G or GO is called without a program being present in working memory, this leads to a crash.

4. Miscellaneous

4.1. Loading Files

By default, the CAOS operating system maps the video memory (IRM) into the address space, thereby covering a RAM area starting at address 8000h (for HC900 and KC85/2..3, this is only the case if a RAM module is mapped in there). However, so that BASIC programs larger than 32 KByte can also be loaded, KC-BASIC files, or files that usually contain a KC-BASIC program, are not loaded into the IRM starting at address 8000h, but into the RAM located behind it. All other files, on the other hand, are loaded into whichever memory is currently mapped in, possibly including the IRM. This way, the loading function of the emulator behaves exactly like the CLOAD command of the BASIC interpreter (in the case of a KC-BASIC file) or like the LOAD command in CAOS (in the case of any other file).

4.1.1. Loading COM Files

COM files contain CP/M-compatible programs. If a CP/M-compatible operating system is used on a KC85/2..5, it usually runs in the floppy disk extension D004 or D008, which is a self-contained computer system. For this reason, JKCEMU loads COM files into the D004 or D008, provided it is emulated. If D004 or D008 emulation is not enabled, then COM files, like all other file types, are loaded into the computer system of the base unit.

4.2. Saving and Loading BASIC Programs

JKCEMU offers special support for saving and loading BASIC programs. If a system with a BASIC interpreter contained in ROM is emulated, i.e., an HC900 or KC85/2 with the BASIC module M006 enabled, or a KC85/3...5, then JKCEMU looks for the BASIC program in the address range of the ROM BASIC interpreter (starting at address 0401h). For an HC900 or KC85/2 without a BASIC module, on the other hand, the BASIC program that lies in the address range of the RAM BASIC interpreter (starting at address 2C01h) is saved.

4.3. Pasting Text from the Clipboard

Pasting text from the clipboard usually works by simulating, for each character to be pasted, the pressing of the corresponding key or key combination. This principle is quite slow. For HC900 and KC85/2..5, there is the option Paste text directly into the keyboard buffer in the Settings. With this option, the characters to be pasted are written directly into the keyboard buffer. This is considerably faster, since the pressing of the corresponding keys does not need to be simulated. However, this also bypasses the CAOS-internal key code mapping. On the other hand, it also makes it possible to paste characters that cannot be entered with the original keyboard.

Should pasting characters not be possible due to special circumstances or because a different operating system is used instead of CAOS, you must disable the option.

If you have enabled the option Faster keyboard input by writing directly into the keyboard buffer, the option for pasting text becomes moot and is therefore no longer selectable, since in that case keyboard input is written directly into the keyboard buffer anyway.

4.4. Timing Behavior of the Screen Control

The vertical sync pulse and the doubled horizontal sync pulse are present at the inputs of the counter/timer circuit (CTC). This makes it possible to write software that runs in sync with the output of the individual pixel rows on the screen. Some programmers make use of this possibility to create special effects (e.g. color scrolling). For such effects to also be visible in the emulator, the visualization must be emulated in sync with the timing regime at the CTC inputs. And that is exactly what the option Emulate timing behavior of the screen control does.

Time-synchronous emulation of the screen control is very computationally intensive. In addition, there are only a few programs that make use of this possibility. For this reason, the time-synchronous emulation between screen output and CTC can be switched on and off via an option.

If the option is enabled, the screen output is also updated synchronously, i.e., the update cycle specified in the settings does not apply.

4.5. Apparent D004/D008 Memory Error

The newer D004/D008 ROM versions contain a memory test. You can start it with JUMP FC FF. In doing so, it can happen that the memory test reports an error in JKCEMU. The cause is not a faulty memory cell, but a timeout that can occur due to the way the emulation works.

In JKCEMU, the two microprocessor systems (base unit and D004/D008) are emulated in separate threads. Since the emulator has no influence on when the operating system lets which thread run, the emulation of the two microprocessors can drift apart in time considerably more than with a real KC85/D004 or KC85/D008 combination. The error message appears because the base unit passes the address of the memory cell to be tested to the D004 or D008. The memory cell is then tested in the D004 or D008 and the result is reported back to the base unit. The base unit waits only a certain amount of time for the response. If this time has elapsed, the memory cell is considered faulty and an error is issued accordingly. If the D004 or D008 thread happens to be delayed in time, so that the memory test in the D004 or D008 may not even have started yet, the response will also arrive too late and thus lead to an error message.

4.6. AutoLoad and AutoInput

On the computers HC900 and KC85/2..5, RESET causes a warm start, in which the system is not completely reinitialized. In such a case, AutoLoad and AutoInput can cause interference. For this reason, AutoLoad and AutoInput are only executed on a cold start (emulated power-on).
