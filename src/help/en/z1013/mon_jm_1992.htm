Description of the Monitor Program "Z1013-OS J.Mueller 1990-1992"

1. General

The monitor program was developed with the goal of replacing the original monitor 2.02 with a more convenient version. The hardware requirements were meant to stay the same (2 KByte ROM, membrane flat keyboard).

2. Features

The monitor program was primarily meant to include the ability to save and load files in the new Headersave cassette recording format. These new functions can be called via the commands L and S, as well as from programs via the jump table. Functions for loading and saving in the old cassette recording format are also still available (commands G and P as well as system functions 8 and 9).

As a further improvement, keyboard polling was made more convenient by implementing autorepeat in system function 4 (INKEY).

Because of the new functions, however, some other functionality that is needed less often (comparing memory areas, setting a breakpoint, single-step mode, register display) had to be dropped.

One disadvantage of the new monitor program is that the system functions reside at different addresses and can therefore only be called via RST 20. This disadvantage is, however, no longer as serious, since the A.2 monitor also has different entry addresses, which is why most Z1013 programs have been adapted accordingly to use only RST 20 for system calls.

3. Initialization

At the start, as with the original, the Z1013 system cells are initialized. In addition, some functions of the jump table are initialized (Headersave, keyboard polling). This requires the range F800h to FFFFh to be RAM. After that, it is checked whether a synchronization tone is currently present at the cassette input. If so, the load routine (command L) is called. After that, the input prompt appears and you are in the command loop.

4. Commands

Compared to the original, the following commands are no longer available: B, C, E, F, N, R

The following commands are new or have a changed or completely new meaning: D, G, L, M, P, S

Only the commands that differ from the original monitor 2.02 are described below:

D <aadr>

Starting at the specified address, the memory contents are output block by block as a HEX-ASCII dump. Pressing ENTER shows the next block. Any other key ends the command.

G <aadr> <eadr>

This command corresponds to the old L command and reads a file in the old non-Headersave format from cassette.

L [<aadr>]

This command loads a file in the Headersave format from the cassette. A load address can be specified, which is then used instead of the one contained in the file.

The command initially only lists the Headersave files that the cassette plays back. Each time a header block has been read, it is displayed. To load the file currently displayed, you must press ENTER.

If the desired file cannot be found, you can abort the command with S4-K/CTRL-C.

M <aadr>

The M command is used to change memory areas and corresponds to the original. However, it was made more convenient, in that ASCII characters can be entered in addition to hexadecimal numbers. If an entry begins with a quote character, the next character is taken as an ASCII character.

P <aadr> <eadr>

This command corresponds to the old S command and saves the specified address range in the old non-Headersave format to cassette.

S <aadr> <eadr> <sadr>

This command saves the specified address range in the Headersave format to cassette. For this, you are asked for the type and the name of the file.
