Z9001, KC85/1 and KC87

The Z9001, KC85/1, and KC87 computers were manufactured at VEB Robotron-Meßelektronik Dresden. The KC85/1 is actually just a renamed Z9001. Over time, however, the operating system was debugged, so that the first units shipped as Z9001 contained operating system version 1.1, and only later was version 1.2 introduced. Since the renaming to KC85/1 also took place a few months after the start of production, the following rough mapping applies: Z9001 → operating system version 1.1 and KC85/1 → operating system version 1.2. Although this mapping does not entirely correspond to reality (the version jump has nothing to do with the renaming; the two events just happened to be relatively close in time), JKCEMU emulates both devices as separate systems with different operating system versions.

The Z9001 operating system is also included in the KC87, as version 1.3. This is why the KC87 also identifies itself as a Z9001.

1.2. Printer

In the settings, you can enable one of two ways to emulate a printer: emulation of a V24 printer module, or interception of the BOS calls for printer output.

1.2.1. Emulation of a V24 Printer Module

If you have enabled this option, a CTC and an SIO are additionally emulated, and the data output on channel A of the SIO is appended to the active print job (see printing and print jobs). For printing to also work from within application programs, you still need to load a driver that establishes the data connection between the operating system and the printer module. The printer module also contains a ROM, in the address range B800h-BFFFh, with the fairly universal drivers V24A1, V24A2, and V24A3. However, this ROM must be switched off if a RAM module is active in the same address range. For this reason, JKCEMU only emulates this ROM if the emulated RAM size is at most 32 KByte.

1.2.2. Intercepting BOS Calls for Printer Output

With this option, you can also print without a driver, because JKCEMU simply intercepts the corresponding operating system calls. However, in that case you also cannot take advantage of a driver, such as special formatting of the print data.

1.3. Full Graphics

The Z9001 and its successors have no full graphics on board, only block graphics. However, full graphics expansions exist.

1.3.1. Robotron Full Graphics Expansion

The full graphics expansion developed by Robotron was not sold as an industrially manufactured module, but was only available as a construction guide for hobbyist replication. The full graphics expansion comes with a separate video RAM for 320x192 pixels and works with only two colors, which can be selected in software from the color module's color palette. The color module is therefore mandatory. For this reason, JKCEMU emulates the Robotron full graphics expansion only in combination with the color module.

1.3.2. KRT Full Graphics Expansion

Issue 11 of Kleinstrechnertips presented a relatively simple full graphics expansion for the Z1013. Volker Pohlers and Ulrich Zander adapted this circuit to the Z9001 with small modifications (different I/O addresses, non-inverting pixel data) and, in reference to Kleinstrechnertips, gave it the name KRT full graphics expansion.

In the address range of the video RAM, there are also 8 parallel memory banks. Each of these banks contains the pixel data for a particular pixel row within a character position (bank 0: topmost pixel row within a character row, bank 7: bottommost pixel row within a character row). A byte in these memory banks represents 8 pixels side by side (most significant bit on the left).

Control is via output port B8h. A set bit 3 activates full graphics, i.e. the original video RAM is switched out of the address space and the memory bank specified by bits 0 to 2 is switched in instead.

1.4. Programmable Character Generator

The programmable character generator is an additional 1 KByte RAM that can be activated and deactivated in software for the graphical display of the upper 128 characters (starting at code 80h).

A write access to address EBFCh maps the character generator into working memory in the range E800h-EBFFh. This allows it to be programmed and read back.

A write access to address EBFEh activates the programmable character generator, i.e. the pixel data for the upper 128 characters is then read from it. For characters below 80h, the standard character generator continues to be used.

A write access to address EBFFh restores the default state, i.e. the programmable character generator is neither mapped into the address space nor active for display.

1.5. 80-Character Mode with Character Set Switching

Issue 6/1990 of the magazine Mikroprozessortechnik presented a circuit that enables an 80-character mode that can be switched on and off in software. Control uses I/O addresses that, however, are also occupied by the floppy disk and printer modules. Based on this publication, Ulrich Zander developed a new circuit that additionally offers character set switching, but which also uses different I/O addresses and therefore no longer conflicts with other modules.

For the 80-character mode, the video memory and, if applicable, the color attribute memory as well, is duplicated. The additional memory this creates lies at the same addresses as the original and can be switched in and out via I/O instructions.

JKCEMU optionally emulates the 80-character mode, with control possible using either the I/O addresses from the publication or those according to Ulrich Zander. If the floppy disk and/or printer module is emulated, the conflicting I/O addresses have no effect on the 80-character mode.

If the 40/80-character switching is emulated, the switchable character generator according to Ulrich Zander's circuit is also available; besides the original, it also contains a character set with German umlauts. Each write access to I/O address 0BBh switches between these two character sets. Character set switching also works with an externally loaded character set file, provided it is larger than 2 KByte. In that case, switching takes place between the lower and the upper 2 KByte.

The Z9001 CP/A system disk included in JKCEMU also contains drivers for the 80-character mode. Since these drivers address the hardware via the I/O addresses according to Ulrich Zander, the file names start with UZ80....

1.5.1. Size and Aspect Ratio of the Screen Output

When switching between 40- and 80-character mode, the size of the emulator window and the aspect ratio change. On the original, in contrast, the size of the screen output area always stays the same; instead, the characters are displayed narrower. With the option Same window size in both screen modes, you can adapt the behavior to match the original. In that case, however, the emulator window is also always as large as needed to display the 80-character mode.

1.6. Floppy Disk Module

There is a floppy disk module from Robotron and one from the Zentralinstitut für Kernforschung of the GDR in Rossendorf. The two variants differ only in the I/O addresses and in how the TC pulse is triggered. JKCEMU emulates both variants.

Caution! The emulator includes an image of a CP/A system disk (a CP/M variant for the Z9001 by Dr. Frank Schwarzenberg). To boot this CP/M system, the 64 KByte RAM module must also be enabled, together with either the boot module or the Mega-ROM module.

1.7. Boot Module

The boot module is a special ROM module that can be switched off in software with a write access to the address range F800h-FBFFh. After a RESET, it identifies itself with CP/M-System and, by entering the command BOOT, allows booting from disk. This naturally also requires the floppy disk module to be enabled.

In the emulation, the boot module cannot be combined with any other ROM module.

Caution! The ROM of the boot module lies in the same address range as that of the KC87's BASIC interpreter. For this reason, the KC87 BASIC ROM is disabled by default. It can be enabled in software, but there is no user command for doing so. For this reason, when the boot module is emulated, BASIC on the KC87 is practically unusable.

1.8. Mega-ROM Module

The Mega-ROM module offers 2.5 MByte of memory, divided into 256 individual 10 KByte segments. The currently active segment is mapped into the address range C000h-E7FFh. Switching the active segment is done via an output instruction to I/O address FFh. A write access to the address range F800h-FBFFh switches the Mega-ROM module off, and a write access to FC00h-FFFFh switches it on.

The content included in JKCEMU for this module by no means fills the available memory, but nevertheless contains quite a number of programs, including a management program. This starts automatically after a RESET and is operated with commands. Especially interesting is the command MENU, which starts a graphical interface through which you can invoke the other programs contained in the Mega-ROM module.

The command BOOT tries to boot from disk, i.e. the Mega-ROM module can also replace the boot module.

In the emulation, the Mega-ROM module cannot be combined with any other ROM module.

1.9. 10/16 KByte ROM Module

A ROM module is emulated that can appear, as selected, in the address range 4000h-7FFFh, 8000h-BFFFh (16 KByte each), or C000-E7FF (10 KByte). You must set the content of the ROM module in the settings by specifying a ROM file.

Only one ROM module can be emulated at a time, i.e. the ROM module cannot be combined with any other, including the boot module or the Mega-ROM module.

1.10. 32 KByte ROM Module

The 32 KByte ROM module resides in the address range 4000h to BFFFh. You set its content by specifying a ROM file. For example, if you specify the content of the KCPASCAL module as the file, the KCPASCAL module is emulated.

The 32 KByte ROM module cannot be combined with any other ROM or RAM module, including the boot module or the Mega-ROM module.

1.11. 64 KByte RAM Module

This module provides additional RAM in the range from 4000h to E7FFh, as well as a background RAM in the range 4000h-7FFFh. Since the range from E800h onward is reserved for the color attribute and video memory as well as the operating system ROM and therefore cannot be occupied by the RAM module, only 58 KByte of the module can be used. In total, 74 KByte of RAM are thus available.

An I/O instruction to port 5 switches in the background RAM starting at 4000h. An I/O instruction to port 4 switches it off again. Port 7 is used to switch in the RAM in the range from C000h onward. On the KC87, this also switches out the BASIC ROM. An I/O instruction to port 6 reverses this.

1.12. KCNet-Compatible Network Card

The original network card contains a socket for an EEPROM with which the boot module can be replaced. If you want to emulate this EEPROM, enable the boot module and, if necessary, load a corresponding ROM image file there. Please also read the notes on network emulation.

1.13. Real-Time Clock Module

A real-time clock RTC-62421 or RTC-72421 is emulated at I/O addresses 60h to 6Fh. The clock can only be read, not set.

1.14. Cassette and Sound Output

You can make the sound signals output at the emulated cassette recorder connector (CTC channel 1 output) audible or record them in the Audio/Tape window, on the Tape Output tab, and then save them to a file. In the original, the same signal can also be heard through a speaker, and can additionally be switched on and off via I/O address 88h, bit 7. The Speaker tab is responsible for this speaker signal. A further tab appears if you have enabled emulation of the K1520 sound card.

1.15. Interrupt Handling with Modules

On the original hardware, modules plugged into the module rack (e.g. the K1520 sound card) have problems with interrupt handling when the interrupt service routine runs in the RAM of the main board (address range 0000h to 3FFFh). Specifically, a data bus driver blocks the module rack whenever the address is below 4000h. If a RETI instruction is then executed in the address range below 4000h, the modules cannot recognize this instruction and therefore cannot reset their interrupt status. JKCEMU also emulates this limitation.

3. Included Disk Images

JKCEMU includes the following disk image for the KC85/1, KC87, and Z9001 emulation:
  • Z9001 CP/A system disk

To use the disk image, you must set at least the following configuration:
  • KC85/1, KC87, or Z9001
  • 64K RAM module
  • Boot ROM or Mega-ROM module
  • Floppy disk module

On startup, the boot ROM module identifies itself with the message CP/M-System, and the Mega-ROM module with its own interface. Regardless of which of the two modules you use, once the CP/A system disk is inserted and the prompt is visible, enter the command BOOT to start CP/A.

The drive assignment is simple:
  A: first drive
  B: second drive

The disk itself is thus accessible under drive A:.

4. Miscellaneous

4.1. Saving and Loading BASIC Programs

JKCEMU offers special support for saving and loading BASIC programs. When a Z9001 or KC85/1 is emulated, i.e. when the ROM contains no BASIC interpreter, JKCEMU looks for the BASIC program in the address range of the RAM BASIC interpreter (starting at address 2C01h). On the KC87, on the other hand, the BASIC program that is saved is the one located in the address range of the ROM BASIC interpreter (starting at address 0401h).

4.2. Pasting Text

Pasting text from the clipboard is usually done by simulating, for each character to be pasted, the pressing of the corresponding key or key combination. This approach is fairly slow. For the KC85/1, KC87, and Z9001, the settings offer the option Paste text directly into the keyboard buffer. With this option, the characters to be pasted are written directly into the keyboard buffer. This is considerably faster, since it avoids having to simulate the pressing of the corresponding keys.

However, if you use an operating system other than the one built into JKCEMU, this option may no longer work, since keyboard polling may be implemented differently there. In that case, you must turn the option off.
