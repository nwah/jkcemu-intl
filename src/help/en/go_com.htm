G.COM and GO.COM

The files G.COM and GO.COM are used to start a CP/M-compatible program that is already located in memory. GO.COM is included on all disk images for CP/M-compatible operating systems contained in JKCEMU. On the MicroDOS disk images, G.COM is included as well, because of the short commands customary there.

G.COM and GO.COM are empty files (0 bytes in size) and work as follows: CP/M-compatible operating systems have internal and external commands. Internal commands are contained in the command processor (CCP), external commands are loaded from floppy disk (or also from RAM floppy or hard disk) and started. When the user has entered a command line and the entered command is not found in the CCP, an attempt is made to load into memory the file whose name matches the command with the extension .COM appended. CP/M-compatible program files are loaded into memory starting at address 100h and are also started at that address. Since the file GO.COM is empty, calling the command GO loads nothing into memory, but the program is started at address 100h anyway. This starts the program that is already located in memory. The same applies to the file G.COM, which is only included on the MicroDOS disk images.

Caution! If there is no program in memory, calling G or GO results in a crash.

In JKCEMU, the file GO.COM (and, for MicroDOS, also G.COM) is therefore included on the disk images so that CP/M-compatible programs can conveniently be loaded into memory using the emulator's facilities and then started there, without these programs first having to be available on an emulated floppy disk.

If you have a floppy disk or RAM floppy without GO.COM, you can create this file with the following command line:

SAVE 0 GO.COM

Of course, the storage medium must be writable for this.
