KC compact

The KC compact is the last home computer manufactured in the GDR. It was developed with the goal of achieving extensive compatibility with the CPC computers from Amstrad. Since the KC compact has to do without the ULA (a custom chip from Amstrad), some central things are solved differently in terms of hardware than in the CPC. Nevertheless, the compatibility is very high, at least if you do without the undocumented graphics mode 3.

In terms of software and hardware, the KC compact corresponds most closely to a CPC664 (64 KByte RAM, Locomotive Basic 1.1), but without a built-in floppy disk drive. The floppy disk extension for the KC compact is designed as a separate device and also had to be purchased separately. In addition, instead of the CPC-specific 3'' floppy disks with 40 tracks, the 5.25'' floppy disks with 80 tracks that were common in the GDR were used.

1. Emulated Hardware

The following are emulated:
  • Base unit
  • Printer
  • Two joysticks
  • optional:
    • 15 ROM extension modules of 16K each
    • RAM extension 512K
    • Floppy disk station

If a function or control key is pressed together with the Control or Shift key, this key combination is also reproduced directly on the emulated KC-compact keyboard. For all other keys (letters, digits, special characters), pressing the Control and Shift keys is reproduced so that the same character appears on the emulated KC compact as on the keyboard of the emulator computer. This is necessary because the characters on the emulated KC-compact keyboard can be on a different shift level than on the keyboard of the computer running the emulator.

1.2. Sound Generator

To hear the tones output by the sound generator, you must enable the sound output in the Audio/Tape window, on the Sound Generator tab.

Note: The sound generator is always emulated with the original clock frequency, i.e., if you specify a different clock frequency in the Settings, this only affects the emulation of the microprocessor.

1.3. Floppy Disk Station

The floppy disk station, which was optionally available as an add-on device for the KC compact, is emulated if you specify this in the Settings. The floppy disk station provides two floppy disk drives and an additional 64 KByte of RAM as well as 16 KByte of ROM (of which, however, only 8 KByte is used).

Since the KC compact aimed for extensive compatibility with the CPC computers from Amstrad, some peculiarities of these computers were also adopted for the floppy disk system:
  • A terminal count cannot be triggered by software. Therefore, an end-of-cylinder error is always reported at the end when reading and writing sectors.

  • Internally, drive selection is done only via the DS0 line. DS1 is not evaluated. Therefore, the internal drive numbers 2 and 3 have the same effect as 0 and 1.

1.3.1 ROM in the Floppy Disk Station

The floppy disk station contains a ROM that holds the BASDOS (the CPC computers' AMSDOS extended with an additional floppy disk format). This ROM is integrated into the system as a ROM extension with ROM number 7, without this appearing in the KC-compact settings in the ROM Extensions subwindow. If you want to replace this ROM content with a different one, add a ROM extension with number 7 in the settings (see ROM Extensions). This extension then replaces the ROM in the floppy disk station.

1.3.2 Floppy Disk Formats

With the KC compact, there are two operating modes with different floppy disk formats regarding disk usage. The first operating mode is called BASDOS. This is the floppy disk support for the BASIC contained in the KC compact, i.e., it can be used, for example, to save BASIC programs to floppy disk and load them from there again. In this operating mode, the following floppy disk formats are supported:
  • BASDOS standard format:
    720/711 KByte: 80 tracks, double-sided, one system track, 9 sectors, 512 byte sector size, sector offset 0, 4 KByte block size

  • AMSDOS format without system track:
    180 KByte: 40 tracks; single-sided, no system track, 9 sectors, 512 byte sector size, sector offset C0h, 1 KByte block size

  • AMSDOS format with system tracks:
    180/171 KByte: 40 tracks; single-sided, 2 system tracks, 9 sectors, 512 byte sector size, sector offset 40h, 1 KByte block size

The BASDOS operating mode is entered automatically when the KC compact is switched on or reset (RESET) with the floppy disk station connected.

The second operating mode is the CP/M-compatible MicroDOS. You enter this operating mode with the command |cpm. To do this, the MicroDOS system disk must have been inserted in the first floppy disk drive beforehand.

MicroDOS supports two floppy disk formats:
  • MicroDOS standard format:
    800/780 KByte: 80 tracks, double-sided, 2 system tracks, 5 sectors, 1024 byte sector size, sector offset 0, 2 KByte block size

  • BASDOS standard format:
    720/711 KByte: 80 tracks, double-sided, one system track, 9 sectors, 512 byte sector size, sector offset 0, 4 KByte block size

The MicroDOS system disk included in JKCEMU is configured so that the first floppy disk drive can be addressed both as drive B: and as drive C:, depending on the format of the inserted disk. Drive B: is configured for the MicroDOS standard format and drive C: for the BASDOS standard format.

With the program FORMATCC.COM included on the MicroDOS system disk, you can format floppy disks for MicroDOS and BASDOS. If you want to create a disk image file for BASDOS in the emulator, for example to store KC compact BASIC programs on it, proceed as follows:
  1. Set up KC compact emulation with a floppy disk station
  2. Open the Floppy Disk Station window
  3. Insert the KC compact MicroDOS system disk in it
  4. Start MicroDOS with |cpm
  5. Start formatcc
  6. In the Floppy Disk Station window, create a new disk image file (e.g. menu item Create New CPC Disk File...)
  7. In the emulator window, in the formatting program, select drive B and format number 2 (9*512*80*2) and start formatting
  8. After formatting has finished, trigger RESET in the emulator

1.4. ROM Extensions

The operating system of the KC compact can manage 15 ROM extension modules, each 16 KByte in size. For this, each ROM module is assigned a number from 1 to 15.

When booting, the operating system performs a so-called ROM walk. Starting with number 15, it maps the ROM modules into working memory in turn and tests whether they contain operating system extensions. If so, the extensions found are integrated into the operating system.

In terms of hardware, the KC compact can even distinguish 255 ROM extension modules, but the operating system only manages 15. For this reason, JKCEMU also only emulates a maximum of 15 modules. To add a ROM extension, in the KC-compact settings, in the ROM Extensions subwindow, click the Add button. A dialog opens in which you specify the ROM number and the file with the ROM content. Adding is also possible by dragging a ROM file into the ROM Extensions subwindow via drag&drop and dropping it over the ROM list.

1.5. RAM Extension 512K

The optionally emulated RAM extension functionally corresponds to two 256K RAM extension modules from DK'tronics. This means that all 8 banks in the bank switch register 7F XX CX are populated with RAM.

Caution! If the floppy disk station and the 512K RAM extension are emulated at the same time, the RAM extension covers the RAM in the floppy disk station, i.e., a total of 576 KByte of RAM is available (64 KByte in the base unit and 512 KByte in the RAM extension).

2. Included Disk Images

For KC-compact emulation, JKCEMU includes the following disk image:
  • MicroDOS system disk
You start MicroDOS by entering the command: |cpm
To do this, the emulation of the floppy disk station must be enabled and the MicroDOS system disk must be inserted into the first emulated floppy disk drive.

The MicroDOS on the system disk is configured with three drives:
  • A: RAM floppy
  • B: first floppy disk drive in MicroDOS standard format (see Floppy Disk Formats above)
  • C: first floppy disk drive in BASDOS standard format (see Floppy Disk Formats above)

In MicroDOS, the directory listing is displayed with the command D, and not with DIR as is otherwise usual with CP/M-compatible operating systems.

Caution! The disk also contains the empty files G.COM and GO.COM. These are used to start a CP/M-compatible program that is already located in working memory. If G or GO is called without a program being present in working memory, this leads to a crash.

3. Miscellaneous

3.1. Loading Programs

3.1.1. Loading KC-compact and CPC Programs

Although JKCEMU offers the option of loading files directly into the emulator's working memory, the KC compact operating system does not recognize programs loaded this way. For this reason, programs must always be loaded with the help of the KC-compact operating system, either via the emulated cassette interface or from an emulated floppy disk.

3.1.2. Loading CP/M Programs

With CP/M-compatible operating systems, programs are loaded from a floppy disk, i.e., in an emulator, from an emulated floppy disk. However, JKCEMU additionally offers the option of loading CP/M program files (*.com) directly into working memory with the help of the emulator functions and starting them with the help of the empty file G.COM or GO.COM, without the CP/M program file in question having to be present on the emulated floppy disk. The prerequisite is that a CP/M-compatible operating system (e.g. MicroDOS) has been started in the KC-compact emulation.

Caution! With MicroDOS, the RAM contained in the floppy disk station is used as working memory. For this reason, JKCEMU loads COM files into this RAM. All other file types (and, if floppy disk emulation is disabled, COM files as well) are loaded into the RAM of the base unit.

3.2. Screen Output

The screen output is always updated synchronously with the emulation of the video controller. This is necessary for the correct display of fast motion sequences (e.g. in game programs). The update cycle specified in the settings therefore does not apply here.

3.2.1. Size and Aspect Ratio

The KC compact offers three screen resolutions. When switching between these (e.g. with the BASIC command mode 2 for the 80-column mode), the size of the emulator window and the aspect ratio also change. On the original, however, the size of the screen output area always stays the same. With the option Same window size in all screen modes, you can adjust the behavior to match that of the original. However, the emulator window is then always as large as needed to display the highest screen resolution.
