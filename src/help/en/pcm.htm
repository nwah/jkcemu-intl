PC/M

The PC/M, also called the Mugler/Mathes-PC or simply Mugler-PC, is a self-build computer with CP/M compatibility that was published in 1988 as a set of construction instructions in a series of articles in the magazine Funkamateur. The original concept used RAM floppies as drives, the contents of which were stored on cassette tape. Support for floppy disk drives was added later.

1. Emulated Hardware

  • 8 KByte ROM, optionally expandable up to 32 KByte
  • 3 RAM banks of 62 KByte each
  • Screen control with the resolutions:
    • 64x16 characters (64x32 characters with interlaced lines)
    • 80x24 characters (only possible with the floppy disk system)
  • Cassette recorder connector
  • Printer connector on system SIO port A
  • NMI generator
  • optional:
    • Floppy disk module

1.1. ROM

The original PC/M has an 8 KByte ROM that contains the base operating system. In the emulator, this ROM can be enlarged in steps of 8 KByte up to 32 KByte by specifying an appropriately sized ROM file in the PC/M settings.

1.2. RAM Banks

RAM banks 1 and 2 of the emulated PC/M are located consecutively in RAM floppy 1 within JKCEMU. This makes sense, since the BIOS contained in the ROM also treats these two banks as a single RAM floppy. This means the RAM floppy can be loaded and saved using the emulator's functions.

1.3. Floppy Disk Module

The floppy disk module is emulated if you have enabled one of the two PC/M expansion levels with a floppy disk system in the settings. However, the first drive does not have the usual internal number 0, but number 1. The reason lies in the PC/M system software, which tries to boot starting from internal drive number 1. So that booting can take place from the first drive shown in the JKCEMU Floppy Disk Station window, the drive numbers are mapped as follows:

1.4. NMI Generator

The NMI generator enables single-step operation and is used by the debugger contained in the base operating system of the RAM floppy system (CTRL-I in the debugger executes a single step).

The NMI generator is activated by an input/output instruction to one of the addresses 98h to 9Bh. A non-maskable interrupt is then triggered after the third instruction following the input/output instruction.

1.5 Extensions

The following extensions are optionally emulated:
  • K1520 sound card
  • USB port (Vinculum VDIP module) at I/O base addresses DCh and FCh

2.1. Base Operating System

On a RESET, the system software is loaded from ROM into RAM, after which the ROM is switched out. The base operating system then reports with the PC/M prompt:

V>

You can now enter commands, each of which must be terminated with Enter. The following commands are possible:

CommandMeaning
0 Set memory bank 0 as the current working memory (default)
1 Set memory bank 1 as the current working memory
2 Set memory bank 2 as the current working memory
B Switch in the operating system ROM
C Start CP/M-compatible system:
  • With the RAM floppy system, CP/V is started. For this, the BDOS must have been loaded beforehand. In the original, it is loaded from cassette tape. For convenience, JKCEMU can also load the BDOS automatically on every RESET, if you set this option in the settings.
  • With the floppy disk system, JKCEMU first tries to start the system from the RAM floppy. If none is found there, it boots from floppy disk. In doing so, the system loaded from the floppy disk is copied into the RAM floppy, so that it can be started directly from there the next time. If you want to force booting from floppy disk after a RESET, the RAM floppy must be empty or previously erased.
D Call debugger (RAM floppy system only)
F X Format drive X
G aaaa Jump to address aaaa,
This can be used to start a program located in working memory.
L Filename.Type [aaaa [bbbb [cccc]]] The file named Filename.Type is loaded from cassette tape into working memory. Optionally, the load address (aaaa), the number of the first block to be loaded (bbbb) and the number of the last block to be loaded (cccc) can be specified. In case of read errors, you can simply rewind and try reading the faulty section again. Loading can be aborted with CTRL-C. Please note that a corresponding audio function must be activated in JKCEMU to load from cassette tape.
R Filename.Type X The file named Filename.Type is loaded from cassette tape into RAM floppy X. Loading can be aborted with CTRL-C.
S Filename.Type aaaa bbbb [cccc] [/F] [dddd] The address range from aaaa to bbbb is saved to cassette tape under the name Filename.Type. Optionally, for executable programs (COM files), a start address (cccc) can be specified. The option /F prevents writing the end-of-file marker, and the file can be continued with the next free frame number (dddd). However, this then leads to larger block gaps. Saving can be aborted with CTRL-C. Please note that a corresponding audio function must be activated in JKCEMU to save to cassette tape.
V Filename.Type aaaa [bbbb [cccc]] The file named Filename.Type on cassette tape is compared with working memory starting at address aaaa. The optional arguments bbbb and cccc have the same meaning as with the L command.
X Filename.Type aaaa [bbbb [cccc]] The file named Filename.Type is loaded from cassette tape into working memory and started at the address specified when it was saved. The arguments have the same meaning as with the L command.
Z aaaa Set the bit rate for the cassette interface,
Possible values are 1200, 2400, 3600 and 4800. The default setting is 3600.
Filename If you specify only a file name without a type, the file is loaded from cassette tape with the type COM and started at the address specified when it was saved.


2.2. RAM Floppy System

If you have enabled the RAM floppy system in the settings, you can start the RAM floppy system from the base operating system with the command C. However, the BDOS must have been loaded beforehand. JKCEMU offers you the option of having the BDOS loaded automatically on every RESET.

The RAM floppy system is compatible with CP/M 2.2. The following resident commands are available:

CommandMeaning
X: Switch to drive X, i.e., X is now the current drive.
DIR Show the directory of the current drive
ERA Filename.Type The file named Filename.Type is deleted. The wildcard characters ? and * are allowed.
REN Newfilename.Type=Filename.Type The file named Filename.Type is renamed to Newfilename.Type. Wildcard characters cannot be used.
TYPE Filename.Type Display the file Filename.Type
SAVE n Filename.Type Starting at address 0100, n blocks of working memory are saved to the current drive in the file Filename.Type. One block is 256 bytes in size.
If you have CP/M programs available as individual files and want to start them in the emulator, first load such a program into working memory at address 0100 and then save it with the command SAVE to the current drive. You can now start the program by calling the corresponding COM file.
USER n Set a user area (n = 0..15),
This is only of limited use with a RAM floppy, though.


2.3. Floppy Disk System

If you have enabled a floppy disk system in the settings, you can boot from floppy disk from the base operating system with the command C. For this, a suitable floppy disk, e.g. the PC/M boot disk supplied with JKCEMU for the corresponding screen resolution, must have been inserted into drive 1 in the JKCEMU Floppy Disk Station window.

3. Included Disk Images

For the PC/M emulation, JKCEMU includes the following disk images:
  • PC/M boot disk for 64x16 characters
  • PC/M boot disk for 80x24 characters
The PC/M boot disks mainly serve for booting and, besides a README file, contain only a few PC/M-specific system programs. The drive assignment on both disk images is:

A:RAM floppy
B:first floppy disk drive, 624 KByte format
C:second floppy disk drive, 624 KByte format
D:third floppy disk drive, 624 KByte format


Caution! Both disks also contain the empty file GO.COM. This is used to start a CP/M-compatible program located in working memory. If GO is called without a program present in working memory, this leads to a crash.

4. Miscellaneous

4.1. Character Set Files

In the settings, you can specify an external character set file which is then used instead of the one built into JKCEMU. Note, however, that the format of this file differs between the 64x16-character and 80x24-character screen resolutions.

With the 64x16-character screen resolution (64x32 characters with interlaced lines), the character set file contains 256 characters of 8x7 pixels each. Eight consecutive bytes represent the 8 pixel rows of a character, with only bits 1 through 7 being evaluated. Bit 7 contains the leftmost pixel.

With the 80x24-character screen resolution, the character set file contains 128 characters of 10x6 pixels each, i.e. only a 7-bit character set is used. The 8th bit is used for cursor control. If it is set, the cursor is drawn as a line in pixel row 8. In the character set file, 16 consecutive bytes make up one character, of which only the first 10 bytes, and of those only bits 2 through 7, are used. Bit 7 contains the leftmost pixel. Unlike the 64x16-character resolution, an unset bit results in a lit pixel.
