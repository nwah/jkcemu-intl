CP/M-kompatible Diskettenabbilddateien entpacken

Diskettenabbilddateien können von JKCEMU entpackt werden, wenn sie dem Diskettenformat von CP/M 2.2 entsprechen. Beim Entpacken werden die einzelnen Dateien, die auf der Diskette bzw. in der Abbilddatei enthalten sind, extrahiert und in das Dateisystem des Emulatorrechners kopiert.

Den Menüpunkt zum Aufruf dieser Funktion finden Sie im Hauptfenster, MenüExtra, Untermenü Werkzeuge. Nach dem Aufruf öffnet sich ein neues Fenster. In diesem wählen Sie im oberen Bereich die zu entpackende Diskettenabbilddatei aus. JKCEMU analysiert die Datei und zeigt im mittleren Bereich an, ob die Blockgröße und das Blocknummernformat (8  oder 16 Bit) erkannt wurden. Wenn nicht, müssen Sie diese beiden Werte selbst korrekt setzen!

Im unterern Bereich wird das Directory der Diskettenabbilddatei angezeigt. Die Abbilddatei kann nur entpackt werden, wenn ein Directory gefunden wurde. Dann können Sie auf die Schaltfläche Entpacken klicken.

Optionen

Im mittleren Bereich können auch diverse Optionen angegeben werden, z.B., ob eventuell vorhandene gelöschte Dateien entpackt werden sollen. Wenn Sie in den Einstellungen ein Profil speichern, werden darin auch die beim letzten Entpacken verwendeten Optionen gespeichert. Beim nächsten Start von JKCEMU mit diesem Profil sind dann im Werkzeugs zum Entpacken von Diskettenabbilddateien die Optionen wieder so gesetzt.

Zeitstempel (DateStamper)

Wenn die zu entpackende Diskettenabbilddatei die Datei !!!TIME&.DAT enthält (siehe DateStamper), werden die Zeitstempel der entpackten Dateien auf die darin enthaltenen Werte gesetzt, vorausgesetzt, die verwendete Java-Laufzeitumgebung sowie das Dateisystem ermöglichen das Setzen der Zeitstempel.

Probleme beim Entpacken

JKCEMU sucht das Directory auf den ersten vier Spuren der ersten Seite im jeweils ersten Sektor. Wenn das Directory sich an einer anderen Stelle befindet, d.h. innerhalb einer Spur, wird es nicht gefunden. In dem Fall handelt es sich entweder um ein Diskettenformat, welches von JKCEMU nicht unterstützt wird oder die Diskettenabbilddatei ist korrupt.

Eine weitere Bedingung für das Entpacken ist, dass die Sektoren ab dem Directory ein gleichmäßiges Sektorlayout haben, d.h. dass auf allen Spuren alle Sektoren die gleichen Nummern und die gleichen Größen haben und dass keine Spuren oder Sektoren fehlen oder Sektoren zu viel sind. Wenn dies nicht der Fall ist, werden nur die Dateien entpackt, deren Daten vor der ersten Unregelmäßigkeit liegen. Die Systemspuren können ein anderes Format haben.

Bei einer einfachen Diskettenabbilddatei sucht JKCEMU das Directory in den ersten Kilobytes der Datei. Es wird nicht geprüft, ob das Directory am Spuranfang beginnt oder ob das Sektorlayout gleichmäßig ist, da eine einfache Abbilddatei keine Sektorinformationen enthält, die geprüft werden könnten. Aufgrund dieser fehlenden Prüfungen ist es eventuell auch möglich, CP/M-kompatible Abbilddateien zu entpacken, die von anderen Quellen als von gewöhnlichen Disketten stammen. Offiziell unterstützt wird dies jedoch nicht!

Wenn man eine Diskettenabbilddatei hat, die sich aufgrund der o.g. Bedingungen nicht entpacken lässt, man jedoch der Meinung ist, die Abbilddatei enthält einen korrekten CP/M-kompatiblen Datenbereich, kann man versuchen, die Datei mit dem Dateikonverter in eine einfache Abbildddatei zu konvertieren und dann zu entpacken. Hintergrund ist, dass bei einer einfachen Diskettenabbilddatei wie oben bereits erläutert weniger geprüft wird. Wenn sich die Abbilddatei nicht konvertieren lässt, weil sie z.B. ein unregelmäßiges Sektorlayout hat, dann kann man bei entsprechend vorhandener Fachkenntnis durch Exportieren der betreffenden Spuren und Sektoren im Diskettenabbilddatei-Inspektor und eventueller Nachbearbeitung im Hex-Editor eine einfache Abbilddatei erstellen und diese dann versuchen zu entpacken. Die Verantwortung, dass eine so erstellte Abbilddatei und die daraus entpackten Dateien korrekt sind, liegt jedoch ausschließlich beim Anwender!
