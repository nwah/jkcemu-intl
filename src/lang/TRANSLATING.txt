JKCEMU - Uebersetzungen / Translations
======================================

This file explains how to translate JKCEMU into your language.
You do NOT need to know Java, and you do not need to write any code.

Diese Datei beschreibt, wie JKCEMU in eine andere Sprache uebersetzt wird.
Java-Kenntnisse sind dafuer nicht erforderlich.


1. What you need
----------------

A plain text editor. The translation files are Java property files:
one line per text, in the form

    key=text

Nothing else is required. Web based translation platforms such as
Weblate and Crowdin support this format directly, should you prefer
one of those.


2. The files in this directory
------------------------------

  jkcemu.properties     The base file, in English. It contains every
                        translatable text of JKCEMU and serves as the
                        fallback for all other languages.

  jkcemu_de.properties  The German texts. German is the language the
                        program is originally written in.

  jkcemu_<code>.properties
                        One file per language, named after the ISO 639-1
                        language code, e.g. jkcemu_fr.properties,
                        jkcemu_cs.properties, jkcemu_pl.properties.

  languages.txt         The list of languages offered in the settings
                        dialog. One line per language, in the form
                        <code>=<name in that language>, e.g.

                            de=Deutsch
                            en=English
                            fr=Francais

  GLOSSARY.txt          Binding terminology. Please read it before you
                        start - it lists the retro-computing terms that
                        are easy to get wrong.

The left hand side of every line is the key. It is what the program
looks up, so it must never be translated or changed. Only the text to
the right of the "=" is yours.

The first part of a key tells you where the text appears, which helps
when a German word could mean several things:

    basic.*                 BASIC compiler
    assembler.*             assembler
    disk.*                  floppy disk tools
    kc85.*                  KC85 specific settings
    debugger.*              debugger
    common.*                used in several places

The second part is the kind of text: action (menu item or button),
menu, label, option, choice, column, section, title, tooltip, msg,
error, filetype or text.


3. Translating an existing language
-----------------------------------

  1. Open the .properties file of your language in your editor.
  2. Translate the text to the right of each "=".
  3. Save the file as UTF-8, and see section 5.6 about umlauts and
     other non-ASCII characters.

A key you leave out is not a problem: JKCEMU then shows the English
text from jkcemu.properties. A partial translation never breaks the
program.


4. Starting a new language
--------------------------

  1. Copy jkcemu.properties to jkcemu_<code>.properties, using the
     ISO 639-1 code of your language, e.g. jkcemu_fr.properties.
  2. Translate it as described in section 3.
  3. Add one line for your language to languages.txt, e.g.

        fr=Francais


5. Rules you have to follow
---------------------------

These are not style preferences - breaking them causes visible bugs.

5.1. Placeholders

Some texts contain placeholders {0}, {1}, {2}. JKCEMU replaces them at
runtime with a file name, a number, an address and so on. Example:

    German      Die Datei {0} konnte nicht geoeffnet werden.
    English     The file {0} could not be opened.

  - Every placeholder of the original MUST appear in the translation.
  - Never renumber them. If your language needs a different word order,
    reuse the same numbers in the new order, e.g. "{1} before {0}".
  - Do not add placeholders that are not in the original.

5.2. Apostrophes in texts that contain placeholders

In a text that contains a placeholder, a literal apostrophe must be
written twice. This is a rule of the Java message formatter.

    wrong       Don't open {0}
    right       Don''t open {0}

In texts without any placeholder, write the apostrophe normally.
Likewise, a literal curly brace in such a text must be written as '{'.

5.3. Line breaks and spaces

  - \n is a line break. Keep them where the original has them.
  - Some texts begin or end with a space. Keep those spaces, they
    separate the text from what comes before or after it. A leading
    space must be written as "\ ", otherwise Java discards it.
  - A backslash is written as "\\", a tab as "\t".
  - The text is one single line in the file, however long it is. Do not
    insert real line breaks into it.

5.4. Do not translate

  - Names of the emulated computers and their software:
    KC85/2..5, KC87, Z1013, Z9001, A5105, LC80, AC1, BCS3, HC900,
    PC/M, SLC1, VCS80, CP/M, CP/A, MicroDOS, CAOS, KCNet, D004, D008,
    GIDE, RAM-Floppy.
  - File format names and extensions: KCC, TAP, SSS, JTC, *.wav ...
  - Z80 register and instruction names: A, BC, IX, LD, CALL, JP ...
  - The keys themselves, i.e. everything left of the "=".

5.5. Keyboard mnemonics

Keys ending in ".mnemonic" are not texts but single letters, underlined
in the menu bar, e.g.

    common.menu.file=File
    common.menu.file.mnemonic=F

Choose a letter that occurs in your translated menu title, and do not
use the same letter twice in one menu bar.

5.6. Umlauts and other non-ASCII characters

JKCEMU also runs on older Java versions, which read property files as
ISO-8859-1. Write any character outside plain ASCII as a Java escape:

    wrong       action.close=Schließen
    right       action.close=Schließen

The shipped files are written this way, so you can copy the notation
from them. Most editors and all of the translation platforms mentioned
in section 1 can produce these escapes for you.


6. Testing your translation
---------------------------

If you have Apache Ant and a JDK installed:

    ant jar
    java -jar jkcemu.jar --lang=<code>

for example:

    java -jar jkcemu.jar --lang=fr

The language can also be selected permanently in JKCEMU under
"Einstellungen" -> "Sonstiges" ("Settings" -> "Miscellaneous").
A change takes effect after restarting JKCEMU.

To check your file for missing or superfluous keys:

    ant lang-check

If you cannot build JKCEMU yourself, just send the .properties file to
the JKCEMU authors - the file is all that is needed.


7. For maintainers: adding and checking texts
---------------------------------------------

Texts are not written into the Java sources. A source line reads

    GUIFactory.createMenuItem( LangUtil.getText( "disk.action.unpack" ) )

so a new text means a new key, which has to be added to
jkcemu.properties (English) and jkcemu_de.properties (German).

    ant lang-check

checks all of this and fails the build on a real problem. It reports

  1. keys used in the sources but missing from jkcemu.properties,
  2. keys in jkcemu.properties that no source line references,
  3. per language file: keys missing compared to the base file, and
     keys that exist there but not in the base file.

The checking tool jkcemu.lang.KeyCheck, this file and GLOSSARY.txt are
development aids only and are not shipped in jkcemu.jar.
